# HXBot 研究版 · 版本记录

各版本改了什么，供维护人员查阅。部署和升级的步骤只看《部署文档.md》，那里只描述当前版本。v1.6.1 起品牌名统一写 HXBot，更早的记录保留当时的名称。

2026-11-18 的版本（v1.7.2，修问题；桌面端 0.67.11，手机端 1.5.0 不变；服务器只有版本号、网页版和新功能页变化，数据库、nginx、`.env` 不变）：用户 2026-11-18：“在windows 和mac的程序坞出现多个HXBot的图表！”“HXBot启动后，电脑文件打开存储都出先卡死现象！”“其他bug，这次全部处理干净！”。**多个图标：**① Mac：每个“这台电脑上的服务器”是一个 HXBot 子进程，原来只在启动最早时调一次 `app.dock.hide()`，macOS 激活应用时会丢掉这次隐藏，图标整场留着；改为先设成 accessory 再隐藏，就绪后再设，之后 30 秒里多次复查（`src/main/hx-dock.ts`）。② 服务器子进程的窗口不进任务栏，被显示了就再藏（同一文件）。③ Windows：主进程里 `child_process` 的 spawn、exec、execFile、fork 默认 `windowsHide: true`，后台命令不再开命令行窗口；要显示窗口的地方（用户选的浏览器、检查里打开的记事本和资源管理器）写明 `windowsHide: false`（`src/main/hx-child-windows.ts`）。④ 打开时结束上次留下、父进程已不在的服务器子进程：先 SIGTERM，5 秒后 SIGKILL，只认这个 HXBot 程序加本机服务器数据目录的命令行，不按进程名（`src/main/hx-local-servers.ts`）。**别的应用存取文件卡：**⑤ 服务器一个接一个启动（原来同时启动），子进程以低于正常的优先级运行。⑥ v1.7.1 的容量 B 每个进程各算各的，桌面端加 5 个服务器最多能到 6×B；改为所有 HXBot 进程把正在跑的回合数写进 `appData/HXBot/hx-flow/<pid>.json`，每个进程能开 B − 别的进程正在跑的，至少 1；20 秒没更新或进程已不在的文件不算（`src/main/hx-flow-share.ts`）。⑦ Windows 上后台命令不再抢焦点（③）。**其他：**⑧ 授权记录写不进去时，“允许一次”“始终允许”不生效、不消耗，判定按没有授权处理（需求 AUD-07，`src/backend/hx-access/`）。⑨ 团队服务器上命令型（stdio）MCP 只有所有者和管理员能加、改、试、打开（需求 MKT-04，`src/main/team-api/hx-mcp-command-servers.ts`；用已有的“需要管理员”错误，Team API 的格式不变）。⑩ GitHub 打包加了可选的真机检查 `desktop_check`（`scripts/hx-desktop-check.mjs`，《客户端构建》第 6.11 节）。⑪ 重跑改造脚本时，v1.7.1 那一段容量代码不会再插一遍（共用 B 的那一行写进了 `hx/flow.py`）。规格书原排在 v1.7.9 的其余安全项（PERM-01、PERM-03、SEC-02、REL-04、REL-14 等）照原计划在 v1.7.9 做。改造说明第 30 节。

2026-11-18 的版本（v1.7.1，并发（一）：多智能体不卡死、团队不设上限、不拒绝只排队；桌面端 0.67.10（原定 0.68.0，见⑨），手机端 1.5.0 不变；服务器带上新的网页版、新功能页，不再按版本拒绝客户端，数据库、nginx、`.env` 不变）：按《需求规格说明书 V2.1》第 5.1 节（BUG-CONC-01、CONC-01、03、04、10、12、TEAM-01）。**容量闸：**① 桌面端按可用内存（先留 2 GB 或总内存 15%）、电池、温度、处理器降速和主进程事件循环延迟算出同时能跑几个回合 B（2～16，很烫时 1），每 5 秒采样，降立刻降、升要连续 3 次；Windows 用 tasklist 读智能体进程内存，macOS 用 vm_stat 和内存压力等级。② 等着的回合按顺序开始：真人消息、关键路径、团队成员、定时任务和后台；每等 2 分钟升一档；几个团队按近来用量轮流；B ≥ 3 时给真人留一个位置；有人在等且内存不够时收起闲了 4 分钟以上的团队成员进程。**团队不设上限：**③ 取消“最多 20 人 · 240 分钟 · 80 次交接”；分派一律接收、进看板排队，回复带“已排队，第 n 位，约 m 分钟”；只认用户在对话里说的上限，只对这一个团队有效；团队房间不再受每频道 2 件、第 8 次自动分派暂停的限制（普通频道不变）。④ 守护：实际干活 30 分钟没进展、转手 3 次没改动或同一成员收到几乎一样的工作 3 次、越拆越散（第一次只提醒）、实际干活 24 小时、花费提醒 10 次没回应 → 暂停并问用户；花费提醒按计费方式；同一件事确定失败 2 次照旧停止。设置里团队一栏改成一行说明“团队：人数按工作定；同时干活由电脑安排（现在 n 个）”。**卡死的根因与修复（BUG-CONC-01）：**⑤ 同一压力脚本、同一台机器对照（《并发根因报告-v1.7.1》《并发基线-v1.7.1.json》）：V1.7.0 桌面端没有容量闸，32 个回合同时跑、智能体进程 5.5 GB、分派被拒 58%；修后同时在跑最多 12、拒绝 0、主进程事件循环整场 p99 31 毫秒、最长 0.5 秒、窗口没有超过 2 秒不响应、停止键后 2 秒内 0 个新成员开工。⑥ 上游的频道列表每次都把没读过的频道的全部消息解析一遍再数未读，在每个 channels-changed 上跑两遍：89 MB 消息时每次 209 毫秒，用久了主进程被占满 → 改为只数新来的消息（5～12 毫秒，条数一致）。⑦ 排队检查和频道调度不再每次扫全部历史。**顺带修好：**⑧ 自动选模型的“小模型判断”的 token 没记进用量（v1.6.5 起），费用提醒和用量页少算。**更新不再强制（用户 2026-11-18：“以后大版本都不做强制更新，只需要在打开 hxbot 客户端后直接更新即可”“以后版本都不拦，需要自动更新即可”）：**⑨ 0.67.10 起，打开 HXBot 时找到的新版本自动下载、装好，在助手都空闲时几秒后重启进入新版，不弹窗、不用点（右下角提示“HXBot 正在安装更新”，可以取消这一次）；用着用着才找到的下次打开时再装；大版本也一样（`hx-update-policy.ts` 的 `hxInstallsByItself`、`hxAutomaticGraceMs`）。“更新 HXBot”窗口只在账号服务拒绝时挡住，而账号服务不再按版本拒绝：最低版本固定为桌面端 0.67.0、手机端 1.5.0，`hx/brand.json` 的 `minimumVersions` 去掉。已装的 0.67.2～0.67.9 看到第二段变了的版本号会挡住界面（那是它们自己的代码），所以这一版用 0.67.10 而不是 0.68.0。设置里“自动更新”一行的说明 15 种语言重写。手机端 1.5.0 的整屏提示随下一次手机端发版改。**测试：**压力脚本 `scripts/hx-flow-stress-e2e.ts` 列入每版必跑；验收脚本 `scripts/hx-flow-acceptance-e2e.ts`；真系统检查 `scripts/hx-flow-system-check.ts` 在 GitHub 的 Windows、Mac 上跑。新增界面文字 15 种语言都有译文；《隐私政策》不变（1.5 版）。

2026-11-15 的版本（v1.7.0，HXBot 不打扰其他应用；桌面端 0.67.9，手机端 1.5.0 不变，服务器只有版本号和新功能页变化）：用户 2026-11-14 反映 HXBot 经常影响其他应用（别的应用变卡、风扇响；焦点被抢、窗口乱跳；快捷键、复制粘贴失灵；别的应用卡死或退出；经常断网），要求在 v1.7.0 全部解决、Windows 也一样。**变卡、风扇：**① 电脑操控的高亮框每 33 毫秒向驱动要一次全部窗口，改为每 250 毫秒看一次、只在驱动最近 15 秒有动作时读、每秒最多两次；② Windows 上 setIgnoreMouseEvents 的转发会装全局低级鼠标钩子：高亮框不转发，灵动岛、停靠栏只在鼠标靠近（32 像素内）时转发；③ 后台读目录的命令最低优先级，助手的进程（及其子进程）低于正常优先级；④ 读窗口（get_window_state）没写上限时补上 1500 个控件、3 秒；⑤ 两分钟没人用的后台网页标签恢复节流。**焦点：**⑥ 发按键前看最前面的应用（Windows 同时比窗口句柄），不是目标应用就不发、不拉回，停下问用户；⑦ 授权页、App 管理、自动化页和远程控制询问：用户在 HXBot 里时直接打开，在别的应用里时只发通知、点了才打开，同一页 60 秒（通知 10 分钟）内只一次；⑧ Mac 自动更新后用户在别的应用里时用 open -g 在后台打开。**快捷键、剪贴板：**⑨ 发过按键的一次操作结束时松开全部修饰键（Mac 另发一次“修饰键全无”，核对系统状态最多五次）；⑩ 停止键 Ctrl+Alt+Esc 只在电脑工具运行中或驱动最近一分钟有动作时占用；⑪ 驱动输入文字前后核对剪贴板，只读文字，变了就放回。**卡死、退出：**⑫ Windows 上停助手的进程树时先列出整棵树，有可见窗口的应用和它下面的进程留下，其余按 PID 结束，4 秒列不出来照旧 /T。**断网：**⑬ 更新下载限速 2 MB/s（Mac 自己的下载按速度走；electron-updater 在它的请求执行器上换成按速度放行的流，会话的网络模拟管不到 net 模块，实测）；⑭ 远程桌面 Sunshine max_bitrate 10000。**全系统核查中查出并修好的：**⑮ 自动选择模型在进行中的对话里每来一条新消息都可能换模型或推理强度，换了就开新的服务商会话，上下文和缓存丢失（上游自带的 307 个端到端测试第一次在研究版上跑，查出 14 个受影响）：进行中的对话保持原模型和强度，打招呼不再请小模型判断；⑯ MCP 的客户端名 hx-bot 改为 hxbot。真机检查（GitHub macOS 15、26，Windows Server 2025）新增“不打扰”一组 Q1～Q7 和 S9，三台全部通过。说明见改造说明第 27 节。
