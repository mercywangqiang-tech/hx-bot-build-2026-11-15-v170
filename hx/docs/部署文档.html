1添加域名解析

解析记录要加在 hxallai.com 当前使用的 DNS 服务商那里。hxallai.com 的 DNS 服务器是腾讯云 DNSPod（perseus.dnspod.net、judith.dnspod.net），www 的解析也在那里，所以要登录 DNSPod 控制台（console.dnspod.cn，或腾讯云控制台 → 云解析 DNS）→ 找到 hxallai.com → 添加记录。加在阿里云“云解析 DNS”里不会生效。

不确定用的是哪家时，在服务器上执行 getent ahostsv4 www.hxallai.com 能看到 IP，再到域名注册商处看“DNS 服务器”一栏：*.dnspod.net 是 DNSPod，*.alidns.com / *.hichina.com 是阿里云。

添加下面 4 条（线路类型选“默认”，记录值都填这台 ECS 的公网 IP 47.119.145.170，TTL 默认即可）：

这 4 个都是已备案域名 hxallai.com 的子域名，不需要重新备案。

3.3 配置镜像加速（国内服务器必须做）

国内服务器直接访问 Docker Hub 会失败，需要配置镜像加速。只配阿里云的个人镜像加速器（https://xxxx.mirror.aliyuncs.com）现在不够：它已不再完整提供 Docker Hub 镜像，拉取 node:24-bookworm-slim 等镜像会报 not found。下面的配置同时使用几个国内可用的公共加速源，Docker 会按顺序逐个尝试。

先看服务器上是否已有 Docker 配置：

终端命令
cat /etc/docker/daemon.json 2>/dev/null || echo "没有配置文件"
  • 显示“没有配置文件”，或里面只有你自己刚加的 registry-mirrors 和日志设置：直接执行下面的命令（会整体替换这个文件）。
  • 里面还有别的设置（例如 data-root、insecure-registries）：不要执行下面的命令，改为用 vi /etc/docker/daemon.json 把 registry-mirrors 一行改成下面命令中的那几个地址，保存后执行 systemctl restart docker。
  • 注意：重启 Docker 会重启这台服务器上所有正在运行的容器。如果官网或其他业务也用 Docker 运行，请选在访问少的时段操作。
终端命令
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://docker.m.daocloud.io"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "20m", "max-file": "5" }
}
EOF
systemctl restart docker
docker info 2>/dev/null | grep -A 4 "Registry Mirrors"

检查：最后一条显示 Registry Mirrors: 和上面三个地址。已经申请了阿里云个人加速器的，可以把它作为第四个地址加在列表最后（前一行末尾要加英文逗号），不加也可以。

再一次性试拉部署要用到的 4 个基础镜像：

终端命令
for img in node:24-bookworm-slim oven/bun:1.4.2-alpine coturn/coturn:4.17.2-r0 certbot/certbot:latest; do
  docker pull -q "$img" >/dev/null && echo "✔ $img" || echo "✘ $img"
done
docker run --rm node:24-bookworm-slim node -v

检查：4 行都是 ✔，最后一行显示 v24.x.x。有 ✘ 时先等一两分钟再执行一次（加速源第一次拉取某个镜像要先从海外缓存）；仍然失败见第 13 节“拉取镜像失败”。

这几个公共加速源由第三方维护，可用性会变化；只用来拉取上面 4 个官方基础镜像。

5.3 发信邮箱（邮箱验证码，默认开启）

用户注册和找回密码时，服务器用 bot@hxallai.com 给他的邮箱发一封 6 位验证码邮件（10 分钟内有效），主机的邮箱邀请也用它发出。这一步把这个邮箱的 SMTP 地址和密码填进配置。下面以阿里企业邮箱为例。

第 1 步：允许这个邮箱用 SMTP 发信。新开通的阿里企业邮箱默认不允许邮箱网页和官方 App 以外的程序登录，要由邮箱管理员放开：

  1. 用邮箱管理员账号（postmaster@hxallai.com）登录 https://qiye.aliyun.com 。
  2. 左侧“安全管理 → 账号安全 → 访问策略”，找到“三方客户端访问策略”。它开着表示禁止，把它关掉（页面上可以只对部分成员生效时，只放开 bot@hxallai.com 即可）。
  3. 左侧“组织与用户 → 员工账号”，点 bot@hxallai.com，切到“功能权限”，在“客户端配置”里打开“IMAP/SMTP”（或“POP3/SMTP”）。

第 2 步：确定要填哪个密码。用 bot@hxallai.com 登录网页邮箱，在“设置”里看“三方客户端安全密码”：

  • 已开启（或公司统一要求开启）：在那里生成一个安全密码，填上设备名称（例如 hxbot-server）并点“确定”才算生成。第 3 步填这个安全密码，不是邮箱的登录密码。
  • 没有开启：第 3 步填邮箱的登录密码。

第 3 步：把五项填进配置。前四条整段复制执行，第五条单独复制执行（它在等你输入密码，后面不能跟着别的命令一起粘贴）：

终端命令
bash scripts/set-env.sh EMAIL_SMTP_HOST smtp.qiye.aliyun.com

11.1 Mac、Windows、Android 安装包

在打包的那台电脑上（源码目录里）执行，一次可以传多个文件：

终端命令
bash hx/scripts/upload-downloads.sh root@47.119.145.170 dist/HXBot-0.67.11-arm64.dmg

Mac 版要有固定签名（v1.6.8 起）。在 Mac 上上传时，脚本先从 dmg 旁边的 zip 里取出 HXBot.app，核对签名身份是 HXBot 的固定证书（或以后的 Developer ID）；没有固定签名的包（例如在自己 Mac 上打的）不上传，因为 macOS 按签名记授权，这样的包一传上去，所有 Mac 用户升级后都要重新授权。发布用 GitHub 上打的 Mac 包，见《客户端构建》第 6.3 节第二部分。

应用内更新用的文件会一并上传。打包时 dmg 和 exe 旁边还会生成几个文件，用户在应用里更新时用的就是它们：Mac 的 HXBot-版本号-arm64.zip 和 latest-mac.yml，Windows 的 HXBot-版本号-x64.exe.blockmap 和 latest.yml。上传 dmg 或 exe 时，这条命令会把同一目录里、同一版本的这几个文件放到服务器的 /opt/hxbot/downloads/updates/desktop/，latest*.yml 最后传，服务器核对文件都齐了才换上，换上之前已经装好的客户端看到的还是原来的版本。旧版本的 .blockmap 留在服务器上（Windows 增量下载要用），旧的 Mac ZIP 自动删除。命令输出的“应用内更新”一段列出现在各端在应用里能更新到的版本；某个文件缺了或版本对不上，会提示“这次不更新 …… 的应用内更新”，这时用户仍能在下载页手动下载新版。

安卓安装包传上去后，下载中心同时给它一个随机串地址（/ota/随机串/HXBot.apk）：手机里点“更新”时由系统浏览器下载，系统浏览器不带登录状态，所以和 iOS 的无线安装一样用随机串；换了安装包就换新的随机串，旧地址随即失效。

也可以用任何方式（如 SFTP 工具）把文件放进服务器的 /opt/hxbot/downloads/（应用内更新的文件放进 /opt/hxbot/downloads/updates/desktop/，latest*.yml 改名为 latest*.yml.new 最后放），再在服务器上运行：

终端命令
chmod 644 /opt/hxbot/downloads/HXBot-*
python3 /opt/hxbot/server/scripts/publish-downloads.py /opt/hxbot/downloads

文件名必须是下面四种之一，门户页才会识别。每个平台只显示版本最新的一个：

平台文件名
Mac（Apple 芯片）HXBot-版本号-arm64.dmg
WindowsHXBot-版本号-x64.exe
AndroidHXBot-版本号-android.apk
iPhone / iPadHXBot-版本号-ios.ipa（只有“直接安装”这条路线才上传 ipa，见 11.7 节）

第 1 步：新建一个公司专用的 Apple 账户，并打开双重认证。不要用个人平时用的 Apple 账户。在浏览器打开 https://account.apple.com ，点“创建你的 Apple 账户”：

  • 姓名填办理人的真实姓名（和身份证一致）。不要填公司名、昵称，否则审核会被退回。
  • 邮箱填上面准备的公司邮箱，手机号填办理人的手机号。
  • 创建完成后，在那台 iPhone 上用这个账户登录（设置 → 最上面的“登录 iPhone”）。登录后进“设置 → 你的姓名 → 登录与安全性”，“双重认证”一行要显示“已开启”。

第 3 步：在 Apple Developer App 里提交注册。

  1. 在那台 iPhone 的 App Store 里搜索并安装“Apple Developer”（开发者是 Apple）。
  2. 打开它，点底部的“账户”（Account），用第 1 步的 Apple 账户登录。提示同意《Apple Developer Agreement》就同意。
  3. 点“立即注册”（Enroll Now），看完说明点“继续”。
  4. 填办理人信息：姓、名、身份证号、手机号。
  5. 按提示自拍：脸在取景框内、光线充足，拍完确认清晰。
  6. 实体类型选公司 / 组织（Company / Organization）。
  7. 填公司信息：法定实体名称（照邓白氏邮件里的名称原样复制）、邓白氏编码、总部地址和电话、公司网站。
  8. 确认你有权代表公司签约。不是创始人或法定代表人时，填那位能证明授权的同事的联系方式。
  9. 提交。屏幕上会显示一个注册编号（Enrollment ID），截图保存，找苹果客服时要用。

第 4 步：等苹果审核。苹果核实公司信息后会发邮件说明下一步，期间也可能来电话或邮件核实，注意接听陌生来电、查看垃圾邮件箱。审核通过时会收到一封邮件，告诉你可以完成注册了。想查进度：用这个 Apple 账户登录 https://developer.apple.com/account 。

第 5 步：付年费。收到“可以完成注册”的邮件后：

  1. 先确认付款方式：iPhone 的“设置 → 你的姓名 → 付款与配送”里有一种可用的付款方式（支付宝、微信支付或银联卡）。想用公司的卡，就把它加在这里。
  2. 在同一台设备上打开 Apple Developer App → 账户 → “继续注册”（Continue Enrollment）。
  3. 阅读并同意《Apple Developer Program 许可协议》。
  4. 核对年度订阅的内容，点“以每年 ¥688 续订”，按提示完成支付。
  5. 收据会发到邮箱，可以用来报销；以后在“设置”的购买历史记录里可以随时重发。

这是按年自动续期的订阅，每年到期自动扣 688 元；不想续了，最晚在续订日的前一天到“设置”里取消订阅，已付的年费不退。付款后 24 小时内没有收到会员确认，带着注册编号联系苹果开发者支持（ https://developer.apple.com/contact/ ）。

第 6 步：记下团队号。在浏览器登录 https://developer.apple.com/account ，往下找到“会员资格详细信息”（Membership details），里面的“团队 ID”（Team ID）是 10 位大写字母和数字，例如 ABCDE12345。把它记下来，后面两个地方要用：打包命令（11.5 节）和服务器配置（11.6 节第 9 步）。

第 7 步：登录一次 App Store Connect。用同一个账户登录 https://appstoreconnect.apple.com ，如果提示有协议要同意就同意。HXBot 是免费应用，不需要填税务和银行信息。

到这里账号就办好了。以后每年只要保证付款方式有效（11.10 节）。

公司的邓白氏编码一时办不下来、又着急用：可以先用办理人的个人身份注册（同样 688 元 / 年，不需要邓白氏编码，提交时当场付款）。区别是应用的开发者一栏显示的是个人姓名而不是公司名。以后可以向苹果申请把个人会员资格转成公司的，条件是办理人是公司创始人并提供邓白氏编码。

11.4 第二步：准备打包用的 Mac

需要一台 Apple 芯片的 Mac（M1 及以后），可用磁盘 50 GB 以上，并且能稳定访问 GitHub、npm 和 CocoaPods（打包时要从这些地方下载依赖，访问不了后面每一步都会卡住）。下面七件事只做一次。

第 1 步：安装 Xcode。打开 Mac 上的 App Store，搜索 Xcode，点“获取”。文件很大，要下载一小时以上。装好后打开一次：同意许可，弹出平台选择时保持 iOS 勾选，等它把组件装完再关掉。然后打开“终端”，逐行执行（第一行会要求输入 Mac 的开机密码，输入时屏幕上不显示字符，输完按回车）：

终端命令
sudo xcode-select -s /Applications/Xcode.app
sudo xcodebuild -license accept
sudo xcodebuild -runFirstLaunch
xcodebuild -version

最后一行应显示 Xcode 26 或更大的版本号。App Store 提示系统版本太低时，先在“系统设置 → 通用 → 软件更新”升级 macOS（Xcode 26 要求 macOS 15.6 或更新，更新的 Xcode 要求更高，以 App Store 页面显示的为准）。

第 2 步：在 Xcode 里登录开发者账号。打开 Xcode → 菜单栏 Xcode → Settings（设置）→ Accounts（账户）→ 左下角 + → Apple Account → 用 11.3 节的账户登录。登录后右侧应出现公司名称的团队。

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
brew install cocoapods

第 4 步：安装 Node.js 24。在浏览器打开 https://nodejs.org/dist/latest-v24.x/ ，下载文件名以 .pkg 结尾的那一个，双击按提示安装。

第 5 步：安装 Bun。

终端命令
curl -fsSL https://bun.com/install | bash -s "bun-v1.4.2"

装完关掉终端重新打开，后面的命令才认得 bun。

第 6 步：登记至少一台 iPhone 或 iPad。这一步不能省：开发者账号里一台设备都没有时，Xcode 生成不了签名用的描述文件，打包会失败（报 Your team has no devices）。走路线 B 的，把要安装的每一台设备都在这里登记。

  1. 取设备编号（UDID）：用数据线把 iPhone 连到 Mac，手机上点“信任”。打开“访达”，在左边栏点这台 iPhone，再点设备名称下面那一行灰色小字（型号、容量那一行），点到显示 UDID 为止，在上面点右键 →“拷贝 UDID”。
  2. 在浏览器打开 https://developer.apple.com/account/resources/devices/list ，点“Devices”旁边的 +。
  3. Platform 选 iOS, iPadOS, tvOS, watchOS, visionOS；Device Name 填一个认得出的名字（如“张三的 iPhone”）；Device ID (UDID) 粘贴刚才拷贝的编号。
  4. 点 Continue，再点 Register。

用户不在身边、手边也没有 Mac 时，让他在 Windows 电脑上装 iTunes，连上手机后点设备图标，在“摘要”页点“序列号”那一行，它会变成 UDID，右键拷贝后发给你。

第 7 步：解压源码并检查环境。把源码包 hxbot-source-v1.7.2.zip 拷到 Mac 上，在终端里进入它所在的文件夹：

终端命令
unzip hxbot-source-v1.7.2.zip
cd hx-bot
bash hx/scripts/build-ios.sh --check

每一行都是 [通过] 才算准备好。出现 [缺少] 的，照它下面“处理”一行做完，再运行一次。全部通过时屏幕显示：

屏幕输出示例
检查这台 Mac 的打包环境……

环境检查通过。另外有两件事脚本查不出来，请自己确认（部署文档 11.4 节）：
  1. Xcode → Settings（设置）→ Accounts（账户）里已经登录开发者账号；
  2. 开发者账号里已经登记了至少一台 iPhone 或 iPad（一台都没有时归档会失败）。

路线 A（TestFlight）：

终端命令

脚本自己完成全部工作，依次显示 1/5 到 5/5：应用改造、安装依赖、生成 iOS 工程、归档签名、导出安装包。第一次打包时注意两件事：

11.6 路线 A：通过 TestFlight 发布

界面上的文字下面写的是英文原文，中文界面的译名可能略有不同，按位置对照即可。

第 1 步（只做一次）：在 App Store Connect 建应用记录。要在第一次打包成功之后做，因为“套装 ID”要等 Xcode 打包时登记过才选得到。

  1. 登录 https://appstoreconnect.apple.com ，点 Apps（App），再点左上角的 + → New App（新建 App）。
  2. Platforms 勾 iOS。
  3. Name 填 HXBot。这个名称在整个 App Store 里不能重复，提示已被占用就改成 HXBot 研究版。
  4. Primary Language 选简体中文。
  5. Bundle ID 在下拉列表里选结尾正好是 com.hxallai.bot 的那一项。结尾多出 .ShareExtension、.NotificationService、.ExpoWidgetsTarget 的是应用的扩展，不要选。
  6. SKU 填 hxbot-ios（只是内部编号，用户看不到）。
  7. User Access 选 Full Access，点 Create。

第 2 步：用 Transporter 上传安装包。

  1. 在 Mac 的 App Store 里搜索并安装 Transporter（开发者是 Apple，免费）。
  2. 打开它，用开发者账号登录。
  3. 把 11.5 节打出来的 dist-hx/HXBot-1.5.0-ios.ipa 拖进窗口。
  4. 点“交付”（Deliver），等进度条走完，显示已交付。

第 3 步：等苹果处理。约 10～30 分钟后，App Store Connect → 你的应用 → TestFlight 标签页的 iOS 构建列表里出现 1.5.0 (2611111530)。还在处理时显示 Processing，耐心等；苹果发现问题会给账户持有人的邮箱发邮件。应用里已经带了出口合规声明（沿用原项目的设置），一般不会再问。

第 4 步（只做一次）：填测试信息。TestFlight 标签页左边栏点 Test Information（测试信息）：

栏目填什么
Beta App Description（必填）HXBot 研究版的手机端，用来远程连接你电脑上的桌面端。仅限研究使用，不得用于商业用途。
Feedback Emailbot@hxallai.com
Beta App Review Information：联系人办理人的姓名、电话、邮箱
Sign-in required（需要登录）勾选，填一个专门给审核员用的账号的邮箱和密码（见表格下面）
NotesHXBot is the mobile companion of the HXBot desktop app (research edition, not for commercial use). Sign in with the email and password above.

给审核员的账号要真的能登录，而且不要用任何真人的账号。在服务器上为它单独建一个：cd /opt/hxbot/server && bash scripts/users.sh add review@hxallai.com（邮箱换成公司的一个邮箱；按提示填用户名、手机号码、公司名称、职位，并设一个只给审核用的密码），把这个邮箱和密码填进上表。服务器设了注册名单的，先把它加进名单（第 12 节“修改注册名单”）。审核期间，最好让一台用这个账号登录的桌面端保持开机在线，这样审核员登录后能看到内容。审核结束后可以停用它：bash scripts/users.sh disable review@hxallai.com，下次送审前再 enable。

第 5 步：先建内部测试群组，自己装上验证。内部测试不用苹果审核，上传处理完就能装；而且苹果规定要先有内部群组才能建外部群组。

  1. TestFlight 标签页左边栏，点 Internal Testing（内部测试）旁边的 +。
  2. 群组名填 内部，保持 Enable automatic distribution（自动分发）勾选，点 Create。以后每次上传的新构建会自动发给这个群组。
  3. 点 Invite Testers（邀请测试员），勾选自己，点 Add。
  4. 在自己的 iPhone 上从 App Store 安装 TestFlight，用开发者账号登录，列表里出现 HXBot，点“安装”。装好后打开，用邮箱和登录口令登录，确认能用。

要让同事也进内部测试：App Store Connect 顶部的 Users and Access（用户和访问）→ +，填他的姓名、邮箱，角色选 Developer 或 Marketing，他在邮件里接受邀请后，回到第 3 步把他勾上。内部测试员最多 100 人。

第 6 步：建外部测试群组，提交审核。客户不是公司的开发者账号成员，属于外部测试员。

  1. TestFlight 标签页左边栏，点 External Testing（外部测试）旁边的 +，群组名填 研究用户，点 Create。
  2. 进这个群组，点 Add Builds（添加构建版本），选 iOS 和版本，在列表里选中刚上传的构建，点 Add。
  3. What to Test（测试内容）填 登录、连接桌面端主机、收发消息。
  4. 勾选 Automatically notify testers（自动通知测试员）。
  5. 点 Submit Review（提交审核）。

构建的状态变成 Waiting for Review（等待审核），之后是 In Beta Review（审核中）。通过后账号的管理员会收到邮件。只有每个版本号的第一个构建要完整审核，同一版本号后面的构建一般不用再审。被拒绝时，在 TestFlight 标签页左边栏的 App Review 里看原因，改好后重新提交。

第 7 步：生成公开链接。审核通过后：

  1. 进 研究用户 群组，在 Testers（测试员）标签页点 Create Public Link（创建公开链接）。
  2. 选 Open to Anyone（面向所有人）。
  3. 可以勾 Set Limit 设一个人数上限（1～10000），建议先设成预计的用户数，以后随时能改。
  4. 点 Confirm，复制得到的链接，形如 https://testflight.apple.com/join/AbCd1234。

第 8 步：把链接发布到下载页。在 Mac 的源码目录里执行（把链接换成你的）：

终端命令

没有配置 SSH 的，也可以登录服务器后执行：

终端命令
python3 /opt/hxbot/server/scripts/publish-downloads.py /opt/hxbot/downloads --ios-url https://testflight.apple.com/join/AbCd1234

屏幕显示：

屏幕输出示例

  ios      https://testflight.apple.com/join/AbCd1234  TestFlight
完成。打开 https://bot.hxallai.com 登录后即可看到新版本。

检查：用 iPhone 打开 https://bot.hxallai.com 登录，“iPhone / iPad”卡片上出现“在 TestFlight 中安装”按钮。脚本只接受苹果的地址（testflight.apple.com、apps.apple.com）。以后要撤下这个按钮，把命令里的 --ios-url 链接 换成 --no-ios-url。

第 9 步（可选）：让 iPhone 上点邀请链接直接打开应用。在服务器上执行（团队号是 11.3 节第 6 步记下的那个）：

终端命令

bash scripts/set-env.sh HX_APPLE_TEAM_ID ABCDE12345
docker compose up -d account

11.9 以后怎么发布更新

需要重新打包上传的三种情况：拿到了新的源码包（有新功能或修复）；TestFlight 的构建快满 90 天了；路线 B 的描述文件快到期或者要加新设备。服务器升级（第 12 节）不会改变已经装在手机上的应用，手机端的界面改动要靠这里的步骤送到用户手上。

路线 A（TestFlight）的更新，四步：

第 1 步：打包。有新源码包就先解压新的（方法同 11.4 节第 7 步），没有就用原来的目录。命令和第一次完全一样，构建号会自动变大：

终端命令
HX_APPLE_TEAM_ID=ABCDE12345 bash hx/scripts/build-ios.sh

第 2 步：上传。打开 Transporter，把新的 ipa 拖进去，点“交付”。

第 3 步：发给测试员。等 App Store Connect → TestFlight 里出现新的构建号。内部 群组开了自动分发，会自动收到。进 研究用户 群组，点 Builds（构建版本）旁边的 +，选中新构建，填测试内容，点 Submit Review 或 Start Testing（按钮是哪个取决于这个构建要不要审核）。

第 4 步：确认。自己的 iPhone 上打开 TestFlight，HXBot 显示“更新”，更新后在 TestFlight 里看到的构建号是新的。

邀请链接不变，下载页不用改，服务器上什么都不用做。用户会在 TestFlight 里收到更新通知。

每个构建只能测试 90 天，到期后用户手上的应用打不开。请在日历里设一个每 80 天重复的提醒，到时候按上面四步发一个新构建，即使源码没有变化。

源码里的版本号变了（例如从 1.5.0 变成 1.5.1）时，对苹果来说是一个新版本，它的第一个构建要重新走一次外部测试审核，其余步骤不变。

路线 B（直接安装）的更新，三步：

第 1 步：有新设备先登记（11.4 节第 6 步）。

第 2 步：打包并上传。

终端命令
HX_IOS_EXPORT=release-testing HX_APPLE_TEAM_ID=ABCDE12345 bash hx/scripts/build-ios.sh
bash hx/scripts/upload-downloads.sh root@47.119.145.170 dist-hx/HXBot-1.5.0-ios.ipa

新文件覆盖旧文件，旧的安装地址随即失效。手机上的 HXBot 点“更新”时打开的就是这个新地址。

第 3 步：确认并通知用户。下载页“iPhone / iPad”卡片上的构建号、更新日期和 SHA-256 变成新的。通知用户用 Safari 打开下载页再点一次“安装”，新版本会覆盖旧版本，登录状态和数据保留。

升级到新版本

每个新版本上线按交付件里的《上线操作手册》做：它按这台服务器写好了每一步（先确认服务器现状、通知用户、上传客户端、升级、检查），比本节更细。本节讲升级的原理和手工方法，作为备查。

每个新版本有两个服务器包，任选一个。.env、账号数据库和下载目录里的安装包都会保留；数据库里新版本增加的表在启动时自动建好。

包内容什么时候用
hxbot-server-v1.7.2.zip（全量包）完整的服务器程序全新部署；从任何旧版本升级
hxbot-server-update-v1.7.2.zip（更新包）只有上一版本以来变动的文件，小得多服务器正好是上一版本时（交付说明里写着起点版本。不是的话脚本会拒绝，并提示改用全量包）

  • 桌面端升到 0.67.3，手机端仍是 1.5.0：只要按《客户端构建.md》重新打包 Mac 和 Windows 版，用第 11.1 节的命令上传，再升级服务器。上传后已经装着 0.67.1、0.67.2 的桌面端会自动下载新版本：0.67.1 下载完自动重启安装，0.67.2 弹出窗口介绍新功能，用户点“立即更新”或“以后再说”（这一版不是大版本，不强制）；手机端不用重新打包，也不受影响。网页版随服务器一起更新。

升级到 v1.6.3 时：

  • 这一版只改了界面样式：桌面端和网页版的开关、下拉框、按钮、输入框、菜单、弹窗、滑块和设置页换了一套更简洁的样式，功能不变。从 v1.6.2 升级时用全量包或更新包都可以；nginx 配置、.env、数据库都不变，用户不用重新登录。
  • 桌面端升到 0.67.2，手机端仍是 1.5.0：只要按《客户端构建.md》重新打包 Mac 和 Windows 版，用第 11.1 节的命令上传，再升级服务器。上传后桌面端 0.67.1 会自动下载新版本、重启安装（0.67.1 自带的窗口是必须更新）；手机端不用重新打包，也不受影响。网页版随服务器一起更新。
  • 更新的规则改了（0.67.2 起）：平时的新版本可以不装，桌面端下载好后弹出窗口介绍新功能，用户点“立即更新”或“以后再说”；大版本（版本号第二段变了，例如 0.68.0）必须更新：窗口挡住，10 分钟内没人点就在空闲时自动安装，账号服务也拒绝旧的大版本。服务器的最低版本由 hx/brand.json 决定：minimumVersions 空着时桌面端是当前版本的“主.次.0”、手机端是当前版本；某个小版本有安全问题必须马上装时，发版前在 minimumVersions 里写上它。每版的新功能写在 hx/release-notes.json（中英文），打包时写进 latest.yml。手机端这一版不变，仍是有新版本就提示更新。
  • 服务器还是 v1.6.2 之前版本的，再看下一段。

升级到 v1.6.2 时：

  • 服务器多了一条命令升级（下面的方法一）、手工更新包和可选的自动更新；从这一版起交付两个服务器包（见上表）。服务器现在是 v1.6.1，这一次用全量包或更新包都可以。
  • nginx 配置新增了应用内更新用的地址（/updates/，只给登录了的客户端）和安卓新版安装包的地址，一定要更新 nginx 配置（一条命令升级会自动做；手工升级是第 6 步）。
  • 账号：一个手机号码只能注册一个账号（邮箱和用户名本来就不能重复）。已经有几个账号共用一个手机号码的，最早注册的那个账号拥有这个号码，几个账号都照常登录，只是不能再用这个号码注册新账号。注册时填完用户名就会提示它能不能用。
  • 用户可以在客户端里自己注销账号（第 12 节表格里的“注销账号”）。
  • 强制更新：新版客户端每个请求都带上自己的版本号，账号服务拒绝比这一版服务器所带客户端（桌面端 0.67.1、手机端 1.5.0）旧的版本，提示用户更新；没有带版本号的旧客户端（桌面端 0.67.0、手机端 1.4.x 及以前）不能再登录。升级时所有设备的登录一次失效（数据库迁移 9003），所以所有用户都要更新客户端并重新登录一次。退出登录、注销账号和下载更新文件不受限制。以后每次升级服务器，客户端都必须跟着更新，所以每次都要先上传新的安装包。
  • 最大权限：新版桌面端里所有智能体默认改为“最大权限”（大多数事情直接做，修改工作区以外已有的文件、删除工作区以外的东西、以管理员身份运行命令、用保存的密码登录、付款等先弹卡片确认），新增“设置 → 授权与记录”。这些都在用户自己的电脑上，服务器不需要设置。
  • 使用指南、服务条款和隐私政策更新到 1.2（自助注销账号、应用内更新与强制更新、账号不能重复、最大权限）。升级前请通知用户，内容参考：“HXBot 将于某日升级：升级后旧版客户端不能再登录，请按提示更新客户端（桌面端会自动下载安装，手机端点‘安装’），然后重新登录一次；助手的默认权限改为‘最大权限’，修改或删除工作区以外的文件等操作会先请你确认；可以在‘设置 → 个人资料’里自行注销账号；服务条款和隐私政策随之更新，见 https://bot.hxallai.com/terms/ 和 https://bot.hxallai.com/privacy/ 。”
  • 客户端换成无底框的长颈鹿图标，版本号升到桌面端 0.67.1、手机端 1.5.0：要按《客户端构建.md》重新打包，用第 11.1 节的命令上传（会把应用内更新用的文件一起传上去）。从这个版本起客户端在应用里自动更新；已经装着的旧版本（桌面端 0.67.0、手机端 1.4.x 及以前）不能再登录，要在下载中心下载、安装这一次，以后的版本就在应用里自动更新。
  • 门户、网页版、使用指南等网页的标签图标换成无底框的长颈鹿（浏览器可能还显示旧图标，强制刷新即可）。服务器还是 v1.6.1 之前版本的，再看下一段。

从 v1.6.1 之前的版本升级时：v1.6.1 起品牌名统一为 HXBot，客户端的安装包名变成 HXBot-版本号-…（如桌面端 HXBot-0.67.1-…、手机端 HXBot-1.5.0-…），要按《客户端构建.md》重新打包并上传到下载中心。Mac 用户装好新版后，确认能打开，再把旧的“HX Bot”应用拖到废纸篓（设置、登录、保密箱都在原来的数据文件夹里，新版继续用）；Windows 安装新版时会自动卸载旧版。新设或重设的密码要同时包含字母、数字和符号，已经设置的密码照常登录。

#### 方法一：一条命令升级（推荐）

第 1 步：把包传到服务器。在你的电脑上执行（文件名换成拿到的包）：

终端命令
scp hxbot-server-v1.7.2.zip root@47.119.145.170:/opt/

第 2 步：在服务器上执行一条命令。服务器已经是 v1.6.2 或更新的版本时：

终端命令
bash /opt/hxbot/server/scripts/update.sh /opt/hxbot-server-v1.7.2.zip

服务器还是 v1.6.1（还没有这个脚本）时，先从包里取出脚本再运行，两行：

终端命令
unzip -o -j /opt/hxbot-server-v1.7.2.zip server/scripts/update.sh -d /tmp/hxbot-update
bash /tmp/hxbot-update/update.sh /opt/hxbot-server-v1.7.2.zip

用更新包时把文件名换成 hxbot-server-update-v1.7.2.zip，命令相同。脚本做的事和下面手工升级的 8 行相同，另外：

  • 先核对包：是不是 HXBot 的部署包；更新包要求这台服务器正好是它的起点版本；同一版本不会重装、也不会装回更旧的版本（确实要这样做时在命令最后加 --force）。
  • 升级前先运行一遍 check.sh，记下已经失败的项（例如某个域名还没解析），升级后只把新出现的失败当作问题。
  • 备份：账号数据库（同 backup.sh）、server/ 和 portal/ 目录（含 .env，放在 /opt/hxbot/backups/server-日期-时间.tgz，只有 root 能读，保留最近 5 份）、nginx 站点配置、正在用的镜像。
  • 新版本需要、而 .env 里还没填的配置（set-env.sh --show 新出现“提醒：”或“还没有填写”），在启动新版本之前就停下来。
  • 放上新文件，更新门户页和 nginx 配置，docker compose up -d --build，等账号服务就绪，再运行 check.sh。刚重启的信令服务要几秒才开始监听、coturn 的第一次健康检查在启动 15 秒后，所以没通过的项每 5 秒重查，最多等 2 分钟才算失败（v1.6.2 的脚本不等，会把正常的升级误判为失败而回滚；v1.6.2 的服务器升级时会自动改用新包里的脚本）。
  • 其中任何一步出错，或者 check.sh 出现升级前没有的失败项，自动回滚：文件、nginx 配置、镜像都换回升级前的；新版本已经启动过的，账号数据库也换回升级前一刻的备份。最后显示“已回滚到 ……”和原因，照原因处理后重新运行同一条命令。

最后一行显示 ✔ 已升级到 版本号 就完成了。整个过程几分钟（主要是构建镜像），账号服务会暂停约 10 秒（备份）、重启一次，已经建立的远程连接不受影响。回滚会把这几分钟里新注册的账号、改的密码也一起换回升级前，所以尽量在没人用的时候升级。每次升级的输出都记在 /var/log/hxbot/update.log。

#### 方法二：手工升级

用于 v1.6 之前的版本，或者想一步一步看着做的时候。只能用全量包。

手工第 1 步：把部署包传到服务器。在你的电脑上执行（把 v1.6.2 换成拿到的版本号）：

终端命令
scp hxbot-server-v1.7.2.zip root@47.119.145.170:/opt/

手工第 2 步：在服务器上逐行执行。任何一行报错就停下来处理，不要跳过：

终端命令
cd /opt/hxbot
bash server/scripts/backup.sh                              # 1. 备份账号数据库
install -m 600 server/.env /root/hxbot.env.bak             # 2. 备份配置
rm -rf server/account/dist server/account/migrations       # 3. 删除旧的程序文件（不影响数据和配置）
unzip -o /opt/hxbot-server-v1.7.2.zip                      # 4. 解压新版本（压缩包里没有 .env，不会覆盖配置）
cp -r server/portal/. portal/                              # 5. 更新门户首页和使用指南、条款、隐私政策页面
cd server
bash scripts/setup-https.sh                                # 6. 更新 nginx 配置（已有证书不会重新申请，不用写邮箱）
bash scripts/set-env.sh --show                             # 6a. 核对配置：不应有“提醒：”开头的行（见下面的小节）
docker compose up -d --build                               # 7. 重新构建并启动，必须带 --build
bash scripts/check.sh                                      # 8. 检查

第 3 步：确认升级已经生效（两种方法都要做）。

  1. check.sh 每一项都是“通过”（一条命令升级时脚本已经检查过，失败项升级前就有的除外）。其中“运行中的账号服务和网页版就是当前部署包”这一项专门核对容器是不是用新包重建的：它失败，说明第 7 步没有执行或没有带 --build，重新执行第 7、8 步。
  2. cat /opt/hxbot/server/VERSION /opt/hxbot/server/BUILD_COMMIT 显示的版本号和提交号与交付说明里写的一致。
  3. 在浏览器里把已经打开的 bot.hxallai.com 页面全部关掉，重新打开 https://bot.hxallai.com/app （或按 Ctrl+F5）。网页版的界面这时就是新版本。
  4. 桌面端、安卓端、iOS 端的界面改动在客户端里，不随服务器升级：按《客户端构建.md》用同一版本的源码重新打包，再按第 11 节上传到下载中心（最好在升级服务器之前），用户在应用里更新、或者下载安装新安装包后生效。iOS 版的更新步骤在 11.9 节。

手工升级后界面没有变化，几乎都是下面三种情况之一：第 7 步没带 --build（容器还是旧程序）；部署包没有解压到 /opt/hxbot（第 4 步前没有先 cd /opt/hxbot）；浏览器还开着旧页面。

#### 自动更新（可选，默认关闭）

打开后，服务器每天 05:07 到你指定的地址检查有没有新版本：有就下载（这台服务器正好是更新包的起点时下载更新包，否则下载全量包），核对 SHA-256 后用一条命令升级，失败自动回滚（同方法一）。

地址是一个 https 目录，里面放打包时生成的 latest.json 和对应的全量包、更新包：交付目录 dist-hx/ 里的 latest.json、hxbot-server-v版本.zip、hxbot-server-update-v版本.zip 三个文件原样上传，每出一个新版本上传一次（先传两个包，最后传 latest.json）。能改这个目录里文件的人就能让服务器升级，所以要放在只有你能上传的地方，例如阿里云对象存储（OSS）里一个“公共读、私有写”的目录。

终端命令
bash /opt/hxbot/server/scripts/auto-update.sh --enable https://你的地址/hxbot/server/   # 打开（先取一次 latest.json，取不到不会打开）
bash /opt/hxbot/server/scripts/auto-update.sh --status    # 这台服务器的版本、是否打开、最近一次的结果
bash /opt/hxbot/server/scripts/auto-update.sh --now       # 现在就检查一次
bash /opt/hxbot/server/scripts/auto-update.sh --disable   # 关闭

自动更新只换服务器，不会改变用户手上的客户端；新版本的客户端安装包仍按第 11 节上传（客户端随后在应用里更新）。开着自动更新时，也要先上传客户端、再把新版本的服务器包放到这个地址。

从共用登录口令升级（v1.6 之前的版本 → v1.6）

v1.6 之前的版本里，所有人共用一个登录口令。v1.6 起每个人注册自己的账号、用自己的密码登录，共用口令不再能登录。升级时要注意四件事：

一、已经登录的设备不受影响。升级不会让任何人退出；他们的账号、发布的服务器、成员关系都原样保留。只是以后在新设备上登录、或退出后重新登录时，要用自己的密码。

二、每位老用户要设置一次自己的密码。方法是在门户页 https://bot.hxallai.com 点“创建账号”，用原来登录用的那个邮箱注册。注册完成后还是原来的那个账号，原来的服务器、成员关系都在。

三、手工升级第 2 步的 6a 要多做的事。新版本默认开着邮箱验证和手机验证，而旧的 .env 里没有发信邮箱和短信的设置，所以 6a 的 --show 会出现两行“提醒：”。升级前（或在 6a 这一步）二选一：

  • 推荐：按第 5.3 节配好发信邮箱；短信按第 5.4 节，没批下来就先执行 bash scripts/set-env.sh HX_PHONE_VERIFICATION off。这样老用户注册时由邮箱验证码证明这个邮箱是他的。
  • 两项验证都关闭（HX_EMAIL_VERIFICATION off、HX_PHONE_VERIFICATION off）：没有验证码时，老用户注册时要多填一项“原来的登录口令”来证明身份，所以这种情况下先不要清空 .env 里的 HX_LOGIN_PASSWORD。新用户不需要填它。

配好后再执行一次 bash scripts/set-env.sh --show，没有“提醒：”再继续第 7 步。

四、通知用户，并在过渡结束后清掉旧口令。升级完成后发通知，内容参考：“HXBot 已升级为每人一个账号。请打开 https://bot.hxallai.com ，点‘创建账号’，用你原来登录的邮箱注册并设置自己的密码；以后各端都用邮箱和这个密码登录。已经登录的设备不受影响。”

用下面的命令看还有谁没设置密码。输出最后的“以前用共用口令登录过、还没有设置自己密码的邮箱”就是名单；名单空了（这一段不再出现），过渡就结束了：

终端命令
bash scripts/users.sh list

过渡结束后清空旧口令并重启账号服务：

终端命令
bash scripts/set-env.sh HX_LOGIN_PASSWORD ''
docker compose up -d account

清空之后（并且关闭着邮箱验证时），还没设置密码的老用户注册会提示“请联系管理员为这个邮箱设置密码”：核实身份后用 bash scripts/users.sh add 他的邮箱 为他建好账号即可，还是原来的那个账号。开着邮箱验证时不受旧口令影响，随时可以清空。

数据库的备份与恢复

账号数据库（注册资料、绑定的第三方账号、登录会话、服务器目录、成员关系）在 Docker 卷 hxbot_account-state 里（第 8.1 节）。对话内容和文件不在服务器上，而是在各自运行助手的电脑上。

备份用 bash scripts/backup.sh（上表），备份文件是 /opt/hxbot/backups/account-日期-时间.tgz，只有 root 能读，里面有全部用户的个人信息：不要外传；要异地保存时，先加密再传。上线当天就按上表设置每天自动备份。

恢复到某个备份。先用 ls -lt /opt/hxbot/backups 看有哪些备份，把下面命令里的 account-20261108-043000.tgz 换成要恢复的文件名：

终端命令
cd /opt/hxbot/server
docker compose down
docker run --rm --user 0 --entrypoint sh -v hxbot_account-state:/state -v /opt/hxbot/backups:/backup hxbot/account:local \
  -c 'rm -rf /state/* && tar xzf /backup/account-20261108-043000.tgz -C /state && chown -R 1000:1000 /state'
docker compose up -d

恢复会把数据库整个换回备份那一刻的样子：备份之后注册的账号、改过的密码都会回到当时的状态，所以恢复前先再备份一次当前的数据。

14安全说明

  • 账号服务（8787）和信令服务（8081）只监听 127.0.0.1，外网只能经过 nginx 的 HTTPS 访问。
  • 账号服务的本地调试接口 /cdn-cgi/ 和信令的内部接口 /internal/ 已在 nginx 中屏蔽，check.sh 会检查这两项。
  • 下载目录必须登录才能访问，登录状态由账号服务校验；未登录时跳回门户登录。
  • 唯一的例外是 iOS 无线安装（发布了 Ad Hoc 安装包时才有）：/ota/32位随机串/ 下的安装清单和安装包不校验登录，因为来取文件的是手机系统的安装程序。随机串只出现在登录后才能读到的下载列表里，不进访问日志，换安装包时更换；安装包只能装到签名时登记过的设备上。其余 /ota/ 地址一律 404。
  • 每个人用自己的邮箱和密码登录。密码在服务器上只保存加盐哈希（PBKDF2-HMAC-SHA256，10 万次迭代），验证码只保存哈希，10 分钟后失效；管理员也看不到任何人的密码。连续输错、频繁注册和频繁获取验证码都有次数限制。
  • 网页版和手机端能远程连接同一账号登录的桌面端，所以账号被盗用等于电脑被远程访问：发现异常时立即 bash scripts/users.sh disable 邮箱 停用（他在各处的登录立即退出），核实后重置密码再恢复。需要只让指定的人注册时，用注册名单（第 5.6 节）。
  • 关闭邮箱验证后，任何人都可以用别人的邮箱注册，也不能自助找回密码；关闭手机验证后，手机号码只检查格式。除非是内部小范围使用并配合注册名单，否则至少保持邮箱验证开启。
  • 发信邮箱的密码、阿里云短信的 AccessKey、各家第三方登录的密钥都只在 .env 里（权限 600），不进日志、不进部署包。短信的 AccessKey 用只有短信权限的 RAM 子用户（第 5.4 节第 6 步），不要用主账号的。任何一项泄露后，到对应平台的后台重置，再用 set-env.sh 重新填写并 docker compose up -d account。
  • 第三方登录只从对方平台取得用来认人的编号（以及对方返回的昵称），不取得也不保存用户在对方平台的密码、好友、支付等信息。
  • 智能体默认“最大权限”：读取任何位置的文件、运行命令、使用网站和 Computer Use 都不用问；修改工作区以外已有的文件、删除工作区以外的东西、读写存放密钥的位置、以管理员身份运行命令、用保存的密码登录和付款前，先由服务器所有者在卡片上确认（允许一次、始终允许或拒绝）。手动改为“完全访问”的智能体什么都不问，改之前请评估。用户可以在“设置 → 授权与记录”里查看和删除“始终允许”的规则、查看授权记录。
  • 弘犀服务器只负责账号和建立连接，对话、文件在客户端之间点对点加密传输，不经过也不存储在服务器上（无法直连时经中继转发的也是加密数据）。
  • 访问日志写在 /var/log/hxbot/access.log，按《网络安全法》至少保存 6 个月（logrotate 每天轮转，保留 200 天后删除）；日志只记路径，不记查询参数，邀请链接里的凭证不会进日志。《隐私政策》写明的保存期限（账号注销后 30 天内删除、备份最多 30 天、日志约 200 天）以这些设置为准，修改设置时请同步修改政策。

  3. 在应用详情的“产品绑定”（或“添加能力”）里添加“获取会员信息”；页面上有“网站支付宝登录”时也一并添加。
  4. 在“开发设置 → 接口加签方式”点“设置”：加签模式选“公钥”（不要选“公钥证书”），算法选 RSA2。按页面提示用“支付宝开放平台密钥工具”生成一对密钥：把“应用公钥”粘贴到页面上保存；把“应用私钥”存成一个文本文件 alipay-app-private-key.txt。私钥不上传给支付宝，只放到服务器上；密钥工具里“PKCS8”和“PKCS1”两种格式本服务都能读。
  5. 在“开发设置 → 授权回调地址”里填完整地址 https://bot.hxallai.com/api/browser/hx/oauth/alipay/callback。
  6. 提交审核，审核通过后把应用“上线”。应用状态是“已上线”时所有支付宝用户才能用它登录。

把私钥文件传到服务器，再回到第 5.5 节执行“支付宝”一段的两条命令。在你的电脑上执行：

终端命令
scp alipay-app-private-key.txt root@47.119.145.170:/root/

A.3 抖音（抖音开放平台 · 网站应用）

用户看到的是一个二维码，用抖音 App 扫码并确认后登录。要准备：营业执照等企业资质。

  1. 打开 https://open.douyin.com ，注册开发者账号并完成企业认证。
  2. 在控制台的“我的应用”里创建应用，类型选“网站应用”，按本附录开头的表格填写名称、简介和网站地址，上传图标，提交审核。
  3. 审核通过后打开应用详情，在“应用信息”里记下 Client Key 和 Client Secret。
  4. 在应用详情“网站应用”下的“授权回调”里登记回调：页面要求填完整地址时填 https://bot.hxallai.com/api/browser/hx/oauth/douyin/callback，只让填域名时填 bot.hxallai.com。
  5. 在“能力管理”里确认已经有“抖音登录”（获取用户公开信息，权限名 user_info）；没有就申请开通。

回到第 5.5 节执行“抖音”一段的两条命令：Client Key 填进 HX_DOUYIN_CLIENT_KEY，Client Secret 用 --secret 隐藏输入。

A.4 Apple（Sign in with Apple）

要准备：已付费的 Apple 开发者账号（第 11.3 节），操作的人要是账户持有人（Account Holder）或 Admin。下面都在 https://developer.apple.com/account 的“Certificates, Identifiers & Profiles”（证书、标识符和描述文件）里操作，一共要拿到四样：Team ID、Services ID、Key ID、.p8 密钥文件。

第 1 步：建一个开启了 Sign in with Apple 的 App ID。网页登录必须挂在一个开启了这项能力的 App ID 上。左侧点“Identifiers”，点标题旁的“+”，选“App IDs”→“App”：Description 填 HXBot Web Sign In，Bundle ID 选 Explicit 并填 com.hxallai.bot.web；在下面的 Capabilities 里勾选“Sign in with Apple”；点 Continue、Register。（这是专门给网页登录用的 App ID，与 iOS 版的 com.hxallai.bot 分开，互不影响。）

第 2 步：建 Services ID。还是在“Identifiers”，点“+”，选“Services IDs”：Description 填 HXBot（用户在 Apple 的登录页上看到的名字），Identifier 填 com.hxallai.bot.signin；点 Continue、Register。然后在列表里点开它，勾选“Sign in with Apple”，点旁边的“Configure”：

页面上的项填什么
Primary App ID第 1 步建的 com.hxallai.bot.web
Domains and Subdomainsbot.hxallai.com（不带 https://）
Return URLshttps://bot.hxallai.com/api/browser/hx/oauth/apple/callback

点 Next、Done，再点 Continue、Save。最后的 Save 不能漏，漏了等于没配。

第 3 步：建密钥。左侧点“Keys”，点“+”：Key Name 填 HXBot Sign In，勾选“Sign in with Apple”，点“Configure”，Primary App ID 选第 1 步的 com.hxallai.bot.web，Save；点 Continue、Register。页面显示 Key ID（10 位字母数字），点“Download”下载 AuthKey_XXXXXXXXXX.p8。这个文件只能下载一次，下载后马上放进密码管理器备份一份。

第 4 步：查 Team ID。在 https://developer.apple.com/account 的“Membership details”（会员资格详情）里，10 位字母数字。iOS 版已经填过 HX_APPLE_TEAM_ID 的，是同一个值，不用再填。

把 .p8 文件传到服务器，再回到第 5.5 节执行“Apple”一段的四条命令。在你的电脑上执行（把文件名换成实际的）：

终端命令
scp AuthKey_ABC123DEFG.p8 root@47.119.145.170:/root/

用户在 Apple 的页面上可以选择“隐藏邮件地址”。这不影响使用：第一次登录时他还是要在门户上填写自己的邮箱来注册或绑定账号，验证码发到他填的那个邮箱。

A.5 Google（只在境外服务器上）

服务器在中国大陆时不要开启（第 5.5 节）。

  1. 打开 https://console.cloud.google.com ，新建一个项目（例如 hx-bot）。
  2. 在“APIs & Services”（或“Google Auth Platform”）里先配置 OAuth 同意屏幕：应用名称填 HXBot，用户支持邮箱和开发者联系邮箱填 bot@hxallai.com，受众（Audience）选“External”；首页、隐私政策、服务条款填本附录开头表格里的英文地址。
  3. 进入“Clients”（或“Credentials”）→“Create client”：Application type 选“Web application”；在“Authorized redirect URIs”里添加 https://bot.hxallai.com/api/browser/hx/oauth/google/callback；创建后记下 Client ID 和 Client secret。
  4. 在“Audience”里点“Publish app”，把发布状态从 Testing 改成 In production。停在 Testing 状态时，只有你列入名单的测试用户（最多 100 个）能登录，而且授权 7 天后失效。

回到第 5.5 节执行“Google”一段的两条命令。回调地址必须与第 3 步登记的逐字相同，否则 Google 的页面会提示 redirect_uri_mismatch；在后台改完设置后，可能要等几分钟到几小时才生效。

A.6 Facebook（只在境外服务器上）

服务器在中国大陆时不要开启（第 5.5 节）。

  1. 打开 https://developers.facebook.com ，登录后进入“My Apps”→“Create App”，用途选与“Facebook Login”（让用户用 Facebook 账号登录）对应的一项，应用名称填 HXBot。
  2. 在“App settings → Basic”里：记下 App ID；点 App secret 旁的“Show”得到 App Secret；App Domains 填 bot.hxallai.com；Privacy Policy URL 和 Terms of Service URL 填本附录开头表格里的英文地址；保存。
  3. 在“Facebook Login → Settings”的“Valid OAuth Redirect URIs”里添加 https://bot.hxallai.com/api/browser/hx/oauth/facebook/callback，保存。
  4. 在登录用途的权限（Permissions）里确认 public_profile 和 email 两项已添加。
  5. 把页面顶部的应用模式从“Development”切换到“Live”。停在 Development 时，只有这个应用的管理员、开发者和测试用户能登录。

回到第 5.5 节执行“Facebook”一段的两条命令。

附录 B：服务器拉不到镜像时，改用离线镜像

如果第 8 步一直卡在下载镜像，可以在任意一台能访问 Docker Hub 的电脑（例如装了 Docker Desktop 的 Mac）上把镜像做好，再传到服务器。先在服务器上执行 uname -m 确认架构：x86_64 用 linux/amd64，aarch64 用 linux/arm64。

在那台电脑上（解压 hxbot-server-v1.7.2.zip 后进入 server 目录）：

终端命令
P=linux/amd64
docker build --platform $P -t hxbot/account:local account
docker build --platform $P -t hxbot/signal:local signal
docker build --platform $P -t hxbot/coturn:local coturn
docker pull --platform $P certbot/certbot:latest
docker save hxbot/account:local hxbot/signal:local hxbot/coturn:local certbot/certbot:latest | gzip > hxbot-images.tar.gz
scp hxbot-images.tar.gz root@47.119.145.170:/opt/

在服务器上：

终端命令
gunzip -c /opt/hxbot-images.tar.gz | docker load
cd /opt/hxbot/server && docker compose up -d       # 注意不加 --build，直接使用导入的镜像

以后升级时同样先导入新镜像，再执行 docker compose up -d。
