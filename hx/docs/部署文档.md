## 1. 添加域名解析

解析记录要加在 hxallai.com **当前使用的 DNS 服务商**那里。hxallai.com 的 DNS 服务器是腾讯云 DNSPod（`perseus.dnspod.net`、`judith.dnspod.net`），www 的解析也在那里，所以要登录 **DNSPod 控制台**（console.dnspod.cn，或腾讯云控制台 → 云解析 DNS）→ 找到 hxallai.com → **添加记录**。加在阿里云“云解析 DNS”里不会生效。

不确定用的是哪家时，在服务器上执行 `getent ahostsv4 www.hxallai.com` 能看到 IP，再到域名注册商处看“DNS 服务器”一栏：`*.dnspod.net` 是 DNSPod，`*.alidns.com` / `*.hichina.com` 是阿里云。

添加下面 4 条（线路类型选“默认”，记录值都填这台 ECS 的公网 IP 47.119.145.170，TTL 默认即可）：

| 记录类型 | 主机记录 | 记录值 |
| --- | --- | --- |
| A | bot | 47.119.145.170 |
| A | api.bot | 47.119.145.170 |
| A | signal.bot | 47.119.145.170 |
| A | turn.bot | 47.119.145.170 |

这 4 个都是已备案域名 hxallai.com 的子域名，不需要重新备案。

**检查**（在服务器上执行，4 行都应显示 47.119.145.170；刚添加时可能要等几分钟）：

```bash
for h in bot api.bot signal.bot turn.bot; do echo "$h.hxallai.com → $(getent ahostsv4 $h.hxallai.com | awk 'NR==1{print $1}')"; done
```

箭头后面是空的，说明还查不到：先确认记录加在了上面说的 DNS 服务商那里，再等 5 分钟重试。

## 2. 放行端口（安全组）

阿里云控制台 → **云服务器 ECS** → 实例 → 点击这台服务器 → **安全组** → 配置规则 → **入方向** → 手动添加。80、443 官网已经在用，一般已放行，只需补上后面 3 条：

| 协议 | 端口范围 | 授权对象 | 用途 |
| --- | --- | --- | --- |
| TCP | 80/80 | 0.0.0.0/0 | 申请证书、跳转 HTTPS（官网已有则跳过） |
| TCP | 443/443 | 0.0.0.0/0 | HTTPS（官网已有则跳过） |
| TCP 和 UDP 各一条 | 3478/3478 | 0.0.0.0/0 | 中继服务 |
| TCP | 5349/5349 | 0.0.0.0/0 | 中继服务（TLS） |
| UDP | 49152/65535 | 0.0.0.0/0 | 中继服务数据端口 |

如果服务器上还开着系统防火墙（firewalld 或 ufw），也要放行同样的端口：

```bash
# Alibaba Cloud Linux / CentOS（firewalld 正在运行时才需要）
systemctl is-active firewalld && {
  firewall-cmd --permanent --add-port=3478/tcp --add-port=3478/udp --add-port=5349/tcp --add-port=49152-65535/udp
  firewall-cmd --reload
}
# Ubuntu（ufw 已启用时才需要）
ufw status | grep -q '^Status: active' && { ufw allow 3478; ufw allow 5349/tcp; ufw allow 49152:65535/udp; }
```

## 3. 安装 Docker

先看是否已经装好：`docker --version && docker compose version`。两条都有版本号输出就跳到 3.3。

### 3.1 Alibaba Cloud Linux 3

```bash
dnf config-manager --add-repo=https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
dnf -y install dnf-plugin-releasever-adapter --repo alinux3-plus
dnf -y install docker-ce docker-compose-plugin --nobest
systemctl enable --now docker
```

### 3.2 Ubuntu

```bash
apt-get update && apt-get install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" > /etc/apt/sources.list.d/docker.list
apt-get update && apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
systemctl enable --now docker
```

如果最后一条 `apt-get install` 报 “Unable to locate package docker-ce” 或软件源 404（较新的 Ubuntu，例如 26.04，Docker 官方源可能还没有对应版本），改用 Ubuntu 自带的软件包：

```bash
rm -f /etc/apt/sources.list.d/docker.list
apt-get update && apt-get install -y docker.io docker-compose-v2
systemctl enable --now docker
docker compose version     # 能显示版本号即可
```

### 3.3 配置镜像加速（国内服务器必须做）

国内服务器直接访问 Docker Hub 会失败，需要配置镜像加速。**只配阿里云的个人镜像加速器（`https://xxxx.mirror.aliyuncs.com`）现在不够**：它已不再完整提供 Docker Hub 镜像，拉取 `node:24-bookworm-slim` 等镜像会报 `not found`。下面的配置同时使用几个国内可用的公共加速源，Docker 会按顺序逐个尝试。

先看服务器上是否已有 Docker 配置：

```bash
cat /etc/docker/daemon.json 2>/dev/null || echo "没有配置文件"
```

- 显示“没有配置文件”，或里面只有你自己刚加的 `registry-mirrors` 和日志设置：直接执行下面的命令（会整体替换这个文件）。
- 里面还有别的设置（例如 `data-root`、`insecure-registries`）：不要执行下面的命令，改为用 `vi /etc/docker/daemon.json` 把 `registry-mirrors` 一行改成下面命令中的那几个地址，保存后执行 `systemctl restart docker`。
- 注意：重启 Docker 会重启这台服务器上所有正在运行的容器。如果官网或其他业务也用 Docker 运行，请选在访问少的时段操作。

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://docker.m.daocloud.io"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "20m", "max-file": "5" }
}
EOF
systemctl restart docker
docker info 2>/dev/null | grep -A 4 "Registry Mirrors"
```

**检查**：最后一条显示 `Registry Mirrors:` 和上面三个地址。已经申请了阿里云个人加速器的，可以把它作为第四个地址加在列表最后（前一行末尾要加英文逗号），不加也可以。

再一次性试拉部署要用到的 4 个基础镜像：

```bash
for img in node:24-bookworm-slim oven/bun:1.4.2-alpine coturn/coturn:4.17.2-r0 certbot/certbot:latest; do
  docker pull -q "$img" >/dev/null && echo "✔ $img" || echo "✘ $img"
done
docker run --rm node:24-bookworm-slim node -v
```

**检查**：4 行都是 ✔，最后一行显示 `v24.x.x`。有 ✘ 时先等一两分钟再执行一次（加速源第一次拉取某个镜像要先从海外缓存）；仍然失败见第 13 节“拉取镜像失败”。

这几个公共加速源由第三方维护，可用性会变化；只用来拉取上面 4 个官方基础镜像。

## 5. 填写配置并生成密钥

本节不用打开文件编辑：每一步都是现成的命令，复制、粘贴到服务器上执行即可。命令里的值已经按弘犀智能的情况填好，需要按实际情况选择或替换的地方会写明。每条命令都会检查格式，填错会直接说明原因；重新执行同一条命令会覆盖原值。

本节一共八小节：5.1、5.2、5.7、5.8 每台服务器都要做；5.3（发信邮箱）和 5.4（短信）对应注册时默认开启的两项验证，要么配好、要么按小节里的说明先关闭；5.5（第三方登录）和 5.6（注册名单）是可选的。

### 5.1 进入目录，创建配置文件

```bash
cd /opt/hxbot/server
[ -f .env ] || cp .env.example .env      # 已有 .env 时不会覆盖
chmod 600 .env
ls -l .env
```

**检查**：显示 `-rw------- 1 root root … .env`（只有 root 能读写）。

### 5.2 服务器公网 IP

HXBot 与官网装在同一台服务器时，直接执行：

```bash
bash scripts/set-env.sh TURN_PUBLIC_IP 47.119.145.170
```

装在另一台服务器时，把 47.119.145.170 换成那台的公网 IP（ECS 控制台“实例详情”里的“公网 IP”，不是“私有 IP”）。

**检查**：显示 `✔ TURN_PUBLIC_IP（服务器公网 IP）= 47.119.145.170`。

### 5.3 发信邮箱（邮箱验证码，默认开启）

用户注册和找回密码时，服务器用 bot@hxallai.com 给他的邮箱发一封 6 位验证码邮件（10 分钟内有效），主机的邮箱邀请也用它发出。这一步把这个邮箱的 SMTP 地址和密码填进配置。下面以阿里企业邮箱为例。

**第 1 步：允许这个邮箱用 SMTP 发信。**新开通的阿里企业邮箱默认不允许邮箱网页和官方 App 以外的程序登录，要由邮箱管理员放开：

1. 用邮箱管理员账号（postmaster@hxallai.com）登录 https://qiye.aliyun.com 。
2. 左侧“安全管理 → 账号安全 → 访问策略”，找到“三方客户端访问策略”。它开着表示禁止，把它关掉（页面上可以只对部分成员生效时，只放开 bot@hxallai.com 即可）。
3. 左侧“组织与用户 → 员工账号”，点 bot@hxallai.com，切到“功能权限”，在“客户端配置”里打开“IMAP/SMTP”（或“POP3/SMTP”）。

**第 2 步：确定要填哪个密码。**用 bot@hxallai.com 登录网页邮箱，在“设置”里看“三方客户端安全密码”：

- 已开启（或公司统一要求开启）：在那里生成一个安全密码，填上设备名称（例如 hxbot-server）并点“确定”才算生成。第 3 步填这个安全密码，不是邮箱的登录密码。
- 没有开启：第 3 步填邮箱的登录密码。

**第 3 步：把五项填进配置。**前四条整段复制执行，第五条单独复制执行（它在等你输入密码，后面不能跟着别的命令一起粘贴）：

```bash
bash scripts/set-env.sh EMAIL_SMTP_HOST smtp.qiye.aliyun.com
bash scripts/set-env.sh EMAIL_SMTP_PORT 465
bash scripts/set-env.sh EMAIL_SMTP_USERNAME bot@hxallai.com
bash scripts/set-env.sh EMAIL_FROM bot@hxallai.com
```

```bash
bash scripts/set-env.sh --secret EMAIL_SMTP_PASSWORD
```

出现“请输入 EMAIL_SMTP_PASSWORD”时输入第 2 步确定的密码，**屏幕上不会显示**，输完按回车；再输入一次。密码不会留在命令历史里。密码里不能有英文单引号 '。

**检查**：每条都显示一行 `✔ …`，最后一条显示 `✔ EMAIL_SMTP_PASSWORD（发信邮箱密码）= 已填（N 个字符，不显示）`。（每条下面还有一行“服务已在运行时，执行 docker compose up -d account 让新设置生效”，现在服务还没启动，不用管。）

**第 4 步：测试。**

```bash
bash scripts/set-env.sh --test-mail
```

**检查**：显示 `✔ 发信邮箱登录成功：地址和密码都正确。`。这条命令只登录、不发邮件。没有通过时按下表处理，再测一次：

| 屏幕上的提示 | 原因和处理 |
| --- | --- |
| `登录失败：账号或密码不对` | 密码填错；或开启了“三方客户端安全密码”却填了登录密码（回到第 2 步）；或第 1 步没有放开。改密码重新执行 `bash scripts/set-env.sh --secret EMAIL_SMTP_PASSWORD` |
| `连不上 smtp.qiye.aliyun.com:465` | SMTP 地址写错；或服务器出方向的 465 端口不通，用表格下面的命令测一下 |
| `SMTP 端口只能填 465` | 账号服务发信时从第一个字节就加密，只能用 465（SSL）端口，587 和 25 用不了 |

测试服务器能不能连到邮箱的 465 端口（把地址换成你填的 SMTP 服务器）：

```bash
timeout 5 bash -c '</dev/tcp/smtp.qiye.aliyun.com/465' && echo 通 || echo 不通
```

显示“不通”时检查 ECS 安全组的出方向规则（默认全部放行；阿里云默认只封 25 端口，465 不受影响）。

bot@hxallai.com 不在阿里企业邮箱时，SMTP 服务器和密码按下表填，其余步骤相同：

| 邮箱 | SMTP 服务器 | 端口 | 密码填什么 |
| --- | --- | --- | --- |
| 阿里企业邮箱 | smtp.qiye.aliyun.com | 465 | 登录密码；开启了“三方客户端安全密码”时填安全密码 |
| 腾讯企业邮箱 | smtp.exmail.qq.com | 465 | 登录密码；开启了安全登录时填“客户端专用密码” |
| QQ 邮箱 | smtp.qq.com | 465 | 授权码（在邮箱“设置 → 账号”里开启 SMTP 服务后生成），不是 QQ 密码 |
| 163 邮箱 | smtp.163.com | 465 | 授权码（在“设置 → POP3/SMTP/IMAP”里开启后生成），不是登录密码 |

其他邮箱：在它的帮助里查“SMTP 服务器地址”和“SSL 端口”，SSL 端口是 465 就能用。

**想关闭邮箱验证时**（不建议）：`bash scripts/set-env.sh HX_EMAIL_VERIFICATION off`。关闭后的变化：注册时不再验证邮箱，任何人都能用别人的邮箱注册；用户不能自己找回密码，要由管理员重置（第 12 节“用户管理”）。重新开启：`bash scripts/set-env.sh HX_EMAIL_VERIFICATION on`。

### 5.4 短信验证码（手机号验证，默认开启）

用户注册时，服务器通过阿里云短信给他填写的手机号发一条 6 位验证码（10 分钟内有效）。只支持中国大陆手机号，按条计费（验证码短信约 0.045 元/条起，以阿里云价格页为准）。

阿里云短信要先通过三道审核（资质、签名、模板），**最快也要 3～5 个工作日**，运营商实名报备完成、发送稳定还要再等 1～2 周。所以分两种情况：

- **已经有审核通过的签名和验证码模板**：直接做下面的第 6～8 步。
- **还没有**：现在先关掉手机验证，让服务器按时上线；同时按第 1～5 步提交申请，批下来后做第 6～8 步，再把验证打开。

```bash
bash scripts/set-env.sh HX_PHONE_VERIFICATION off      # 暂时关闭手机验证；批下来后改成 on
```

关闭期间，注册时仍然要填手机号码，只检查格式、不发短信，也可以填其他国家和地区的号码（写 + 和国家代码）。

阿里云控制台的页面会改版，下面各项的名称以页面实际显示为准，意思对应即可。

**第 1 步：阿里云账号完成企业实名认证。**登录 https://www.aliyun.com ，在账号中心的“实名认证”里确认是企业认证。个人认证的账号过不了短信签名的实名制报备，不能用。

**第 2 步：开通短信服务。**打开短信服务控制台 https://dysms.console.aliyun.com ，第一次进入时按提示点“开通”（开通本身不收费）。

**第 3 步：申请资质。**控制台左侧“国内消息 → 资质管理 → 添加资质”：用途选“自用”，按页面上传营业执照、法定代表人证件和管理员证件，填写管理员手机号并验证，提交。审核约 2 个工作日。

**第 4 步：申请签名。**资质通过后，“国内消息 → 签名管理 → 添加签名”：

| 页面上的项 | 填什么 |
| --- | --- |
| 签名名称 | `弘犀智能`（这就是短信开头【】里的字） |
| 关联资质 | 第 3 步通过的资质 |
| 签名来源 | 签名用公司简称时选“企事业单位的全称或简称”；也可以用已备案网站名、已上线 App 名或商标名，选对应的一项 |
| 适用场景（页面上有这一项时） | 选包含验证码的那一项（“验证码”或“通用”） |
| 场景说明 | 例如：用于 HXBot（bot.hxallai.com）用户注册时验证手机号码 |

审核一般在 2 小时内完成（每天 9:00～21:00）。企业自用资质通过后，阿里云通常会赠送一个与资质对应的签名，已经有了就不用再申请。

**第 5 步：申请模板。**“国内消息 → 模板管理 → 添加模板”：

| 页面上的项 | 填什么 |
| --- | --- |
| 模板类型 | 验证码 |
| 模板名称 | HXBot 注册验证码 |
| 模板内容 | `您的验证码为${code}，10分钟内有效，请勿告诉他人。` |
| 变量属性 | 变量 `code` 选“仅数字” |
| 关联签名 | 第 4 步的签名 |
| 申请说明 | 例如：用户在 bot.hxallai.com 注册账号时，向其填写的手机号发送 6 位数字验证码 |

**模板里只能有一个变量，而且名字必须是 `code`**（写成 `${code}`）：服务器发短信时只传这一个值，变量名不一致短信发不出去。审核一般在 2 小时内完成，通过后在模板列表里记下“模板 CODE”，形如 `SMS_123456789`。

**第 6 步：创建只能发短信的 AccessKey。**不要用阿里云主账号的 AccessKey。打开 RAM 控制台 https://ram.console.aliyun.com ：

1. 左侧“身份管理 → 用户 → 创建用户”：登录名称填 `hxbot-sms`，访问方式只勾选“使用永久 AccessKey 访问”（旧版页面叫“OpenAPI 调用访问”），确定。
2. 页面显示 AccessKey ID 和 AccessKey Secret。**Secret 只显示这一次**，现在就复制保存到密码管理器里。
3. 回到用户列表，在 `hxbot-sms` 一行点“添加权限”，搜索并选中 `AliyunDysmsFullAccess`（管理短信服务的权限），确定。

**第 7 步：确认账户里有钱或有套餐包。**在短信服务控制台购买“国内短信套餐包”，或给阿里云账户充值（没有套餐包时按量从余额扣）。建议同时在控制台的“通用设置”里设置每日发送总量上限和余额预警，防止有人恶意刷短信。

**第 8 步：把四项填进配置并测试。**把 AccessKey ID、签名名称、模板 CODE 换成你自己的：

```bash
bash scripts/set-env.sh HX_SMS_ACCESS_KEY_ID 你的AccessKeyID
bash scripts/set-env.sh HX_SMS_SIGN_NAME 弘犀智能
bash scripts/set-env.sh HX_SMS_TEMPLATE_CODE SMS_123456789
```

```bash
bash scripts/set-env.sh --secret HX_SMS_ACCESS_KEY_SECRET
```

签名名称要与控制台里审核通过的一字不差，不带【】。然后给自己的手机发一条真实的验证码短信（按 1 条计费）：

```bash
bash scripts/set-env.sh --test-sms 你的手机号
```

**检查**：屏幕显示 `✔ 阿里云已接收。请看这部手机：应在 1 分钟内收到短信，里面的验证码是 ……`，并且手机在 1 分钟内收到短信，短信里的 6 位数字与屏幕上的相同。通过后，之前关掉过手机验证的，执行 `bash scripts/set-env.sh HX_PHONE_VERIFICATION on` 打开。

没有通过时，屏幕上会显示阿里云返回的错误码和“怎么办”，常见的几种：

| 阿里云返回 | 原因和处理 |
| --- | --- |
| `InvalidAccessKeyId.NotFound`、`SignatureDoesNotMatch` | AccessKey ID 或 Secret 不对。重新执行第 8 步对应的那一条 |
| `isp.RAM_PERMISSION_DENY`、`Forbidden.RAM` | 第 6 步没有给 `hxbot-sms` 加 `AliyunDysmsFullAccess` |
| `isv.SMS_SIGNATURE_ILLEGAL` | 签名不存在或还没审核通过；或签名名称与控制台里的不完全一样 |
| `isv.SMS_TEMPLATE_ILLEGAL` | 模板不存在或还没审核通过；或模板 CODE 填错 |
| `isv.TEMPLATE_MISSING_PARAMETERS` | 模板里的变量名不是 `code`。按第 5 步重新申请模板 |
| `isv.BUSINESS_LIMIT_CONTROL` | 这个号码收验证码太频繁。设置没有问题，过几分钟再试或换一个号码 |
| `isv.AMOUNT_NOT_ENOUGH`、`isv.OUT_OF_SERVICE` | 余额不足或欠费。做第 7 步 |
| 显示已接收，但手机一直收不到 | 到控制台“发送记录”里看这一条的状态。签名刚通过审核时，运营商实名报备还没完成，部分号码会收不到，等几个工作日 |

频率限制（知道即可）：阿里云默认对同一个手机号每分钟最多发 1 条、每小时 5 条、每天 10 条验证码；本服务自己也限制同一个号码 60 秒内只能获取一次、每天最多 10 条。

### 5.5 第三方登录（可选，批下来一家开一家）

门户登录框下面可以出现“或者用下面的账号登录”和六家的按钮：微信、支付宝、抖音、Apple、Google、Facebook。**一家都不配置也能正常上线**，以后随时可以加。每一家都要先用公司名义在它的开放平台创建应用并通过审核，拿到应用编号和密钥，再把它们填进配置。六家的申请步骤在文末**附录 A**，这里是总表：

| 平台 | 要填的设置 | 在它的后台登记的回调地址 | 服务器在中国大陆时 |
| --- | --- | --- | --- |
| 微信 | `HX_WECHAT_APP_ID`、`HX_WECHAT_APP_SECRET` | 授权回调域：`bot.hxallai.com` | 可用（电脑上扫码登录） |
| 支付宝 | `HX_ALIPAY_APP_ID`、`HX_ALIPAY_PRIVATE_KEY` | `https://bot.hxallai.com/api/browser/hx/oauth/alipay/callback` | 可用 |
| 抖音 | `HX_DOUYIN_CLIENT_KEY`、`HX_DOUYIN_CLIENT_SECRET` | `https://bot.hxallai.com/api/browser/hx/oauth/douyin/callback`（页面只让填域名时填 `bot.hxallai.com`） | 可用（用抖音 App 扫码） |
| Apple | `HX_APPLE_TEAM_ID`、`HX_APPLE_SERVICE_ID`、`HX_APPLE_KEY_ID`、`HX_APPLE_PRIVATE_KEY` | `https://bot.hxallai.com/api/browser/hx/oauth/apple/callback` | 可用；需要付费的 Apple 开发者账号（第 11.3 节） |
| Google | `HX_GOOGLE_CLIENT_ID`、`HX_GOOGLE_CLIENT_SECRET` | `https://bot.hxallai.com/api/browser/hx/oauth/google/callback` | **不可用**，见下 |
| Facebook | `HX_FACEBOOK_APP_ID`、`HX_FACEBOOK_APP_SECRET` | `https://bot.hxallai.com/api/browser/hx/oauth/facebook/callback` | **不可用**，见下 |

**Google 和 Facebook 在现在这台服务器上用不了。**用户在这两家的页面上同意之后，账号服务要从服务器连到 Google、Facebook 的接口去换取身份；中国大陆的服务器连不上这两家的接口，登录会卡在最后一步。只有把 HXBot 部署在中国大陆以外的服务器上，并且用户的网络也能打开这两家网站时，才开启它们。第 9 节的 check.sh 会逐家检查服务器能不能连上。

**用户看到的过程。**点某一家的按钮 → 在这一家的页面上扫码或同意 → 回到门户。这个第三方账号第一次来时，门户显示“还差一步”：选“注册新账号”（照常填写邮箱、手机号码、用户名、密码、职位、公司名称，开着的验证照常要过），或者输入已有账号的邮箱和密码“绑定并登录”。以后再点这一家的按钮就直接登录。桌面端、安卓端和 iOS 端的登录界面只有邮箱 + 密码，没有这些按钮：用第三方账号注册的人，在注册时也设置了密码，在客户端里用邮箱和这个密码登录。

**填写命令。**拿到某一家的应用编号和密钥后，执行它那一段命令。示例里的编号都是假的，换成你自己的。带 `--secret` 的一条会让你隐藏输入密钥（输两次，屏幕上不显示）；带 `--file` 的一条读入密钥文件。**一次只复制一段**：`--secret` 那条在等你输入，后面不能跟着别的命令一起粘贴。

微信：

```bash

bash scripts/set-env.sh --secret HX_WECHAT_APP_SECRET
```

### 5.6 注册名单（可选，默认不限制）

默认任何邮箱都可以注册（qq.com、163.com、公司邮箱都可以）。两条一起复制执行：

```bash
bash scripts/set-env.sh HX_ALLOWED_EMAIL_DOMAINS ''
bash scripts/set-env.sh HX_ALLOWED_EMAILS ''
```

**检查**：两行都显示 `= （空）`。

只想让指定的人注册时，把邮箱域名写进第一条、或把一个个邮箱写进第二条，多个用英文逗号分隔，例如：`bash scripts/set-env.sh HX_ALLOWED_EMAIL_DOMAINS 'hxallai.com'`、`bash scripts/set-env.sh HX_ALLOWED_EMAILS 'zhang@qq.com,li@163.com'`。填了任意一项后，只有名单内的邮箱能注册和登录，名单外的会提示“该邮箱不在研究版名单中”。服务启动之后再改名单，改完执行 `docker compose up -d account` 生效。

第二条复制门户首页和 `pages/` 目录（使用指南、服务条款、隐私政策的中英文页面）。最后一条会提示“还没有安装包”，正常。安装包在客户端构建好之后上传（第 11 节）。

### 8.1 数据库（自动建好，不用安装）

用户账号存在账号服务自带的轻量数据库（SQLite）里，**不需要单独安装数据库软件，也没有数据库账号、密码和端口要配置**：账号服务第一次启动时自动创建数据库并建好全部数据表，以后每次升级启动时自动补上新版本增加的表。

| 项目 | 说明 |
| --- | --- |
| 数据库文件在哪里 | Docker 数据卷 `hxbot_account-state` 里（容器内的 `/state` 目录）。`docker compose down`、重启、升级都不会删除它 |
| 里面有什么 | 注册资料（邮箱、用户名、手机号码、职位、公司名称、密码的哈希）、绑定的第三方账号、登录会话、服务器目录、成员关系和邀请。密码只保存加盐哈希，验证码只保存哈希，任何人（包括管理员）都看不到原文 |
| 没有什么 | 对话内容和文件。它们在各自运行助手的电脑上，不经过也不保存在这台服务器上 |
| 怎么查看和管理 | 用 `bash scripts/users.sh`（第 12 节“用户管理”）。不要直接打开或修改数据库文件 |
| 怎么备份 | `bash scripts/backup.sh`，并设置每天自动备份（第 12 节） |

确认数据库已经建好：

```bash
docker compose logs account | grep -E '登录方式|第三方登录|数据库迁移'
bash scripts/users.sh list
```

**检查**：第一条显示三行，形如下面这样（括号里的“开启 / 关闭”和第三方登录的名单与你在第 5 节的设置一致）；第二条显示 `注册用户：0 个`（它会暂停账号服务几秒再自动启动）。

```text
账号服务：登录方式为邮箱 + 密码（注册账号；邮箱验证开启，手机验证关闭）
账号服务：第三方登录已开启： 无
账号服务：应用数据库迁移……
```

## 10. 注册第一个账号并验证

用你自己的邮箱和手机走一遍用户会走的过程：

1. 用电脑浏览器打开 https://bot.hxallai.com ，在登录框里点“创建账号”。
2. 填邮箱和手机号码，点“下一步”。页面提示“验证码已发送，10 分钟内有效”：邮箱收到一封标题为“HXBot 验证码 / Your HXBot verification code”的邮件（开着邮箱验证时）；手机收到一条验证码短信（开着手机验证时）。
3. 填邮箱验证码、短信验证码（哪一项验证关着，哪一项就不出现）、用户名、密码（8～32 个字符，字母、数字、符号都要有，输两次）、职位、公司名称，点“完成注册”。
4. 页面显示“已登录”和四个平台的下载卡片（安装包未上传时显示“安装包尚未上传”）。
5. 点右上角的“退出登录”，再用邮箱和刚才的密码登录。故意输错一次密码，应提示“邮箱或密码不正确”。
6. 退出后点“忘记了密码？”，输入邮箱，收到验证码邮件后设置一个新密码，能直接登录（关闭了邮箱验证时没有自助找回密码，跳过这一步）。
7. 点“进入网页版”，能看到 HXBot 网页版的“连接服务器”页面。
8. 回到门户，页脚的“使用指南”“服务条款”“隐私政策”都能打开；点右上角 English 后再点这三个链接，打开的是英文版。
9. 开启了第三方登录的：退出后点对应的按钮，按第 5.5 节“用户看到的过程”走一遍。

在服务器上确认账号已经进了数据库：

```bash
cd /opt/hxbot/server && bash scripts/users.sh list
```

**检查**：显示 `注册用户：1 个`，下面一行是你的邮箱、用户名、手机号码、公司名称、职位和注册时间。

到这里服务器端就部署完成了。第 2 步收不到邮件或短信、第 3 步提示出错时，见第 13 节“注册和登录”的几条。

注册的规则（回答用户问题时用得上）：

| 项目 | 规则 |
| --- | --- |
| 邮箱 | 一个邮箱只能注册一个账号，注册后不能改。登录、找回密码都用它 |
| 用户名 | 2～32 个字符，可以用中文、字母、数字和 `_` `.` `-`，不能与别人重复（不区分大小写） |
| 密码 | 8～32 个字符，字母、数字、符号都要有。服务器只保存加盐哈希 |
| 手机号码 | 开着手机验证时只能填中国大陆手机号（11 位）；关闭时也可以填其他国家和地区的号码（+ 和国家代码） |
| 职位、公司名称 | 各 1～64 个字符，必填 |
| 验证码 | 6 位数字，10 分钟内有效；输错 5 次要重新获取；60 秒内不能重复获取 |
| 频率限制 | 同一个邮箱 15 分钟内最多发起 6 次注册，同一个网络 20 次；同一个手机号每天最多 10 条短信 |
| 在哪里注册 | 只在门户页 https://bot.hxallai.com 注册。桌面端、安卓端、iOS 端的登录界面用邮箱 + 密码登录，上面写着注册地址 |

### 服务器邀请链接（邀请同事加入）

“服务器”指运行 HXBot 桌面端的那台电脑，不是这台阿里云服务器。邀请链接由那台电脑的所有者在桌面端创建，每个链接都不同，形如：

```
https://bot.hxallai.com/join?api=https://api.bot.hxallai.com&server=<服务器编号>&fingerprint=<身份指纹>&invite=<一次性凭证>
```

链接里带着服务器编号、身份指纹和凭证，所以没有、也不能提前给出一个通用的邀请链接。

所有者创建链接：

1. 在 Mac 或 Windows 上打开 HXBot 桌面端，用邮箱和密码登录。
2. 在左侧服务器栏右键当前服务器，选“服务器设置”，打开“成员”。
3. 打开“发布该服务器”，显示“可在公网访问，仅受邀者可以登录”。
4. 点“邀请成员”，邀请方式选“邀请链接”，选角色（成员或管理员），点“创建链接”，再点“复制链接”发给同事；对方用手机时可点“显示邀请二维码”扫码加入。

同事加入：在下载页登录后，打开网页版 `https://bot.hxallai.com/app` 点“用邀请加入”（或在自己的桌面端、安卓端点“添加服务器”），粘贴链接，点“查看邀请”并确认。也可以直接在浏览器里打开邀请链接。

一次性链接 24 小时后过期、只能用一次；“永久链接”不会过期、可多次使用，任何拿到它的人都能加入，只发给信任的人，不用时在“待处理的邀请”里撤销。邀请方式建议选“邀请链接”；配好了发信邮箱（第 5.3 节）时也可以选“邮箱”，由服务器把邀请发到对方邮箱。下载页 `https://bot.hxallai.com/`（英文 `/en/`）的“服务器邀请链接”一节有同样的说明。

## 11. 上传客户端安装包

客户端在 GitHub 上打包，或者在各自的系统上打包（Mac 版在 Mac 上、Windows 版在 Windows 上），方法见《客户端构建》。**每个新版本上传客户端按《上线操作手册》第 3 步做**（已经按这台服务器写好）；本节是第一次部署时的上传方法和原理。打好的安装包传到服务器的下载中心，用户登录下载页就能下载。iOS 版比另外三个多出“注册苹果开发者账号”这一段，从 11.2 节起单独、完整地写。

### 11.1 Mac、Windows、Android 安装包

在打包的那台电脑上（源码目录里）执行，一次可以传多个文件：

```bash
bash hx/scripts/upload-downloads.sh root@47.119.145.170 dist/HXBot-0.68.0-arm64.dmg
```

**Mac 版要有固定签名（v1.6.8 起）。**在 Mac 上上传时，脚本先从 dmg 旁边的 zip 里取出 HXBot.app，核对签名身份是 HXBot 的固定证书（或以后的 Developer ID）；没有固定签名的包（例如在自己 Mac 上打的）不上传，因为 macOS 按签名记授权，这样的包一传上去，所有 Mac 用户升级后都要重新授权。发布用 GitHub 上打的 Mac 包，见《客户端构建》第 6.3 节第二部分。

**应用内更新用的文件会一并上传。**打包时 dmg 和 exe 旁边还会生成几个文件，用户在应用里更新时用的就是它们：Mac 的 `HXBot-版本号-arm64.zip` 和 `latest-mac.yml`，Windows 的 `HXBot-版本号-x64.exe.blockmap` 和 `latest.yml`。上传 dmg 或 exe 时，这条命令会把同一目录里、同一版本的这几个文件放到服务器的 `/opt/hxbot/downloads/updates/desktop/`，`latest*.yml` 最后传，服务器核对文件都齐了才换上，换上之前已经装好的客户端看到的还是原来的版本。旧版本的 `.blockmap` 留在服务器上（Windows 增量下载要用），旧的 Mac ZIP 自动删除。命令输出的“应用内更新”一段列出现在各端在应用里能更新到的版本；某个文件缺了或版本对不上，会提示“这次不更新 …… 的应用内更新”，这时用户仍能在下载页手动下载新版。

安卓安装包传上去后，下载中心同时给它一个随机串地址（`/ota/随机串/HXBot.apk`）：手机里点“更新”时由系统浏览器下载，系统浏览器不带登录状态，所以和 iOS 的无线安装一样用随机串；换了安装包就换新的随机串，旧地址随即失效。

也可以用任何方式（如 SFTP 工具）把文件放进服务器的 /opt/hxbot/downloads/（应用内更新的文件放进 /opt/hxbot/downloads/updates/desktop/，`latest*.yml` 改名为 `latest*.yml.new` 最后放），再在服务器上运行：

```bash
chmod 644 /opt/hxbot/downloads/HXBot-*
python3 /opt/hxbot/server/scripts/publish-downloads.py /opt/hxbot/downloads
```

文件名必须是下面四种之一，门户页才会识别。每个平台只显示版本最新的一个：

| 平台 | 文件名 |
| --- | --- |
| Mac（Apple 芯片） | HXBot-版本号-arm64.dmg |
| Windows | HXBot-版本号-x64.exe |
| Android | HXBot-版本号-android.apk |
| iPhone / iPad | HXBot-版本号-ios.ipa（只有“直接安装”这条路线才上传 ipa，见 11.7 节） |

### 11.2 iOS 版：先看懂整条路

> 没有付费的 Apple 开发者账号和团队号，就打不出能上 TestFlight 或直接装到 iPhone 上的签名包。苹果不允许像安卓那样把安装包随便装到手机上，所以 iOS 版必须先办账号。

整条路一共六步，前三步每个公司只做一次：

| 步骤 | 做什么 | 在哪里做 | 大约要多久 | 章节 |
| --- | --- | --- | --- | --- |
| 1 | 注册苹果开发者账号、付年费、拿到团队号 | iPhone + 浏览器 | 办理本身 1 小时；等邓白氏编码和苹果审核通常几个工作日到两周 | 11.3 |
| 2 | 准备打包用的 Mac | Mac | 1～2 小时（主要是下载 Xcode） | 11.4 |
| 3 | 打包 | Mac | 第一次 30～60 分钟，以后 20～30 分钟 | 11.5 |
| 4 | 发布：TestFlight（推荐）或直接安装 | Mac + 浏览器 | TestFlight 第一次要等苹果审核，通常一个工作日左右 | 11.6、11.7 |
| 5 | 用户安装 | 用户的 iPhone | 3 分钟 | 11.8 |
| 6 | 以后发布更新 | Mac + 浏览器 | 30 分钟 | 11.9 |

上表里的等待时间是经验值，苹果和邓白氏都不承诺具体时间。

**费用：**苹果开发者计划每年 688 元（中国大陆，在 Apple Developer App 里支付时的价格；其他地区为 99 美元或等值当地货币）。邓白氏编码通过苹果的入口申请是免费的。除此之外没有别的费用。

**两种发布方式怎么选：**

| | 路线 A：TestFlight（推荐） | 路线 B：直接安装（Ad Hoc） |
| --- | --- | --- |
| 谁能装 | 拿到邀请链接的任何 iPhone / iPad，最多 10000 人 | 只有打包前在开发者账号里登记过的设备，每年最多 100 台 iPhone、100 台 iPad |
| 要不要收集用户的设备编号 | 不要 | 要，每台设备都要先拿到 UDID 并登记 |
| 苹果审核 | 给公司以外的人用，第一个构建要审核；只给团队成员用不审核 | 不审核 |
| 用户怎么装 | 装苹果的 TestFlight 应用，点下载页的按钮 | 用 Safari 打开下载页点“安装”，再打开一次开发者模式 |
| 有效期 | 每个构建 90 天，到期前上传新的 | 到描述文件过期为止，最长一年 |
| 加一个新用户 | 把链接发给他 | 登记他的设备、重新打包、重新上传 |

建议：给客户用就走路线 A。路线 B 只适合公司自己的几台测试机，或者在等 TestFlight 审核时先装上看看。两条路线可以同时用，下载页会同时显示。

**不要选错计划：**要加入的是 Apple Developer Program（688 元 / 年）。另有一个名字相近的 Apple Developer Enterprise Program（299 美元 / 年），它只给 100 人以上的大公司分发内部应用，申请不下来，也不需要。

### 11.3 第一步：注册苹果开发者账号并付费

以公司名义注册。全部在一台 iPhone 或 iPad 上完成，**从头到尾必须用同一台设备**。

**先备齐这些东西：**

| 要准备的 | 要求 |
| --- | --- |
| 一台 iPhone 或 iPad | 已设置锁屏密码（或面容 ID、触控 ID），系统升到最新 |
| 办理人 | 公司的法定代表人、创始人或高管；或者得到他们授权的员工（这时要另外提供一位能证明授权的同事的姓名、电话、邮箱）。办理人以后就是这个开发者账号的“账户持有人” |
| 办理人的身份证 | 注册时要填身份证号并当场自拍验证 |
| 公司信息 | 营业执照上的公司全称、总部地址和电话 |
| 公司邮箱 | 域名属于公司的邮箱，例如 xxx@hxallai.com（不要用 QQ、163 等个人邮箱） |
| 公司网站 | https://www.hxallai.com ，要能公开访问、有实际内容 |
| 付款方式 | 绑定在 Apple 账户上的支付宝、微信支付或银联卡。**不能用 Apple 账户余额**（充值卡、直接充值的钱都不行） |

**第 1 步：新建一个公司专用的 Apple 账户，并打开双重认证。**不要用个人平时用的 Apple 账户。在浏览器打开 https://account.apple.com ，点“创建你的 Apple 账户”：

- 姓名填办理人的真实姓名（和身份证一致）。不要填公司名、昵称，否则审核会被退回。
- 邮箱填上面准备的公司邮箱，手机号填办理人的手机号。
- 创建完成后，在那台 iPhone 上用这个账户登录（设置 → 最上面的“登录 iPhone”）。登录后进“设置 → 你的姓名 → 登录与安全性”，“双重认证”一行要显示“已开启”。

**第 2 步：申请邓白氏编码（D-U-N-S Number）。**这是一个 9 位数字的企业编号，苹果用它核实公司是真实存在的法人。

1. 在浏览器打开 https://developer.apple.com/enroll/duns-lookup/ ，用第 1 步的 Apple 账户登录。
2. 按页面填写公司全称、总部地址、通信地址和办理人的工作联系方式，提交查询。
3. 页面显示公司已有编号：编号会发到你填的邮箱，记下来。
4. 页面显示查不到：按提示把资料提交给邓白氏申请，免费。之后邓白氏可能来电话或邮件核实公司类型、人数等，手边备好营业执照。
5. 拿到编号后，**再等 2 个工作日**，让苹果那边同步到这条记录，然后才做第 3 步。早做会提示查不到公司。

> 公司必须是法人实体（有限责任公司、股份有限公司等）。个体工商户、分公司、只有商号没有注册的不能以公司名义注册。邓白氏回复邮件里写的公司名称（常常是英文或拼音）请保存好，第 3 步要原样填写。

**第 3 步：在 Apple Developer App 里提交注册。**

1. 在那台 iPhone 的 App Store 里搜索并安装“Apple Developer”（开发者是 Apple）。
2. 打开它，点底部的“账户”（Account），用第 1 步的 Apple 账户登录。提示同意《Apple Developer Agreement》就同意。
3. 点“立即注册”（Enroll Now），看完说明点“继续”。
4. 填办理人信息：姓、名、身份证号、手机号。
5. 按提示自拍：脸在取景框内、光线充足，拍完确认清晰。
6. 实体类型选公司 / 组织（Company / Organization）。
7. 填公司信息：法定实体名称（**照邓白氏邮件里的名称原样复制**）、邓白氏编码、总部地址和电话、公司网站。
8. 确认你有权代表公司签约。不是创始人或法定代表人时，填那位能证明授权的同事的联系方式。
9. 提交。屏幕上会显示一个注册编号（Enrollment ID），截图保存，找苹果客服时要用。

**第 4 步：等苹果审核。**苹果核实公司信息后会发邮件说明下一步，期间也可能来电话或邮件核实，注意接听陌生来电、查看垃圾邮件箱。审核通过时会收到一封邮件，告诉你可以完成注册了。想查进度：用这个 Apple 账户登录 https://developer.apple.com/account 。

**第 5 步：付年费。**收到“可以完成注册”的邮件后：

1. 先确认付款方式：iPhone 的“设置 → 你的姓名 → 付款与配送”里有一种可用的付款方式（支付宝、微信支付或银联卡）。想用公司的卡，就把它加在这里。
2. 在**同一台设备**上打开 Apple Developer App → 账户 → “继续注册”（Continue Enrollment）。
3. 阅读并同意《Apple Developer Program 许可协议》。
4. 核对年度订阅的内容，点“以每年 ¥688 续订”，按提示完成支付。
5. 收据会发到邮箱，可以用来报销；以后在“设置”的购买历史记录里可以随时重发。

这是按年自动续期的订阅，每年到期自动扣 688 元；不想续了，最晚在续订日的前一天到“设置”里取消订阅，已付的年费不退。付款后 24 小时内没有收到会员确认，带着注册编号联系苹果开发者支持（ https://developer.apple.com/contact/ ）。

**第 6 步：记下团队号。**在浏览器登录 https://developer.apple.com/account ，往下找到“会员资格详细信息”（Membership details），里面的“团队 ID”（Team ID）是 10 位大写字母和数字，例如 `ABCDE12345`。**把它记下来**，后面两个地方要用：打包命令（11.5 节）和服务器配置（11.6 节第 9 步）。

**第 7 步：登录一次 App Store Connect。**用同一个账户登录 https://appstoreconnect.apple.com ，如果提示有协议要同意就同意。HXBot 是免费应用，不需要填税务和银行信息。

到这里账号就办好了。以后每年只要保证付款方式有效（11.10 节）。

> 公司的邓白氏编码一时办不下来、又着急用：可以先用办理人的个人身份注册（同样 688 元 / 年，不需要邓白氏编码，提交时当场付款）。区别是应用的开发者一栏显示的是个人姓名而不是公司名。以后可以向苹果申请把个人会员资格转成公司的，条件是办理人是公司创始人并提供邓白氏编码。

### 11.4 第二步：准备打包用的 Mac

需要一台 Apple 芯片的 Mac（M1 及以后），可用磁盘 50 GB 以上，并且**能稳定访问 GitHub、npm 和 CocoaPods**（打包时要从这些地方下载依赖，访问不了后面每一步都会卡住）。下面七件事只做一次。

**第 1 步：安装 Xcode。**打开 Mac 上的 App Store，搜索 Xcode，点“获取”。文件很大，要下载一小时以上。装好后**打开一次**：同意许可，弹出平台选择时保持 iOS 勾选，等它把组件装完再关掉。然后打开“终端”，逐行执行（第一行会要求输入 Mac 的开机密码，输入时屏幕上不显示字符，输完按回车）：

```bash
sudo xcode-select -s /Applications/Xcode.app
sudo xcodebuild -license accept
sudo xcodebuild -runFirstLaunch
xcodebuild -version
```

最后一行应显示 `Xcode 26` 或更大的版本号。App Store 提示系统版本太低时，先在“系统设置 → 通用 → 软件更新”升级 macOS（Xcode 26 要求 macOS 15.6 或更新，更新的 Xcode 要求更高，以 App Store 页面显示的为准）。

**第 2 步：在 Xcode 里登录开发者账号。**打开 Xcode → 菜单栏 Xcode → Settings（设置）→ Accounts（账户）→ 左下角 `+` → Apple Account → 用 11.3 节的账户登录。登录后右侧应出现公司名称的团队。

**第 3 步：安装 Homebrew 和 CocoaPods。**逐行执行。第一行会要求输入开机密码，并提示按回车继续：

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"
brew install cocoapods
```

**第 4 步：安装 Node.js 24。**在浏览器打开 https://nodejs.org/dist/latest-v24.x/ ，下载文件名以 `.pkg` 结尾的那一个，双击按提示安装。

**第 5 步：安装 Bun。**

```bash
curl -fsSL https://bun.com/install | bash -s "bun-v1.4.2"
```

装完**关掉终端重新打开**，后面的命令才认得 bun。

**第 6 步：登记至少一台 iPhone 或 iPad。这一步不能省**：开发者账号里一台设备都没有时，Xcode 生成不了签名用的描述文件，打包会失败（报 `Your team has no devices`）。走路线 B 的，把要安装的每一台设备都在这里登记。

1. 取设备编号（UDID）：用数据线把 iPhone 连到 Mac，手机上点“信任”。打开“访达”，在左边栏点这台 iPhone，再点设备名称下面那一行灰色小字（型号、容量那一行），点到显示 UDID 为止，在上面点右键 →“拷贝 UDID”。
2. 在浏览器打开 https://developer.apple.com/account/resources/devices/list ，点“Devices”旁边的 `+`。
3. Platform 选 iOS, iPadOS, tvOS, watchOS, visionOS；Device Name 填一个认得出的名字（如“张三的 iPhone”）；Device ID (UDID) 粘贴刚才拷贝的编号。
4. 点 Continue，再点 Register。

用户不在身边、手边也没有 Mac 时，让他在 Windows 电脑上装 iTunes，连上手机后点设备图标，在“摘要”页点“序列号”那一行，它会变成 UDID，右键拷贝后发给你。

**第 7 步：解压源码并检查环境。**把源码包 `hxbot-source-v1.7.1.zip` 拷到 Mac 上，在终端里进入它所在的文件夹：

```bash
unzip hxbot-source-v1.7.1.zip
cd hx-bot
bash hx/scripts/build-ios.sh --check
```

每一行都是 `[通过]` 才算准备好。出现 `[缺少]` 的，照它下面“处理”一行做完，再运行一次。全部通过时屏幕显示：

```text
检查这台 Mac 的打包环境……
  [通过] macOS 26.2
  [通过] Xcode 26.4
  [通过] CocoaPods 1.16.2
  [通过] Bun 1.4.2
  [通过] Node.js 24.11.0
  [通过] Python 3.9.6
  [提示] 还没有给团队号。构建时在命令前加 HX_APPLE_TEAM_ID=你的团队号（部署文档 11.3 节第 6 步说明在哪里看）

环境检查通过。另外有两件事脚本查不出来，请自己确认（部署文档 11.4 节）：
  1. Xcode → Settings（设置）→ Accounts（账户）里已经登录开发者账号；
  2. 开发者账号里已经登记了至少一台 iPhone 或 iPad（一台都没有时归档会失败）。
确认后开始构建：HX_APPLE_TEAM_ID=你的团队号 bash hx/scripts/build-ios.sh
```

### 11.5 第三步：打包

在源码目录（上一步的 `hx-bot`）里执行，把 `ABCDE12345` 换成你的团队号。两条路线的命令只差前面一段，**两种包不能混用**：

路线 A（TestFlight）：

```bash
HX_APPLE_TEAM_ID=ABCDE12345 bash hx/scripts/build-ios.sh
```

路线 B（直接安装）：

```bash
HX_IOS_EXPORT=release-testing HX_APPLE_TEAM_ID=ABCDE12345 bash hx/scripts/build-ios.sh
```

两条路线都要的，两条命令各跑一遍，但要**先传走第一个包再跑第二条**（两次的文件名相同，后一次会覆盖前一次）。

脚本自己完成全部工作，依次显示 `1/5` 到 `5/5`：应用改造、安装依赖、生成 iOS 工程、归档签名、导出安装包。第一次打包时注意两件事：

- 中途 Mac 可能弹出“codesign 想要访问钥匙串中的密钥”的窗口：输入 Mac 的开机密码，点“**始终允许**”（点“允许”会反复弹出）。
- 第一次要下载很多依赖，整个过程 30～60 分钟，中途不要合上电脑。

成功时最后显示（路线 A 的例子）：

```text
构建完成：
-rw-r--r--  1 you  staff  （文件大小）  Nov 11 15:42 dist-hx/HXBot-1.5.0-ios.ipa
（64 位的 SHA-256）  dist-hx/HXBot-1.5.0-ios.ipa
应用：HXBot（com.hxallai.bot）
版本：1.5.0，构建号 2611111530
系统要求：iOS 16.4 或更新
签名：App Store / TestFlight。交给 TestFlight 用，不能直接装到手机。
上传到 TestFlight 后，这个构建可以测试 90 天，到期前要再上传一个新构建。

这个包是交给 TestFlight 的，不能直接装到手机，也不用传到服务器。下一步：
  1. 打开 Transporter，把 /Users/you/hx-bot/dist-hx/HXBot-1.5.0-ios.ipa 拖进去，点“交付”。
  …
```

路线 B 的包，“签名”一行是 `Ad Hoc（已登记的设备）。可以直接安装。`，下面列出这个包能装到的每一台设备的 UDID。**要安装的设备不在这个列表里就装不上**：回到 11.4 节第 6 步登记，再重新打包。

关于版本号和构建号：版本号（如 1.5.0）写在源码里，跟着源码走，不用管。**构建号**由脚本每次自动生成，取打包时的时间（年月日时分，`2611111530` 就是 26 年 11 月 11 日 15:30），所以每次打包都比上一次大。苹果对同一个版本号的每个构建号只收一次，这就是以前“第二次上传被拒收”的原因，现在不会再发生。

打包失败时，脚本会在最后用中文写出原因和处理办法；它认不出的，对照 11.11 节的表格。想知道手上某个 ipa 是哪种包、能装到哪些设备，随时可以查看：

```bash
python3 hx/server/scripts/publish-downloads.py --inspect dist-hx/HXBot-1.5.0-ios.ipa
```

### 11.6 路线 A：通过 TestFlight 发布

界面上的文字下面写的是英文原文，中文界面的译名可能略有不同，按位置对照即可。

**第 1 步（只做一次）：在 App Store Connect 建应用记录。**要在第一次打包成功之后做，因为“套装 ID”要等 Xcode 打包时登记过才选得到。

1. 登录 https://appstoreconnect.apple.com ，点 Apps（App），再点左上角的 `+` → New App（新建 App）。
2. Platforms 勾 iOS。
3. Name 填 `HXBot`。这个名称在整个 App Store 里不能重复，提示已被占用就改成 `HXBot 研究版`。
4. Primary Language 选简体中文。
5. Bundle ID 在下拉列表里选结尾正好是 `com.hxallai.bot` 的那一项。结尾多出 `.ShareExtension`、`.NotificationService`、`.ExpoWidgetsTarget` 的是应用的扩展，不要选。
6. SKU 填 `hxbot-ios`（只是内部编号，用户看不到）。
7. User Access 选 Full Access，点 Create。

**第 2 步：用 Transporter 上传安装包。**

1. 在 Mac 的 App Store 里搜索并安装 Transporter（开发者是 Apple，免费）。
2. 打开它，用开发者账号登录。
3. 把 11.5 节打出来的 `dist-hx/HXBot-1.5.0-ios.ipa` 拖进窗口。
4. 点“交付”（Deliver），等进度条走完，显示已交付。

**第 3 步：等苹果处理。**约 10～30 分钟后，App Store Connect → 你的应用 → TestFlight 标签页的 iOS 构建列表里出现 `1.5.0 (2611111530)`。还在处理时显示 Processing，耐心等；苹果发现问题会给账户持有人的邮箱发邮件。应用里已经带了出口合规声明（沿用原项目的设置），一般不会再问。

**第 4 步（只做一次）：填测试信息。**TestFlight 标签页左边栏点 Test Information（测试信息）：

| 栏目 | 填什么 |
| --- | --- |
| Beta App Description（必填） | `HXBot 研究版的手机端，用来远程连接你电脑上的桌面端。仅限研究使用，不得用于商业用途。` |
| Feedback Email | `bot@hxallai.com` |
| Beta App Review Information：联系人 | 办理人的姓名、电话、邮箱 |
| Sign-in required（需要登录） | 勾选，填一个专门给审核员用的账号的邮箱和密码（见表格下面） |
| Notes | `HXBot is the mobile companion of the HXBot desktop app (research edition, not for commercial use). Sign in with the email and password above.` |

给审核员的账号要真的能登录，而且不要用任何真人的账号。在服务器上为它单独建一个：`cd /opt/hxbot/server && bash scripts/users.sh add review@hxallai.com`（邮箱换成公司的一个邮箱；按提示填用户名、手机号码、公司名称、职位，并设一个只给审核用的密码），把这个邮箱和密码填进上表。服务器设了注册名单的，先把它加进名单（第 12 节“修改注册名单”）。审核期间，最好让一台用这个账号登录的桌面端保持开机在线，这样审核员登录后能看到内容。审核结束后可以停用它：`bash scripts/users.sh disable review@hxallai.com`，下次送审前再 `enable`。

**第 5 步：先建内部测试群组，自己装上验证。**内部测试不用苹果审核，上传处理完就能装；而且苹果规定要先有内部群组才能建外部群组。

1. TestFlight 标签页左边栏，点 Internal Testing（内部测试）旁边的 `+`。
2. 群组名填 `内部`，保持 Enable automatic distribution（自动分发）勾选，点 Create。以后每次上传的新构建会自动发给这个群组。
3. 点 Invite Testers（邀请测试员），勾选自己，点 Add。
4. 在自己的 iPhone 上从 App Store 安装 TestFlight，用开发者账号登录，列表里出现 HXBot，点“安装”。装好后打开，用邮箱和登录口令登录，确认能用。

要让同事也进内部测试：App Store Connect 顶部的 Users and Access（用户和访问）→ `+`，填他的姓名、邮箱，角色选 Developer 或 Marketing，他在邮件里接受邀请后，回到第 3 步把他勾上。内部测试员最多 100 人。

**第 6 步：建外部测试群组，提交审核。**客户不是公司的开发者账号成员，属于外部测试员。

1. TestFlight 标签页左边栏，点 External Testing（外部测试）旁边的 `+`，群组名填 `研究用户`，点 Create。
2. 进这个群组，点 Add Builds（添加构建版本），选 iOS 和版本，在列表里选中刚上传的构建，点 Add。
3. What to Test（测试内容）填 `登录、连接桌面端主机、收发消息。`
4. 勾选 Automatically notify testers（自动通知测试员）。
5. 点 Submit Review（提交审核）。

构建的状态变成 Waiting for Review（等待审核），之后是 In Beta Review（审核中）。通过后账号的管理员会收到邮件。只有每个版本号的第一个构建要完整审核，同一版本号后面的构建一般不用再审。被拒绝时，在 TestFlight 标签页左边栏的 App Review 里看原因，改好后重新提交。

**第 7 步：生成公开链接。**审核通过后：

1. 进 `研究用户` 群组，在 Testers（测试员）标签页点 Create Public Link（创建公开链接）。
2. 选 Open to Anyone（面向所有人）。
3. 可以勾 Set Limit 设一个人数上限（1～10000），建议先设成预计的用户数，以后随时能改。
4. 点 Confirm，复制得到的链接，形如 `https://testflight.apple.com/join/AbCd1234`。

**第 8 步：把链接发布到下载页。**在 Mac 的源码目录里执行（把链接换成你的）：

```bash
bash hx/scripts/upload-downloads.sh root@47.119.145.170 --ios-url https://testflight.apple.com/join/AbCd1234
```

没有配置 SSH 的，也可以登录服务器后执行：

```bash
python3 /opt/hxbot/server/scripts/publish-downloads.py /opt/hxbot/downloads --ios-url https://testflight.apple.com/join/AbCd1234
```

屏幕显示：

```text
已更新 /opt/hxbot/downloads/manifest.json：
  ios      https://testflight.apple.com/join/AbCd1234  TestFlight
完成。打开 https://bot.hxallai.com 登录后即可看到新版本。
```

**检查：**用 iPhone 打开 https://bot.hxallai.com 登录，“iPhone / iPad”卡片上出现“在 TestFlight 中安装”按钮。脚本只接受苹果的地址（testflight.apple.com、apps.apple.com）。以后要撤下这个按钮，把命令里的 `--ios-url 链接` 换成 `--no-ios-url`。

**第 9 步（可选）：让 iPhone 上点邀请链接直接打开应用。**在服务器上执行（团队号是 11.3 节第 6 步记下的那个）：

```bash
cd /opt/hxbot/server
bash scripts/set-env.sh HX_APPLE_TEAM_ID ABCDE12345
docker compose up -d account
```

不做这一步也能用：邀请链接会用浏览器打开，或者在应用里点“添加服务器”粘贴链接。

### 11.7 路线 B：直接安装（Ad Hoc）

**第 1 步：登记每一台要安装的设备。**做法见 11.4 节第 6 步。每个会员年度每类设备最多登记 100 台，停用设备不会腾出名额，名额在每年续费后可以重新整理一次。新加入的账号一次登记超过 10 台时，苹果可能要 24～72 小时才处理完，这期间打的包里不含这些设备。

**第 2 步：打包。**用 11.5 节路线 B 的命令。打完核对屏幕上列出的 UDID 里有要安装的设备。

**第 3 步：上传到服务器。**在 Mac 的源码目录里执行：

```bash
bash hx/scripts/upload-downloads.sh root@47.119.145.170 dist-hx/HXBot-1.5.0-ios.ipa
```

屏幕显示：

```text

  HXBot-1.5.0-ios.ipa：Ad Hoc（已登记的设备），构建号 2611111530，登记了 3 台设备，描述文件到 2027-11-10 过期（过期后应用打不开，需要重新构建）。

完成。打开 https://bot.hxallai.com 登录后即可看到新版本。
```

如果显示的是“签名是 App Store / TestFlight……下载页不会提供这个文件”，说明传上来的是路线 A 的包：用路线 B 的命令重新打包再传。

**第 4 步：检查。**在服务器上运行 `bash /opt/hxbot/server/scripts/check.sh`，“iOS 无线安装”三项都是“通过”。再用一台登记过的 iPhone 的 Safari 打开 https://bot.hxallai.com 登录，“iPhone / iPad”卡片上是“安装”按钮，下面显示版本、构建号、大小、有效期和 SHA-256。

点“安装”后来取安装包的是手机系统的安装程序，它不带网页的登录状态，所以安装清单和安装包通过 `https://bot.hxallai.com/ota/32位随机串/…` 提供。随机串由服务器生成，只写在登录后才能读到的下载列表里，不进访问日志，换安装包时自动更换；安装包本身也只能装到登记过的设备上。

### 11.8 用户怎么安装

下面两段可以直接转发给用户。

**通过 TestFlight 安装（路线 A）：**

1. 在 iPhone 或 iPad 的 App Store 里搜索 TestFlight（开发者是 Apple），安装。
2. 用手机浏览器打开 https://bot.hxallai.com ，用邮箱和密码登录（还没有账号的先点“创建账号”）。
3. 在“iPhone / iPad”卡片上点“在 TestFlight 中安装”。
4. 手机跳到 TestFlight，点“接受”，再点“安装”。
5. 回到主屏幕打开 HXBot，用同一个邮箱和密码登录。

以后有新版本，TestFlight 会发通知，打开 TestFlight 点“更新”即可；在 TestFlight 里这个应用的页面打开“自动更新”后不用手动点。TestFlight 里显示的“还剩多少天”是这个构建的有效期，管理员会在到期前发新的。

**直接安装（路线 B，只适用于已经把设备编号交给管理员登记的设备）：**

1. **必须用 Safari** 打开 https://bot.hxallai.com 并登录。微信、钉钉等应用里打开的页面装不了。
2. 在“iPhone / iPad”卡片上点“安装”，弹出的窗口里再点“安装”。
3. 回到主屏幕，等 HXBot 的图标装完。
4. 第一次点开会提示需要开发者模式：进“设置 → 隐私与安全性”，拉到最下面点“开发者模式”，打开开关，点“重新启动”。
5. 重启并解锁后，屏幕弹出确认窗口，点“打开”，输入锁屏密码。
6. 再点开 HXBot，用邮箱和密码登录。

第 4、5 步每台设备只做一次。提示“无法安装”的，说明这台设备还没有登记，联系管理员。

### 11.9 以后怎么发布更新

需要重新打包上传的三种情况：拿到了新的源码包（有新功能或修复）；TestFlight 的构建快满 90 天了；路线 B 的描述文件快到期或者要加新设备。服务器升级（第 12 节）不会改变已经装在手机上的应用，手机端的界面改动要靠这里的步骤送到用户手上。

**路线 A（TestFlight）的更新，四步：**

**第 1 步：打包。**有新源码包就先解压新的（方法同 11.4 节第 7 步），没有就用原来的目录。命令和第一次完全一样，构建号会自动变大：

```bash
HX_APPLE_TEAM_ID=ABCDE12345 bash hx/scripts/build-ios.sh
```

**第 2 步：上传。**打开 Transporter，把新的 ipa 拖进去，点“交付”。

**第 3 步：发给测试员。**等 App Store Connect → TestFlight 里出现新的构建号。`内部` 群组开了自动分发，会自动收到。进 `研究用户` 群组，点 Builds（构建版本）旁边的 `+`，选中新构建，填测试内容，点 Submit Review 或 Start Testing（按钮是哪个取决于这个构建要不要审核）。

**第 4 步：确认。**自己的 iPhone 上打开 TestFlight，HXBot 显示“更新”，更新后在 TestFlight 里看到的构建号是新的。

邀请链接不变，下载页不用改，服务器上什么都不用做。用户会在 TestFlight 里收到更新通知。

> 每个构建只能测试 90 天，到期后用户手上的应用打不开。请在日历里设一个每 80 天重复的提醒，到时候按上面四步发一个新构建，即使源码没有变化。

源码里的版本号变了（例如从 1.5.0 变成 1.5.1）时，对苹果来说是一个新版本，它的第一个构建要重新走一次外部测试审核，其余步骤不变。

**路线 B（直接安装）的更新，三步：**

**第 1 步：有新设备先登记**（11.4 节第 6 步）。

**第 2 步：打包并上传。**

```bash
HX_IOS_EXPORT=release-testing HX_APPLE_TEAM_ID=ABCDE12345 bash hx/scripts/build-ios.sh
bash hx/scripts/upload-downloads.sh root@47.119.145.170 dist-hx/HXBot-1.5.0-ios.ipa
```

新文件覆盖旧文件，旧的安装地址随即失效。手机上的 HXBot 点“更新”时打开的就是这个新地址。

**第 3 步：确认并通知用户。**下载页“iPhone / iPad”卡片上的构建号、更新日期和 SHA-256 变成新的。通知用户用 Safari 打开下载页再点一次“安装”，新版本会覆盖旧版本，登录状态和数据保留。

### 11.11 iOS 常见问题

打包脚本失败时会自己写出原因。下表是全部已知情况，左边是屏幕或邮件里出现的文字。

| 出现在哪、显示什么 | 处理 |
| --- | --- |
| 打包：`No Accounts` 或 `No Account for Team` | Xcode 没有登录开发者账号，或团队号写错。按 11.4 节第 2 步登录，核对团队号 |
| 打包：`Your team has no devices from which to generate a provisioning profile` | 开发者账号里没有登记任何设备。按 11.4 节第 6 步登记一台 |
| 打包：`No profiles for 'com.hxallai.bot…' were found` | 登录 Xcode 的账号在团队里权限不够（要账户持有人或 Admin），或上一条的原因。用账户持有人的账号登录 Xcode |
| 打包：提示 App Groups、Push Notifications、Associated Domains 等能力不可用，或 `Personal development teams … do not support` | 用的是没有付费的个人账号。必须用已经加入 Apple Developer Program 的账号和它的团队号 |
| 打包：`You have not agreed to the Xcode license` | 运行 `sudo xcodebuild -license accept && sudo xcodebuild -runFirstLaunch` |
| 打包：`iOS … is not installed. To use with Xcode, first download and install the platform` | 运行 `xcodebuild -downloadPlatform iOS`，装完重新打包 |
| 打包：提到 `Program License Agreement` 或 agreement 需要同意 | 账户持有人登录 https://developer.apple.com/account 同意最新协议 |
| 打包：`Could not resolve host`、`CDN: trunk`、`timed out` | 网络访问不了 GitHub、npm 或 CocoaPods。换网络后重新运行，已下载的不会重下 |
| 打包：一直弹“codesign 想要访问钥匙串” | 输入 Mac 开机密码后点“始终允许” |
| 打包：换了更新的 Xcode 大版本后编译报错 | 原项目用 Xcode 27.1 构建。在 https://developer.apple.com/download/all/ 搜索下载对应版本的 Xcode（.xip 文件），解压后拖进“应用程序”，再运行 `sudo xcode-select -s /Applications/Xcode.app` |
| Transporter：`The App Bundle ID … does not exist yet. Go to App Store Connect to add a new App` | 还没有建应用记录。做 11.6 节第 1 步 |
| Transporter：`The bundle version must be higher than the previously uploaded version`，或提示重复上传 | 传的是以前已经传过的包。重新打包（构建号会自动变大）再传 |
| Transporter：登录后看不到团队，或提示没有权限 | 用账户持有人的账号登录；先在浏览器里登录一次 App Store Connect 把协议同意掉 |
| TestFlight：构建一直是 Processing | 一般 30 分钟内完成，偶尔要几个小时。超过一天，查账户持有人的邮箱有没有苹果发来的问题说明 |
| TestFlight：构建旁边出现 Missing Compliance | 点 Manage，如实回答加密相关的问题后保存 |
| TestFlight：外部测试被拒（Rejected） | 在 TestFlight 左边栏 App Review 里看原因。最常见的是审核员登录不上：核对第 4 步填的邮箱和密码现在还能登录（账号没有被停用、密码没有改过） |
| 用户点邀请链接：`This beta isn't accepting any new testers right now` | 群组里没有可用的构建（都过期了，或还没通过审核），或公开链接被关闭。发一个新构建，或在群组里重新开启链接 |
| 用户点邀请链接：`This beta is full` | 到人数上限了。在群组的 Public Link 旁点 Manage，把上限调大 |
| 用户：TestFlight 里应用打不开，显示已过期 | 构建满 90 天了。按 11.9 节发新构建 |
| 用户：下载页点“安装”没有反应 | 没有用 Safari。微信等应用内置的浏览器不支持 |
| 用户：提示“无法安装”或“无法验证其完整性” | 这台设备不在安装包登记的设备里，或描述文件过期了。用 `--inspect` 命令（11.5 节末尾）核对，登记设备后重新打包上传 |
| 用户：点开应用提示需要开发者模式，但设置里找不到这一项 | 先把应用装上并点开一次，再到“设置 → 隐私与安全性”最下面找；还没有就重启手机再看 |
| 下载页的 iPhone / iPad 卡片还是“即将推出” | 还没有发布链接或安装包。路线 A 做 11.6 节第 8 步，路线 B 做 11.7 节第 3 步 |
| 服务器：check.sh 的“iOS 无线安装地址只认服务器生成的随机串”失败 | nginx 还是旧配置。在 /opt/hxbot/server 运行 `bash scripts/setup-https.sh 你的邮箱` |

没有 Mac 和开发者账号时，上面的打包和上传步骤没有办法在别的系统上代替完成。本文档的命令都对照脚本核对过，但 iOS 的真机打包、TestFlight 上传和安装需要你的账号和设备，第一次执行时遇到与文档不一致的地方，请把屏幕上的文字发到 bot@hxallai.com。

### 用户管理

注册用户用 `scripts/users.sh` 查看和管理。每条命令会暂停账号服务几秒再自动启动（已建立的远程连接不受影响，这几秒内新的登录会失败），所以不要在脚本运行中途按 Ctrl+C。

| 要做的事 | 命令 |
| --- | --- |
| 列出全部注册用户 | `bash scripts/users.sh list` |
| 查看一个用户 | `bash scripts/users.sh show 用户邮箱` |
| 为用户设置新密码 | `bash scripts/users.sh reset-password 用户邮箱` |
| 停用账号（不能登录，资料保留） | `bash scripts/users.sh disable 用户邮箱` |
| 恢复被停用的账号 | `bash scripts/users.sh enable 用户邮箱` |
| 代为建账号 | `bash scripts/users.sh add 用户邮箱` |
| 导出全部用户为表格 | `bash scripts/users.sh export` |
| 彻底删除账号及其个人信息 | `bash scripts/delete-account.sh 用户邮箱`（见上表“注销账号”） |

**列出用户。**每个用户一行：邮箱、用户名、手机号码、公司名称、职位、注册时间、最近使用时间，停用的在行尾标“【已停用】”。

```text
注册用户：2 个
  zhangsan@example.com  张三  +8613800138000  某某研究院  研究员  注册 2026-11-12 09:30  最近使用 2026-11-12 10:05
  lisi@example.com  李四  +8613900139000  某某大学  讲师  注册 2026-11-12 11:20  最近使用 无  【已停用】
```

**查看一个用户。**显示资料、邮箱和手机号是否验证过、登录方式（密码、绑定了哪几家第三方账号）、最近使用时间、现在有几处登录着、是否停用。看不到密码：服务器只保存密码的加盐哈希。

**设置新密码。**用户忘记密码又不能自助找回时使用。先核实对方身份（例如他用注册邮箱发来的请求）。命令会让你隐藏输入两次新密码（8～32 个字符，字母、数字、符号都要有），成功后显示 `✔ 已为 …… 设置新密码，他在各处的登录状态已全部退出`。用电话等安全的方式把新密码告诉本人，不要用邮件或聊天工具发密码；开着邮箱验证时，提醒他登录后用“忘记密码”换成自己的密码。

**停用和恢复。**停用后这个账号不能再登录（密码登录和第三方登录都会提示“这个账号已停用，请联系管理员”），他在各处的登录状态立即全部退出，资料和他发布的服务器目录保留。有人不再参与研究、或账号被盗用时使用。`enable` 恢复后可以重新登录。

**代为建账号。**依次询问用户名、手机号码、公司名称、职位，再隐藏输入两次密码，成功后显示 `✔ 已为 …… 建好账号`。邮箱、用户名、手机号码已经被别的账号用了的，会提示并停下（一个手机号码只能有一个账号）。这样建的账号邮箱和手机号都标为“未验证”。用在两种情况：关闭了验证、想由管理员逐个开通；或者某个用户收不到验证码。

**导出。**不带文件名时导出到 `users-日期.csv`（在 /opt/hxbot/server 目录），可以用 Excel 直接打开。文件里是个人信息：只有 root 能读，用完删除（`rm -f users-*.csv`），不要外传。

### 升级到新版本

**每个新版本上线按交付件里的《上线操作手册》做**：它按这台服务器写好了每一步（先确认服务器现状、通知用户、上传客户端、升级、检查），比本节更细。本节讲升级的原理和手工方法，作为备查。

每个新版本有两个服务器包，任选一个。`.env`、账号数据库和下载目录里的安装包都会保留；数据库里新版本增加的表在启动时自动建好。

| 包 | 内容 | 什么时候用 |
| --- | --- | --- |
| `hxbot-server-v1.7.1.zip`（全量包） | 完整的服务器程序 | 全新部署；从任何旧版本升级 |
| `hxbot-server-update-v1.7.1.zip`（更新包） | 只有上一版本以来变动的文件，小得多 | 服务器正好是上一版本时（交付说明里写着起点版本。不是的话脚本会拒绝，并提示改用全量包） |

**先上传新的客户端安装包，再升级服务器。**服务器升级后会告诉手机端有新版本（手机端打开的是下载中心里的安装包）；从 v1.6.2 起，服务器还会拒绝低于最低版本的客户端（v1.6.3 起桌面端的最低版本是这一版的“主.次.0”，所以只有大版本必须更新，见下面“升级到 v1.6.3 时”），用户只能去下载中心或在应用里拿新版本，所以新的安装包一定要先按第 11 节传上去。

**从 v1.6 之前的版本升级到 v1.6 及以后时，用下面的“方法二：手工升级”，并先看完“从共用登录口令升级”一小节**：登录方式变了，手工升级的第 2 步里要多做两件事，升级后要通知用户。

**升级到 v1.7.1 时**：

- 这一版改桌面端：多开智能体不卡死、团队不设上限、不拒绝只排队。桌面端按可用内存、电池、温度、处理器降速和主进程的忙闲决定同时跑几个回合（2～16 个），多出来的排队；团队取消“最多 20 人 · 240 分钟 · 80 次交接”，分派一律接收、排队，团队卡住时暂停并问用户；频道列表的未读数只数新来的消息，用久了不再变慢。这些都在用户自己的电脑上，**服务器不参与、不保存**，也不用做任何配置。服务器程序变的是版本号、网页版（随桌面端的界面）、门户的新功能页（加了“桌面端 0.68.0”一节）和客户端最低版本。
- **0.68.0 是大版本，必须更新：**升级后服务器只让 0.68.0 及以后的桌面端登录（最低版本取这一版的“主.次.0”）。0.67.1～0.67.9 的桌面端在新安装包上传后就会自动下载 0.68.0，弹出不能关闭的“更新 HXBot”窗口；所以先通知用户，选人少的时候上传。手机端仍是 1.5.0，不受影响。
- nginx 配置、`.env`、数据库都不变，用户不用重新登录。这一版只交付全量包（没有更新包），服务器是 v1.7.0～v1.6.2 都用全量包。
- 桌面端升到 0.68.0：按《客户端构建》在 GitHub 上重新打包 Mac 和 Windows 版（源码推到放着 Mac 签名证书的仓库 `mercywangqiang-tech/hx-bot-build`），**先上传桌面端，再升级服务器**；上线前按《上线操作手册》第 1.6 节第一部分在真机上补看。

**升级到 v1.7.0 时**：

- 这一版只改桌面端：HXBot 不打扰其他应用（高亮框少读窗口、Windows 上不挂全局鼠标钩子、按键只发给目标应用、松开修饰键、授权页和远程控制询问先发通知、停止键只在操作电脑时占用、剪贴板放回、助手进程低于正常优先级、读窗口有上限、更新下载限速 2 MB/s、远程桌面码率封顶 10 Mbit/s、Windows 上停助手时留下它打开的应用、自动选择模型在进行中的对话里保持原模型）。服务器程序只有版本号和门户的新功能页变了。
- nginx 配置、`.env`、数据库都不变，用户不用重新登录。服务器现在是 v1.6.9 的，用更新包或全量包都可以；是 v1.6.8～v1.6.2 的（跳过了中间的版本），用全量包。
- 桌面端升到 0.67.9，手机端仍是 1.5.0：按《客户端构建》在 GitHub 上重新打包 Mac 和 Windows 版（源码推到放着 Mac 签名证书的仓库 `mercywangqiang-tech/hx-bot-build`），**先上传桌面端，再升级服务器**；上线前在真机上补看的内容见《上线操作手册》第 1.6 节第二部分。

- **更新的规则改了（0.67.2 起）：**平时的新版本可以不装，桌面端下载好后弹出窗口介绍新功能，用户点“立即更新”或“以后再说”；**大版本（版本号第二段变了，例如 0.68.0）必须更新**：窗口挡住，10 分钟内没人点就在空闲时自动安装，账号服务也拒绝旧的大版本。服务器的最低版本由 `hx/brand.json` 决定：`minimumVersions` 空着时桌面端是当前版本的“主.次.0”、手机端是当前版本；某个小版本有安全问题必须马上装时，发版前在 `minimumVersions` 里写上它。每版的新功能写在 `hx/release-notes.json`（中英文），打包时写进 `latest.yml`。手机端这一版不变，仍是有新版本就提示更新。
- 服务器还是 v1.6.2 之前版本的，再看下一段。

**升级到 v1.6.2 时**：

- 服务器多了一条命令升级（下面的方法一）、手工更新包和可选的自动更新；从这一版起交付两个服务器包（见上表）。服务器现在是 v1.6.1，这一次用全量包或更新包都可以。
- nginx 配置新增了应用内更新用的地址（`/updates/`，只给登录了的客户端）和安卓新版安装包的地址，一定要更新 nginx 配置（一条命令升级会自动做；手工升级是第 6 步）。
- 账号：一个手机号码只能注册一个账号（邮箱和用户名本来就不能重复）。已经有几个账号共用一个手机号码的，最早注册的那个账号拥有这个号码，几个账号都照常登录，只是不能再用这个号码注册新账号。注册时填完用户名就会提示它能不能用。
- 用户可以在客户端里自己注销账号（第 12 节表格里的“注销账号”）。
- **强制更新：**新版客户端每个请求都带上自己的版本号，账号服务拒绝比这一版服务器所带客户端（桌面端 0.67.1、手机端 1.5.0）旧的版本，提示用户更新；没有带版本号的旧客户端（桌面端 0.67.0、手机端 1.4.x 及以前）不能再登录。**升级时所有设备的登录一次失效**（数据库迁移 9003），所以所有用户都要更新客户端并重新登录一次。退出登录、注销账号和下载更新文件不受限制。以后每次升级服务器，客户端都必须跟着更新，所以每次都要先上传新的安装包。
- **最大权限：**新版桌面端里所有智能体默认改为“最大权限”（大多数事情直接做，修改工作区以外已有的文件、删除工作区以外的东西、以管理员身份运行命令、用保存的密码登录、付款等先弹卡片确认），新增“设置 → 授权与记录”。这些都在用户自己的电脑上，服务器不需要设置。
- 使用指南、服务条款和隐私政策更新到 1.2（自助注销账号、应用内更新与强制更新、账号不能重复、最大权限）。升级前请通知用户，内容参考：“HXBot 将于某日升级：升级后旧版客户端不能再登录，请按提示更新客户端（桌面端会自动下载安装，手机端点‘安装’），然后重新登录一次；助手的默认权限改为‘最大权限’，修改或删除工作区以外的文件等操作会先请你确认；可以在‘设置 → 个人资料’里自行注销账号；服务条款和隐私政策随之更新，见 https://bot.hxallai.com/terms/ 和 https://bot.hxallai.com/privacy/ 。”
- 客户端换成无底框的长颈鹿图标，版本号升到桌面端 0.67.1、手机端 1.5.0：要按《客户端构建.md》重新打包，用第 11.1 节的命令上传（会把应用内更新用的文件一起传上去）。**从这个版本起客户端在应用里自动更新**；已经装着的旧版本（桌面端 0.67.0、手机端 1.4.x 及以前）不能再登录，要在下载中心下载、安装这一次，以后的版本就在应用里自动更新。
- 门户、网页版、使用指南等网页的标签图标换成无底框的长颈鹿（浏览器可能还显示旧图标，强制刷新即可）。服务器还是 v1.6.1 之前版本的，再看下一段。

**从 v1.6.1 之前的版本升级时**：v1.6.1 起品牌名统一为 HXBot，客户端的安装包名变成 HXBot-版本号-…（如桌面端 HXBot-0.67.1-…、手机端 HXBot-1.5.0-…），要按《客户端构建.md》重新打包并上传到下载中心。Mac 用户装好新版后，确认能打开，再把旧的“HX Bot”应用拖到废纸篓（设置、登录、保密箱都在原来的数据文件夹里，新版继续用）；Windows 安装新版时会自动卸载旧版。新设或重设的密码要同时包含字母、数字和符号，已经设置的密码照常登录。

#### 方法一：一条命令升级（推荐）

**第 1 步：把包传到服务器。**在你的电脑上执行（文件名换成拿到的包）：

```bash
scp hxbot-server-v1.7.1.zip root@47.119.145.170:/opt/
```

**第 2 步：在服务器上执行一条命令。**服务器已经是 v1.6.2 或更新的版本时：

```bash
bash /opt/hxbot/server/scripts/update.sh /opt/hxbot-server-v1.7.1.zip
```

服务器还是 v1.6.1（还没有这个脚本）时，先从包里取出脚本再运行，两行：

```bash
unzip -o -j /opt/hxbot-server-v1.7.1.zip server/scripts/update.sh -d /tmp/hxbot-update
bash /tmp/hxbot-update/update.sh /opt/hxbot-server-v1.7.1.zip
```

用更新包时把文件名换成 `hxbot-server-update-v1.7.1.zip`，命令相同。脚本做的事和下面手工升级的 8 行相同，另外：

- 先核对包：是不是 HXBot 的部署包；更新包要求这台服务器正好是它的起点版本；同一版本不会重装、也不会装回更旧的版本（确实要这样做时在命令最后加 `--force`）。
- 升级前先运行一遍 check.sh，记下已经失败的项（例如某个域名还没解析），升级后只把**新出现**的失败当作问题。
- 备份：账号数据库（同 backup.sh）、server/ 和 portal/ 目录（含 .env，放在 `/opt/hxbot/backups/server-日期-时间.tgz`，只有 root 能读，保留最近 5 份）、nginx 站点配置、正在用的镜像。
- 新版本需要、而 .env 里还没填的配置（`set-env.sh --show` 新出现“提醒：”或“还没有填写”），在启动新版本之前就停下来。
- 放上新文件，更新门户页和 nginx 配置，`docker compose up -d --build`，等账号服务就绪，再运行 check.sh。刚重启的信令服务要几秒才开始监听、coturn 的第一次健康检查在启动 15 秒后，所以没通过的项每 5 秒重查，最多等 2 分钟才算失败（v1.6.2 的脚本不等，会把正常的升级误判为失败而回滚；v1.6.2 的服务器升级时会自动改用新包里的脚本）。
- **其中任何一步出错，或者 check.sh 出现升级前没有的失败项，自动回滚**：文件、nginx 配置、镜像都换回升级前的；新版本已经启动过的，账号数据库也换回升级前一刻的备份。最后显示“已回滚到 ……”和原因，照原因处理后重新运行同一条命令。

最后一行显示 `✔ 已升级到 版本号` 就完成了。整个过程几分钟（主要是构建镜像），账号服务会暂停约 10 秒（备份）、重启一次，已经建立的远程连接不受影响。回滚会把这几分钟里新注册的账号、改的密码也一起换回升级前，所以尽量在没人用的时候升级。每次升级的输出都记在 `/var/log/hxbot/update.log`。

#### 方法二：手工升级

用于 v1.6 之前的版本，或者想一步一步看着做的时候。只能用全量包。

**手工第 1 步：把部署包传到服务器。**在你的电脑上执行（把 `v1.6.2` 换成拿到的版本号）：

```bash
scp hxbot-server-v1.7.1.zip root@47.119.145.170:/opt/
```

**手工第 2 步：在服务器上逐行执行。**任何一行报错就停下来处理，不要跳过：

```bash
cd /opt/hxbot
bash server/scripts/backup.sh                              # 1. 备份账号数据库
install -m 600 server/.env /root/hxbot.env.bak             # 2. 备份配置
rm -rf server/account/dist server/account/migrations       # 3. 删除旧的程序文件（不影响数据和配置）
unzip -o /opt/hxbot-server-v1.7.1.zip                      # 4. 解压新版本（压缩包里没有 .env，不会覆盖配置）
cp -r server/portal/. portal/                              # 5. 更新门户首页和使用指南、条款、隐私政策页面
cd server
bash scripts/setup-https.sh                                # 6. 更新 nginx 配置（已有证书不会重新申请，不用写邮箱）
bash scripts/set-env.sh --show                             # 6a. 核对配置：不应有“提醒：”开头的行（见下面的小节）
docker compose up -d --build                               # 7. 重新构建并启动，必须带 --build
bash scripts/check.sh                                      # 8. 检查
```

**第 3 步：确认升级已经生效（两种方法都要做）。**

1. check.sh 每一项都是“通过”（一条命令升级时脚本已经检查过，失败项升级前就有的除外）。其中“运行中的账号服务和网页版就是当前部署包”这一项专门核对容器是不是用新包重建的：它失败，说明第 7 步没有执行或没有带 `--build`，重新执行第 7、8 步。
2. `cat /opt/hxbot/server/VERSION /opt/hxbot/server/BUILD_COMMIT` 显示的版本号和提交号与交付说明里写的一致。
3. 在浏览器里把已经打开的 bot.hxallai.com 页面全部关掉，重新打开 https://bot.hxallai.com/app （或按 Ctrl+F5）。网页版的界面这时就是新版本。
4. 桌面端、安卓端、iOS 端的界面改动在客户端里，不随服务器升级：按《客户端构建.md》用同一版本的源码重新打包，再按第 11 节上传到下载中心（最好在升级服务器之前），用户在应用里更新、或者下载安装新安装包后生效。iOS 版的更新步骤在 11.9 节。

手工升级后界面没有变化，几乎都是下面三种情况之一：第 7 步没带 `--build`（容器还是旧程序）；部署包没有解压到 `/opt/hxbot`（第 4 步前没有先 `cd /opt/hxbot`）；浏览器还开着旧页面。

#### 自动更新（可选，默认关闭）

打开后，服务器每天 05:07 到你指定的地址检查有没有新版本：有就下载（这台服务器正好是更新包的起点时下载更新包，否则下载全量包），核对 SHA-256 后用一条命令升级，失败自动回滚（同方法一）。

地址是一个 https 目录，里面放打包时生成的 `latest.json` 和对应的全量包、更新包：交付目录 `dist-hx/` 里的 `latest.json`、`hxbot-server-v版本.zip`、`hxbot-server-update-v版本.zip` 三个文件原样上传，每出一个新版本上传一次（先传两个包，最后传 `latest.json`）。**能改这个目录里文件的人就能让服务器升级**，所以要放在只有你能上传的地方，例如阿里云对象存储（OSS）里一个“公共读、私有写”的目录。

```bash
bash /opt/hxbot/server/scripts/auto-update.sh --enable https://你的地址/hxbot/server/   # 打开（先取一次 latest.json，取不到不会打开）
bash /opt/hxbot/server/scripts/auto-update.sh --status    # 这台服务器的版本、是否打开、最近一次的结果
bash /opt/hxbot/server/scripts/auto-update.sh --now       # 现在就检查一次
bash /opt/hxbot/server/scripts/auto-update.sh --disable   # 关闭
```

自动更新只换服务器，不会改变用户手上的客户端；新版本的客户端安装包仍按第 11 节上传（客户端随后在应用里更新）。开着自动更新时，也要先上传客户端、再把新版本的服务器包放到这个地址。

### 从共用登录口令升级（v1.6 之前的版本 → v1.6）

v1.6 之前的版本里，所有人共用一个登录口令。v1.6 起每个人注册自己的账号、用自己的密码登录，共用口令不再能登录。升级时要注意四件事：

**一、已经登录的设备不受影响。**升级不会让任何人退出；他们的账号、发布的服务器、成员关系都原样保留。只是以后在新设备上登录、或退出后重新登录时，要用自己的密码。

**二、每位老用户要设置一次自己的密码。**方法是在门户页 https://bot.hxallai.com 点“创建账号”，用**原来登录用的那个邮箱**注册。注册完成后还是原来的那个账号，原来的服务器、成员关系都在。

**三、手工升级第 2 步的 6a 要多做的事。**新版本默认开着邮箱验证和手机验证，而旧的 .env 里没有发信邮箱和短信的设置，所以 6a 的 `--show` 会出现两行“提醒：”。升级前（或在 6a 这一步）二选一：

- 推荐：按第 5.3 节配好发信邮箱；短信按第 5.4 节，没批下来就先执行 `bash scripts/set-env.sh HX_PHONE_VERIFICATION off`。这样老用户注册时由邮箱验证码证明这个邮箱是他的。
- 两项验证都关闭（`HX_EMAIL_VERIFICATION off`、`HX_PHONE_VERIFICATION off`）：没有验证码时，老用户注册时要多填一项“原来的登录口令”来证明身份，所以这种情况下先**不要清空** .env 里的 `HX_LOGIN_PASSWORD`。新用户不需要填它。

配好后再执行一次 `bash scripts/set-env.sh --show`，没有“提醒：”再继续第 7 步。

**四、通知用户，并在过渡结束后清掉旧口令。**升级完成后发通知，内容参考：“HXBot 已升级为每人一个账号。请打开 https://bot.hxallai.com ，点‘创建账号’，用你原来登录的邮箱注册并设置自己的密码；以后各端都用邮箱和这个密码登录。已经登录的设备不受影响。”

用下面的命令看还有谁没设置密码。输出最后的“以前用共用口令登录过、还没有设置自己密码的邮箱”就是名单；名单空了（这一段不再出现），过渡就结束了：

```bash
bash scripts/users.sh list
```

过渡结束后清空旧口令并重启账号服务：

```bash
bash scripts/set-env.sh HX_LOGIN_PASSWORD ''
docker compose up -d account
```

清空之后（并且关闭着邮箱验证时），还没设置密码的老用户注册会提示“请联系管理员为这个邮箱设置密码”：核实身份后用 `bash scripts/users.sh add 他的邮箱` 为他建好账号即可，还是原来的那个账号。开着邮箱验证时不受旧口令影响，随时可以清空。

### 数据库的备份与恢复

账号数据库（注册资料、绑定的第三方账号、登录会话、服务器目录、成员关系）在 Docker 卷 `hxbot_account-state` 里（第 8.1 节）。对话内容和文件不在服务器上，而是在各自运行助手的电脑上。

备份用 `bash scripts/backup.sh`（上表），备份文件是 `/opt/hxbot/backups/account-日期-时间.tgz`，只有 root 能读，里面有全部用户的个人信息：不要外传；要异地保存时，先加密再传。上线当天就按上表设置每天自动备份。

恢复到某个备份。先用 `ls -lt /opt/hxbot/backups` 看有哪些备份，把下面命令里的 `account-20261108-043000.tgz` 换成要恢复的文件名：

```bash
cd /opt/hxbot/server
docker compose down
docker run --rm --user 0 --entrypoint sh -v hxbot_account-state:/state -v /opt/hxbot/backups:/backup hxbot/account:local \
  -c 'rm -rf /state/* && tar xzf /backup/account-20261108-043000.tgz -C /state && chown -R 1000:1000 /state'
docker compose up -d
```

恢复会把数据库整个换回备份那一刻的样子：备份之后注册的账号、改过的密码都会回到当时的状态，所以恢复前先再备份一次当前的数据。

### 停用研究版

```bash
cd /opt/hxbot/server && docker compose down
rm -f /etc/nginx/conf.d/hxbot.conf /etc/cron.d/hxbot-cert /etc/cron.d/hxbot-backup   # 宝塔面板为 /www/server/panel/vhost/nginx/hxbot.conf
nginx -t && nginx -s reload
```

官网不受影响。需要彻底删除数据时再执行 `docker volume rm hxbot_account-state`。

## 13. 常见问题

**界面还是旧的：开屏动画还是毛绒角色、帮助菜单或某个页面通往上游项目、看到上游的英文宣传页**
- 原因只有两种：服务器上运行的还是旧版本（解压了新包但没有重新构建容器，或 nginx 配置没有更新），或者用户装的还是旧的客户端安装包。当前版本的任何界面、链接、下载和更新检查都不通往上游项目。
- 服务器：按第 12 节“升级到新版本”用一条命令升级（或者把手工升级的 8 行命令完整执行一遍），check.sh 要全部“通过”，特别是“运行中的账号服务和网页版就是当前部署包”和两项“上游官网页面已转回下载页”。
- 浏览器：关闭页面重新打开，或按 Ctrl+F5；手机浏览器和微信里打开的页面，可以在地址后面加 `?v=2` 再打开一次。
- 客户端：安装用当前版本源码重新打包的安装包（《客户端构建.md》），旧安装包里的界面不会随服务器升级而变化。

**iOS 版：打包失败、Transporter 上传被拒、TestFlight 审核、iPhone 上装不上**
- 全部情况和处理办法在 11.11 节的表格里，按屏幕上出现的文字查找。
- 没有 Apple 开发者账号和团队号时打不出能安装的 iOS 包，先做 11.3 节。
- 服务器侧只有一项与 iOS 有关：`bash /opt/hxbot/server/scripts/check.sh` 的“iOS 无线安装”几项应为“通过”（只有发布了直接安装的 ipa 时才有后两项）。

**拉取镜像失败（pull access denied、timeout、i/o timeout）**
- 报 `not found`、`i/o timeout`：先按第 3.3 节配置加速源（只配阿里云个人加速器会报 `not found`），`docker info | grep -A 4 "Registry Mirrors"` 确认已生效。
- 报 `429 Too Many Requests`：Docker Hub 限流，过一小时再试，或注册一个免费 Docker Hub 账号后 `docker login` 再拉。
- 仍然失败时，在服务器上把镜像地址直接写成带加速源前缀的形式，再重新构建：

```bash
cd /opt/hxbot/server
bash scripts/set-env.sh NODE_IMAGE docker.1ms.run/library/node:24-bookworm-slim
bash scripts/set-env.sh BUN_IMAGE docker.1ms.run/oven/bun:1.4.2-alpine
bash scripts/set-env.sh COTURN_IMAGE docker.1ms.run/coturn/coturn:4.17.2-r0
bash scripts/set-env.sh CERTBOT_IMAGE docker.1ms.run/certbot/certbot:latest
docker compose up -d --build
```

`docker.1ms.run` 不通时，把四条命令里的它换成 `docker.m.daocloud.io` 再执行一次。都不行时改用附录 B 的离线镜像。

**注册和登录：注册页提示“服务器还没有配置发信邮箱，暂时不能注册或找回密码”或“服务器还没有配置短信服务，暂时不能注册”**
开着的验证没有配好对应的服务。在服务器上执行 `bash scripts/set-env.sh --show`，按“提醒：”一行处理：配好第 5.3 节的发信邮箱或第 5.4 节的短信，或者先关闭这项验证；然后 `docker compose up -d account`。

**注册和登录：用户收不到验证码邮件**
- 先让他看垃圾邮件箱，并确认邮箱地址没有写错；验证码 10 分钟内有效，60 秒后可以点“重新获取验证码”。
- 页面提示“验证码邮件没有发出去”时，是服务器发信失败。执行 `bash scripts/set-env.sh --test-mail`，按第 5.3 节的表格处理；再看原因：`docker compose logs --tail 200 account | grep 验证码邮件发送失败`。
- 测试通过、个别邮箱还是收不到：多半被对方邮箱当成垃圾邮件拦截了。让他把 bot@hxallai.com 加进通讯录或白名单；实在收不到的，用 `bash scripts/users.sh add 他的邮箱` 代为建账号。

**注册和登录：用户收不到短信验证码**
- 页面提示“短信没有发出去”：执行 `bash scripts/set-env.sh --test-sms 你的手机号`，按屏幕上的“怎么办”和第 5.4 节的表格处理；账号服务记录的原因用 `docker compose logs --tail 200 account | grep 短信发送失败` 查看。
- 页面提示“这个号码获取验证码太频繁”：同一个号码每分钟 1 条、每小时 5 条、每天 10 条，过一会儿再试。
- 页面提示“目前只能验证中国大陆的手机号码”：开着手机验证时只支持 11 位的中国大陆手机号。用其他国家和地区号码的用户，由管理员用 `bash scripts/users.sh add 他的邮箱` 代为建账号。
- 页面显示已发送、手机却没收到：到阿里云短信服务控制台的“发送记录”里查这个号码。签名刚通过审核、运营商报备还没完成时，部分号码会收不到。

**注册和登录：提示“邮箱或密码不正确”“这个账号已停用”“尝试太频繁”**
- “邮箱或密码不正确”：密码区分大小写。忘记了就点登录框下面的“忘记了密码？”（关闭了邮箱验证时由管理员 `bash scripts/users.sh reset-password 邮箱`）。用 `bash scripts/users.sh show 邮箱` 可以确认这个邮箱有没有注册；v1.5.1 以前用共用口令登录过、还没有设置自己密码的邮箱，要先“注册账号”（第 12 节“从共用登录口令升级”）。
- “这个账号已停用，请联系管理员”：账号被 `users.sh disable` 停用了，`bash scripts/users.sh enable 邮箱` 恢复。
- “尝试太频繁”或“密码输错次数太多”：同一个邮箱或同一个网络在 15 分钟内尝试太多次，过几分钟再试。

**注册和登录：提示“这个邮箱以前登录过，请填写原来的登录口令”或“请联系管理员为这个邮箱设置密码”**
只在关闭了邮箱验证、又是从共用登录口令的版本升级上来时出现：这个邮箱是老用户，注册时要证明身份。处理办法见第 12 节“从共用登录口令升级”的第三、四条。

**第三方登录：按钮没有出现，或点了以后出错**
- 按钮没有出现：`bash scripts/set-env.sh --show` 看这一家是不是“已开启”（各项都要填好），改完要 `docker compose up -d account`；浏览器按 Ctrl+F5 刷新。
- 点按钮后，对方页面提示回调地址或域名不对（例如 `redirect_uri 参数错误`、`redirect_uri_mismatch`、`Invalid Redirect URI`、`invalid_request`）：在这一家后台登记的回调地址与第 5.5 节表格里的不一致。地址要逐字相同：`https` 开头、没有多余的斜杠和空格；微信只填域名 `bot.hxallai.com`。
- 对方页面提示应用未上线、无权限、`scope` 没有权限：这一家的应用还没有审核通过或没有上线，或者没有开通登录能力（附录 A 对应小节）。
- 在对方页面上同意之后，回到门户提示“第三方登录没有成功，请重试”：账号服务换取身份时被拒绝了，多半是密钥填错。查看原因：`docker compose logs --tail 200 account | grep 第三方登录失败`，然后重新填写这一家的密钥（第 5.5 节）。check.sh 里“服务器能连上 ……”失败时，是服务器连不上这一家的接口（Google、Facebook 在中国大陆的服务器上就是这样）。
- 提示“这个第三方账号已经绑定了别的账号”：这个微信（或其他）账号以前已经绑定过另一个 HXBot 账号，用那个账号登录即可。

**桌面端、安卓端、iOS 端怎么注册、怎么找回密码**
客户端的登录界面只有邮箱 + 密码，上面写着注册地址。注册和找回密码都在门户页 https://bot.hxallai.com 完成，然后回到客户端用邮箱和密码登录。

**账号服务起不来，日志里有 `No CA certificates were loaded from the system`**
11-09 之前的部署包里，账号服务镜像缺少根证书。按第 12 节“升级到新版本”换成新版部署包，再执行 `docker compose build account && docker compose up -d`。构建时会从阿里云的 Debian 镜像源安装根证书，装不上时自动改用部署包自带的根证书。

**门户页提示“该邮箱不在研究版名单中”**
说明注册名单生效了：把这个邮箱加进 HX_ALLOWED_EMAILS（第 12 节“修改注册名单”），或按第 5.6 节把名单清空。

**setup-https.sh 提示“无法通过 http://… 访问到本机”**
脚本会从服务器上用域名访问自己的 80 端口，拿不到测试文件就停下，此时还没有申请证书，官网不受影响。整段执行，看是哪一步不通：

```bash
D=/var/www/hxbot-acme/.well-known/acme-challenge
mkdir -p $D && printf hxbot-ok > $D/check
LAN=$(hostname -I | awk '{print $1}')
echo "== 1. 域名解析（4 行都应为 47.119.145.170）"
for h in bot api.bot signal.bot turn.bot; do
  ip=$(getent ahostsv4 $h.hxallai.com | awk 'NR==1{print $1}')
  echo "  $h.hxallai.com → ${ip:-没有解析}"
done
echo "== 2. 本机 nginx（2 行都应为 hxbot-ok）"
echo "  127.0.0.1 → $(curl -s --noproxy '*' --max-time 5 -H 'Host: bot.hxallai.com' http://127.0.0.1/.well-known/acme-challenge/check)"
echo "  内网 $LAN → $(curl -s --noproxy '*' --max-time 5 -H 'Host: bot.hxallai.com' http://$LAN/.well-known/acme-challenge/check)"
echo "== 3. 经公网 IP（应为 hxbot-ok [HTTP 200]）"
echo "  $(curl -s --noproxy '*' --max-time 10 -H 'Host: bot.hxallai.com' -w ' [HTTP %{http_code}]' http://47.119.145.170/.well-known/acme-challenge/check | head -c 300)"
echo "== 4. 系统防火墙"
echo "  ufw: $(command -v ufw >/dev/null && ufw status | head -1 || echo 未安装)"
```

- 第 1 项显示“没有解析”或不是 47.119.145.170：4 条解析记录没加或还没生效，按第 1 节添加，等几分钟再查。
- 第 1 项正常、第 2 项不是 `hxbot-ok`：执行 `nginx -T 2>/dev/null | grep -nE "listen|server_name"`，把输出发给开发人员。
- 第 1、2 项正常、第 3 项是 `[HTTP 000]`：80 端口被挡住了，检查安全组入方向的 80 端口（第 2 节）；ufw 显示 `Status: active` 时执行 `ufw allow 80/tcp && ufw allow 443/tcp`。
- 第 3 项返回一段网页而不是 `hxbot-ok`：把这段内容发给开发人员。

查出原因并解决后，重新执行 setup-https.sh 即可，脚本可以重复运行。

**check.sh 中“账号服务 127.0.0.1:8787”失败**
`docker compose logs --tail 100 account` 查看原因。最常见的是 .env 里缺少某项，日志会写明“缺少环境变量 XXX”。

**网页版、安卓端提示连接失败**
网页版和安卓端连接的是用户自己的桌面端主机。先在 Mac 或 Windows 上安装桌面端、用同一个账号登录，并在桌面端的服务器设置里开启远程访问。仍然失败时检查第 2 节的 3478、5349、49152-65535 端口。

**修改了配置但没有生效**
用 set-env.sh 改了配置（或直接改了 .env）后，必须执行 `docker compose up -d`（只重启不会重新读取 .env）。

**门户或网页版打开是 502 Bad Gateway**
先看 `docker compose ps` 里 account、signal 是否在运行。都在运行时，检查是否开启了 SELinux：`getenforce` 显示 `Enforcing` 时执行 `setsebool -P httpd_can_network_connect 1`，允许 nginx 连接本机的 8787、8081 端口。

## 14. 安全说明

- 账号服务（8787）和信令服务（8081）只监听 127.0.0.1，外网只能经过 nginx 的 HTTPS 访问。
- 账号服务的本地调试接口 `/cdn-cgi/` 和信令的内部接口 `/internal/` 已在 nginx 中屏蔽，check.sh 会检查这两项。
- 下载目录必须登录才能访问，登录状态由账号服务校验；未登录时跳回门户登录。
- 唯一的例外是 iOS 无线安装（发布了 Ad Hoc 安装包时才有）：`/ota/32位随机串/` 下的安装清单和安装包不校验登录，因为来取文件的是手机系统的安装程序。随机串只出现在登录后才能读到的下载列表里，不进访问日志，换安装包时更换；安装包只能装到签名时登记过的设备上。其余 `/ota/` 地址一律 404。
- 每个人用自己的邮箱和密码登录。密码在服务器上只保存加盐哈希（PBKDF2-HMAC-SHA256，10 万次迭代），验证码只保存哈希，10 分钟后失效；管理员也看不到任何人的密码。连续输错、频繁注册和频繁获取验证码都有次数限制。
- 网页版和手机端能远程连接同一账号登录的桌面端，所以账号被盗用等于电脑被远程访问：发现异常时立即 `bash scripts/users.sh disable 邮箱` 停用（他在各处的登录立即退出），核实后重置密码再恢复。需要只让指定的人注册时，用注册名单（第 5.6 节）。
- 关闭邮箱验证后，任何人都可以用别人的邮箱注册，也不能自助找回密码；关闭手机验证后，手机号码只检查格式。除非是内部小范围使用并配合注册名单，否则至少保持邮箱验证开启。
- 发信邮箱的密码、阿里云短信的 AccessKey、各家第三方登录的密钥都只在 .env 里（权限 600），不进日志、不进部署包。短信的 AccessKey 用只有短信权限的 RAM 子用户（第 5.4 节第 6 步），不要用主账号的。任何一项泄露后，到对应平台的后台重置，再用 set-env.sh 重新填写并 `docker compose up -d account`。
- 第三方登录只从对方平台取得用来认人的编号（以及对方返回的昵称），不取得也不保存用户在对方平台的密码、好友、支付等信息。
- 智能体默认“最大权限”：读取任何位置的文件、运行命令、使用网站和 Computer Use 都不用问；修改工作区以外已有的文件、删除工作区以外的东西、读写存放密钥的位置、以管理员身份运行命令、用保存的密码登录和付款前，先由服务器所有者在卡片上确认（允许一次、始终允许或拒绝）。手动改为“完全访问”的智能体什么都不问，改之前请评估。用户可以在“设置 → 授权与记录”里查看和删除“始终允许”的规则、查看授权记录。
- 弘犀服务器只负责账号和建立连接，对话、文件在客户端之间点对点加密传输，不经过也不存储在服务器上（无法直连时经中继转发的也是加密数据）。
- 访问日志写在 `/var/log/hxbot/access.log`，按《网络安全法》至少保存 6 个月（logrotate 每天轮转，保留 200 天后删除）；日志只记路径，不记查询参数，邀请链接里的凭证不会进日志。《隐私政策》写明的保存期限（账号注销后 30 天内删除、备份最多 30 天、日志约 200 天）以这些设置为准，修改设置时请同步修改政策。

### A.1 微信（微信开放平台 · 网站应用）

用户看到的是一个二维码，用手机微信扫码并确认后登录，适合在电脑上使用。要准备：营业执照、对公账户信息、一位管理员的微信；开发者资质认证要缴认证费（常见为 300 元，以平台页面为准）。

1. 打开 https://open.weixin.qq.com ，用公司邮箱注册开发者账号，按邮件激活并填写基本资料。
2. 进入“账号中心 → 开发者资质认证”，主体类型选企业，按页面上传营业执照等材料并缴费，等待审核（一般 1～2 个工作日）。
3. 认证通过后，进入“管理中心 → 网站应用 → 创建网站应用”，按上表填写名称、简介和官网，上传应用图标和页面要求的《网站信息登记表》（下载模板、盖公章后扫描），提交审核（通常 1～7 个工作日）。
4. 审核通过后打开这个应用的详情页：记下 **AppID**；在 **AppSecret** 处点“生成”（或“重置”），用管理员微信扫码确认后显示，立即复制保存（之后不再显示）。
5. 在详情页“开发信息”的“授权回调域”里填 `bot.hxallai.com`。只填域名，不带 `https://`，也不带路径。
6. 确认“接口信息”里“微信登录”一项的状态是“已获得”。

回到第 5.5 节执行“微信”一段的两条命令：AppID 填进 `HX_WECHAT_APP_ID`，AppSecret 用 `--secret` 隐藏输入。

### A.2 支付宝（支付宝开放平台 · 网页应用）

要准备：已完成企业实名认证的支付宝账号。

1. 打开 https://open.alipay.com ，用企业支付宝账号登录，按提示入驻成为开发者。
2. 在控制台“创建应用”，选“网页/移动应用”里的“网页应用”，填写应用名称（不能含“支付宝”“测试”等字样）并上传图标。创建后在应用详情里记下 **APPID**（一串数字）。
3. 在应用详情的“产品绑定”（或“添加能力”）里添加“获取会员信息”；页面上有“网站支付宝登录”时也一并添加。
4. 在“开发设置 → 接口加签方式”点“设置”：加签模式选“公钥”（**不要选“公钥证书”**），算法选 RSA2。按页面提示用“支付宝开放平台密钥工具”生成一对密钥：把“应用公钥”粘贴到页面上保存；把“应用私钥”存成一个文本文件 `alipay-app-private-key.txt`。私钥不上传给支付宝，只放到服务器上；密钥工具里“PKCS8”和“PKCS1”两种格式本服务都能读。
5. 在“开发设置 → 授权回调地址”里填完整地址 `https://bot.hxallai.com/api/browser/hx/oauth/alipay/callback`。
6. 提交审核，审核通过后把应用“上线”。应用状态是“已上线”时所有支付宝用户才能用它登录。

把私钥文件传到服务器，再回到第 5.5 节执行“支付宝”一段的两条命令。在你的电脑上执行：

```bash
scp alipay-app-private-key.txt root@47.119.145.170:/root/
```

### A.3 抖音（抖音开放平台 · 网站应用）

用户看到的是一个二维码，用抖音 App 扫码并确认后登录。要准备：营业执照等企业资质。

1. 打开 https://open.douyin.com ，注册开发者账号并完成企业认证。
2. 在控制台的“我的应用”里创建应用，类型选“网站应用”，按本附录开头的表格填写名称、简介和网站地址，上传图标，提交审核。
3. 审核通过后打开应用详情，在“应用信息”里记下 **Client Key** 和 **Client Secret**。
4. 在应用详情“网站应用”下的“授权回调”里登记回调：页面要求填完整地址时填 `https://bot.hxallai.com/api/browser/hx/oauth/douyin/callback`，只让填域名时填 `bot.hxallai.com`。
5. 在“能力管理”里确认已经有“抖音登录”（获取用户公开信息，权限名 `user_info`）；没有就申请开通。

回到第 5.5 节执行“抖音”一段的两条命令：Client Key 填进 `HX_DOUYIN_CLIENT_KEY`，Client Secret 用 `--secret` 隐藏输入。

### A.4 Apple（Sign in with Apple）

要准备：已付费的 Apple 开发者账号（第 11.3 节），操作的人要是账户持有人（Account Holder）或 Admin。下面都在 https://developer.apple.com/account 的“Certificates, Identifiers & Profiles”（证书、标识符和描述文件）里操作，一共要拿到四样：Team ID、Services ID、Key ID、.p8 密钥文件。

**第 1 步：建一个开启了 Sign in with Apple 的 App ID。**网页登录必须挂在一个开启了这项能力的 App ID 上。左侧点“Identifiers”，点标题旁的“+”，选“App IDs”→“App”：Description 填 `HXBot Web Sign In`，Bundle ID 选 Explicit 并填 `com.hxallai.bot.web`；在下面的 Capabilities 里勾选“Sign in with Apple”；点 Continue、Register。（这是专门给网页登录用的 App ID，与 iOS 版的 `com.hxallai.bot` 分开，互不影响。）

**第 2 步：建 Services ID。**还是在“Identifiers”，点“+”，选“Services IDs”：Description 填 `HXBot`（用户在 Apple 的登录页上看到的名字），Identifier 填 `com.hxallai.bot.signin`；点 Continue、Register。然后在列表里点开它，勾选“Sign in with Apple”，点旁边的“Configure”：

| 页面上的项 | 填什么 |
| --- | --- |
| Primary App ID | 第 1 步建的 `com.hxallai.bot.web` |
| Domains and Subdomains | `bot.hxallai.com`（不带 `https://`） |
| Return URLs | `https://bot.hxallai.com/api/browser/hx/oauth/apple/callback` |

点 Next、Done，再点 Continue、Save。**最后的 Save 不能漏**，漏了等于没配。

**第 3 步：建密钥。**左侧点“Keys”，点“+”：Key Name 填 `HXBot Sign In`，勾选“Sign in with Apple”，点“Configure”，Primary App ID 选第 1 步的 `com.hxallai.bot.web`，Save；点 Continue、Register。页面显示 **Key ID**（10 位字母数字），点“Download”下载 `AuthKey_XXXXXXXXXX.p8`。**这个文件只能下载一次**，下载后马上放进密码管理器备份一份。

**第 4 步：查 Team ID。**在 https://developer.apple.com/account 的“Membership details”（会员资格详情）里，10 位字母数字。iOS 版已经填过 `HX_APPLE_TEAM_ID` 的，是同一个值，不用再填。

把 .p8 文件传到服务器，再回到第 5.5 节执行“Apple”一段的四条命令。在你的电脑上执行（把文件名换成实际的）：

```bash
scp AuthKey_ABC123DEFG.p8 root@47.119.145.170:/root/
```

用户在 Apple 的页面上可以选择“隐藏邮件地址”。这不影响使用：第一次登录时他还是要在门户上填写自己的邮箱来注册或绑定账号，验证码发到他填的那个邮箱。

### A.5 Google（只在境外服务器上）

服务器在中国大陆时不要开启（第 5.5 节）。

1. 打开 https://console.cloud.google.com ，新建一个项目（例如 `hx-bot`）。
2. 在“APIs & Services”（或“Google Auth Platform”）里先配置 OAuth 同意屏幕：应用名称填 `HXBot`，用户支持邮箱和开发者联系邮箱填 bot@hxallai.com，受众（Audience）选“External”；首页、隐私政策、服务条款填本附录开头表格里的英文地址。
3. 进入“Clients”（或“Credentials”）→“Create client”：Application type 选“Web application”；在“Authorized redirect URIs”里添加 `https://bot.hxallai.com/api/browser/hx/oauth/google/callback`；创建后记下 **Client ID** 和 **Client secret**。
4. 在“Audience”里点“Publish app”，把发布状态从 Testing 改成 In production。停在 Testing 状态时，只有你列入名单的测试用户（最多 100 个）能登录，而且授权 7 天后失效。

回到第 5.5 节执行“Google”一段的两条命令。回调地址必须与第 3 步登记的逐字相同，否则 Google 的页面会提示 `redirect_uri_mismatch`；在后台改完设置后，可能要等几分钟到几小时才生效。

### A.6 Facebook（只在境外服务器上）

服务器在中国大陆时不要开启（第 5.5 节）。

1. 打开 https://developers.facebook.com ，登录后进入“My Apps”→“Create App”，用途选与“Facebook Login”（让用户用 Facebook 账号登录）对应的一项，应用名称填 `HXBot`。
2. 在“App settings → Basic”里：记下 **App ID**；点 App secret 旁的“Show”得到 **App Secret**；App Domains 填 `bot.hxallai.com`；Privacy Policy URL 和 Terms of Service URL 填本附录开头表格里的英文地址；保存。
3. 在“Facebook Login → Settings”的“Valid OAuth Redirect URIs”里添加 `https://bot.hxallai.com/api/browser/hx/oauth/facebook/callback`，保存。
4. 在登录用途的权限（Permissions）里确认 `public_profile` 和 `email` 两项已添加。
5. 把页面顶部的应用模式从“Development”切换到“Live”。停在 Development 时，只有这个应用的管理员、开发者和测试用户能登录。

回到第 5.5 节执行“Facebook”一段的两条命令。

## 附录 B：服务器拉不到镜像时，改用离线镜像

如果第 8 步一直卡在下载镜像，可以在任意一台能访问 Docker Hub 的电脑（例如装了 Docker Desktop 的 Mac）上把镜像做好，再传到服务器。先在服务器上执行 `uname -m` 确认架构：`x86_64` 用 `linux/amd64`，`aarch64` 用 `linux/arm64`。

在那台电脑上（解压 hxbot-server-v1.7.1.zip 后进入 server 目录）：

```bash
P=linux/amd64
docker build --platform $P -t hxbot/account:local account
docker build --platform $P -t hxbot/signal:local signal
docker build --platform $P -t hxbot/coturn:local coturn
docker pull --platform $P certbot/certbot:latest
docker save hxbot/account:local hxbot/signal:local hxbot/coturn:local certbot/certbot:latest | gzip > hxbot-images.tar.gz
scp hxbot-images.tar.gz root@47.119.145.170:/opt/
```

在服务器上：

```bash
gunzip -c /opt/hxbot-images.tar.gz | docker load
cd /opt/hxbot/server && docker compose up -d       # 注意不加 --build，直接使用导入的镜像
```

以后升级时同样先导入新镜像，再执行 `docker compose up -d`。
