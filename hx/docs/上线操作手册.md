## 先看懂：要做哪几件事、按什么顺序

v1.7.1 的服务器只让 0.68.0 及以后的桌面端、1.5.0 及以后的手机端登录。0.67.1～0.67.9 的桌面端登录时，服务器回答“版本太旧”，HXBot 马上检查新版本，弹出“更新 HXBot”窗口，装好 0.68.0 才能用；0.67.0 及以前的只能到下载页下载新版安装。照旧**先把新客户端放到下载中心，再升级服务器**。

还要注意：服务器已经是 v1.6.2 或以后（路线 A）时，**新的桌面端一传上去，已经装着 0.67.1～0.67.9 的电脑就会自动下载 0.68.0**，不用等服务器升级。0.68.0 是大版本：0.67.2～0.67.9 弹出“更新 HXBot”窗口（“HXBot 0.68.0 已发布，更新后才能继续使用。”），没有“以后再说”，窗口挡住 HXBot；下载好后点“立即更新”重启安装，10 分钟内没人点就在空闲时自动重启安装；0.67.1 下载完 10 秒后自动重启安装（它自带的窗口）。正在做的对话和团队会因为重启停下，所以**先通知用户，选人少的时候上传**。

### 1.2 确认能登录服务器

上传脚本用 SSH 把文件传到服务器。在 GitHub 上打包时，只需要你的 Mac 能用 root 登录服务器（上一版已经做过 1.2～1.4 节的，试一下 1.2 节的命令能登录就直接跳到 1.5 节）。

**先试一下**（在你的电脑上：Mac 的“终端”，或 Windows 的 Git Bash）：

```bash
ssh root@47.119.145.170 "cat /opt/hxbot/server/BUILD_COMMIT"
```

- 第一次连接会问 `Are you sure you want to continue connecting (yes/no/[fingerprint])?`，输入 `yes` 回车；再问 `root@47.119.145.170's password:` 时输入 root 密码（输入时屏幕上不显示，输完回车）。
- 显示一串字母和数字（例如 `85ddb3c5`），或者 `No such file or directory`：都说明**能登录**，接着做 1.3 节。这串字母数字代表什么版本，在 1.5 节看。
- `Permission denied`：密码不对，或者服务器只允许密钥登录（看 1.4 节）。忘了 root 密码：在阿里云控制台这台实例的页面点“重置密码”，按页面提示做（可能要重启实例，选没人用的时候）。
- `Operation timed out` 或 `Connection refused`：安全组没有放行 22 端口。在阿里云控制台打开这台实例 → “网络与安全组”页签 → 点安全组 ID → “入方向” → 看有没有端口范围是 `22/22`、授权策略是“允许”的规则。没有就点“手动添加”：授权策略“允许”，优先级 `1`，协议类型“自定义 TCP”，端口范围 `22/22`，授权对象填你电脑的出口 IP 加 `/32`（不知道出口 IP 时可以先填 `0.0.0.0/0`，传完再删掉这条），保存后再试。

**备用：在浏览器里登录服务器。**本手册里所有“在服务器上”执行的命令，也可以在阿里云控制台这台实例的页面点“远程连接”→ 通过 Workbench 远程连接 → 用 root 和密码登录，在打开的网页终端里执行。上传安装包仍要在 Mac 上用 SSH（第 3 步）。

### 1.3 设置免密登录（推荐）

上传一次要连服务器四五次，不设免密就要输四五次 root 密码。设置一次，以后都不用输。

**Mac：**打开“终端”。**Windows：**在开始菜单里打开 **Git Bash**（装 Git for Windows 时自带）。两边命令完全一样：

```bash
# 1. 看看有没有现成的密钥。显示文件路径就跳过第 2 行
ls ~/.ssh/id_ed25519.pub

# 2. 没有就生成一个，问三个问题都直接回车
ssh-keygen -t ed25519 -C "hxbot-upload"

# 3. 把公钥放到服务器上（这一次要输 root 密码）
cat ~/.ssh/id_ed25519.pub | ssh root@47.119.145.170 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'

# 4. 验证：不再问密码，直接显示一串字母数字（或 No such file or directory）
ssh root@47.119.145.170 "cat /opt/hxbot/server/BUILD_COMMIT"
```

### 1.4 服务器只能用阿里云密钥对（.pem 文件）登录时

在 Mac 终端或 Windows 的 Git Bash 里：

```bash
mkdir -p ~/.ssh
cp ~/Downloads/你的密钥.pem ~/.ssh/hxbot.pem      # 改成 .pem 实际所在的位置
chmod 600 ~/.ssh/hxbot.pem
cat >> ~/.ssh/config <<'EOF'
Host hxbot
  HostName 47.119.145.170
  User root
  IdentityFile ~/.ssh/hxbot.pem
EOF
ssh hxbot "cat /opt/hxbot/server/BUILD_COMMIT"    # 不问密码、显示一串字母数字（或 No such file）就对了
```

以后本手册里所有的 `root@47.119.145.170` 都换成 `hxbot`。上传脚本同样认这个名字。

## 第 8 节：出错了怎么办

### 上传时（你的电脑上）

| 看到的提示 | 原因 | 怎么办 |
| --- | --- | --- |
| `文件名不符合规则：……` | 安装包改过名 | 用打包生成的原名：`HXBot-0.68.0-arm64.dmg`、`HXBot-0.68.0-x64.exe`、`HXBot-1.5.0-android.apk` |
| `找不到文件：……` | 不在源码目录里，或路径写错 | 先 `cd` 到源码目录，`ls dist dist-hx` 看文件在不在 |
| `提示：dist 里没有 latest-mac.yml（或 latest.yml），这次不更新 Mac（Windows）的应用内更新` | 文件被删了或挪走了 | 安装包照样传上去了，用户能在下载页下载；但已安装的客户端在应用里看不到更新。重新打包，或把同一次打包的 yml 放回 dist 后再传一次 |
| `提示：……latest.yml 是 0.67.2 版的，和 HXBot-0.68.0-x64.exe 不一致` | dist 里混着两次打包的文件 | 用同一次打包生成的文件。最稳妥：删掉 dist 重新打包 |
| `提示：没找到 dist/HXBot-0.68.0-arm64.zip，这次不更新 Mac 的应用内更新` | zip 被删了 | 重新打包 Mac 版 |
| `Permission denied (publickey,password)` | 不能登录服务器 | 第 1.2～1.4 节 |
| `ssh: connect to host … port 22: Operation timed out` | IP 不对，或安全组没放行 22 端口 | 核对 IP；在阿里云安全组里给你的出口 IP 放行 22 端口 |
| `scp: /opt/hxbot/downloads/: No such file or directory` | 服务器上的部署目录不是 /opt/hxbot | 部署文档第 7 节建好下载目录 |
| `No space left on device` | 服务器磁盘满了（系统盘 40 GiB） | 登录服务器 `df -h /` 查看；删掉 `/opt/hxbot/downloads/` 里很旧的安装包（`updates/desktop/` 里的 `.blockmap` 文件留着），`docker image prune -f` 删掉没在用的旧镜像 |

## 第 9 节：以后的版本怎么上线

服务器到了 v1.6.2 之后，每个新版本都是同样的几步：

1. 打包新版本的客户端（哪个端改了打哪个端，见交付说明）。
   Mac 版每一版都用仓库 Secrets 里的同一张证书签名，不用再运行 `mac-signing-cert.sh`；**不要重新生成证书**（新证书等于新应用，所有 Mac 用户的授权都要重给一次）。换了打包用的仓库时，用 `bash hx/scripts/mac-signing-cert.sh 账号名/新仓库名 --upload` 把原来的证书写进新仓库（《客户端构建》第 6.3 节第二部分）。
2. 先通知用户（第 2 步），再按第 3 步上传。这时“应用内更新：”一段会直接显示新版本，已装旧版本的桌面端随即在后台下载，**不用做第 6 步**。0.67.2 起：平时的版本，用户在弹出的窗口里点“立即更新”或“以后再说”；大版本（版本号第二段变了，例如 0.68.0）必须更新。新功能介绍来自源码的 `hx/release-notes.json`，打包前写好。某个小版本必须马上装（例如修安全问题）时，打包前在 `hx/brand.json` 的 `minimumVersions` 里写上它，服务器升级后旧版本就会被要求更新。
3. 升级服务器，一条命令（v1.6.2 起服务器上已经有升级脚本）。交付件所在的文件夹换成那一版实际放的位置（例如 `/Volumes/US203/HX Web/交付日期/HXBot/版本号`，路径有空格，要加英文双引号）：

在 Mac 的“终端”里：

```bash
cd "/Volumes/US203/HX Web/交付日期/HXBot/版本号"                     # 换成那一版交付件实际所在的文件夹
scp hxbot-server-update-v版本号.zip SHA256SUMS root@47.119.145.170:/opt/
ssh root@47.119.145.170
```

登录服务器后，先核对（应显示 `hxbot-server-update-v版本号.zip: OK`），再开 tmux 窗口升级（同第 5.3 节）：

```bash
cd /opt && sha256sum --ignore-missing -c SHA256SUMS
tmux new -s hxbot
```

```bash
bash /opt/hxbot/server/scripts/update.sh /opt/hxbot-server-update-v版本号.zip
```

更新包要求服务器正好是它的起点版本（交付说明里写着）；不是的话脚本会提示，改用全量包 `hxbot-server-v版本号.zip`，命令相同。

4. 按第 7 步检查。

**服务器上只放最新的安装包就够了**：下载页每个平台只显示最新的一个；0.67.1 及以后的桌面端在应用里直接升到最新版，中间跳过几个版本都可以；0.67.0、手机端 1.4.x 及以前的没有应用内更新，在下载页直接装最新版。旧安装包可以删，`/opt/hxbot/downloads/updates/desktop/` 里旧版本的 `.blockmap` 留着（Windows 增量下载用）。

## 附录：从 v1.6 之前的版本升级（路线 C）

只有第 1.5 节显示“数据库迁移”是空的才看这一节。v1.6 之前的版本里，所有人共用一个登录口令；v1.6 起每人一个账号、用自己的密码登录。并且升级到 v1.6.2 及以后时所有设备的登录都会失效一次，所以**升级后每位老用户都要先在门户用原来的邮箱“创建账号”、设置自己的密码，再用新客户端登录**。原来的账号、服务器、成员关系都保留。

先照常做完第 2～4 步（通知用户、上传客户端，安卓 1.5.0 也要传），再按下面做。

### C.1 先决定老用户怎么证明“这个邮箱是我的”（二选一）

- **推荐：开着邮箱验证。**老用户注册时收一封验证码邮件。要先有发信邮箱（bot@hxallai.com 的 SMTP 设置），填写方法见《部署文档》第 5.3 节，在下面 C.2 的第 6a 步填。短信验证没批下来就关掉。
- **两项验证都关掉。**老用户注册时多填一项“原来的登录口令”证明身份。这种情况下，过渡期内**不要清空** .env 里的 `HX_LOGIN_PASSWORD`。

### C.2 手工升级（在服务器上，在 tmux 窗口里）

把全量包传上去并核对（同第 5.2 节路线 B），然后登录服务器，开 tmux 窗口（同第 5.3 节开头）：

```bash
ssh root@47.119.145.170
command -v tmux >/dev/null || (apt-get update && apt-get install -y tmux)
tmux new -s hxbot
```

在 tmux 窗口里**一行一行执行**，任何一行报错就停下来，不要跳过：

```bash
cd /opt/hxbot
bash server/scripts/backup.sh                              # 1. 备份账号数据库
install -m 600 server/.env /root/hxbot.env.bak             # 2. 备份配置
rm -rf server/account/dist server/account/migrations       # 3. 删除旧的程序文件（不影响数据和配置）
unzip -o /opt/hxbot-server-v1.7.1.zip                      # 4. 解压新版本（压缩包里没有 .env，不会覆盖配置）
cp -r server/portal/. portal/                              # 5. 更新门户首页和使用指南、条款、隐私政策页面
cd server
bash scripts/setup-https.sh                                # 6. 更新 nginx 配置（已有证书不会重新申请，不用写邮箱）
bash scripts/set-env.sh --show                             # 6a. 核对配置
```

**第 6a 步会显示两行“提醒：”**（新版本默认开着邮箱验证和手机验证，旧的 .env 里没有发信邮箱和短信的设置）。按 C.1 的选择处理：

```bash
# 选“开着邮箱验证”：先按《部署文档》第 5.3 节填好发信邮箱，再关掉还没批下来的短信验证
bash scripts/set-env.sh HX_PHONE_VERIFICATION off
```

```bash
# 选“两项验证都关掉”
bash scripts/set-env.sh HX_EMAIL_VERIFICATION off
bash scripts/set-env.sh HX_PHONE_VERIFICATION off
```

然后再执行一次 `bash scripts/set-env.sh --show`，**没有“提醒：”开头的行**再继续：

```bash
docker compose up -d --build                               # 7. 重新构建并启动，必须带 --build（几分钟）
bash scripts/check.sh                                      # 8. 检查，每一项都应是“通过”
```

接着做本手册的第 6 步（启用应用内更新文件）和第 7 步（升级后检查）。

### C.3 通知老用户、结束过渡

升级完成后发通知，内容参考：

> HXBot 已升级为每人一个账号，旧版客户端不能再登录。请先打开 https://bot.hxallai.com ，点“创建账号”，用你原来登录的邮箱注册并设置自己的密码；然后在下载页下载新版客户端安装（Mac 把新的 HXBot 拖进“应用程序”替换旧的，Windows 直接运行安装程序），用邮箱和新密码登录。原来的服务器和成员关系都保留。

在服务器上看还有谁没设置密码。输出最后的“以前用共用口令登录过、还没有设置自己密码的邮箱”就是名单；这一段不再出现，过渡就结束了：

```bash
cd /opt/hxbot/server
bash scripts/users.sh list
```

过渡结束后清空旧口令，并重启账号服务：

```bash
cd /opt/hxbot/server
bash scripts/set-env.sh HX_LOGIN_PASSWORD ''
docker compose up -d account
```

清空之后（并且关着邮箱验证时），还没设置密码的老用户注册会提示“请联系管理员为这个邮箱设置密码”：核实身份后用 `bash scripts/users.sh add 他的邮箱` 为他建好账号，还是原来的那个账号。开着邮箱验证时不受旧口令影响，随时可以清空。

升级中哪一行报错了：第 1 行已经把账号数据库备份在 `/opt/hxbot/backups/account-日期-时间.tgz`（屏幕上显示“已备份：……”），第 2 行把配置备份在 `/root/hxbot.env.bak`。不要自己删文件或重装，把报错的那一行和它下面的输出、以及 `docker compose logs --tail 100 account` 的输出发给维护人员，按他的说明处理（数据库的恢复方法在《部署文档》“数据库的备份与恢复”一节）。
