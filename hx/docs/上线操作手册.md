**上一版 v1.7.4 改的（服务器还没上线过 v1.7.4 时一起生效）：**应用技能（一）＋并发（二）（需求规格说明书 V2.2 第 5.3、5.4 节；用户 2026-11-19：“两个合并一起做”“追赶进度，保证质量！”），改的是桌面端；服务器只带上新的网页版和新功能页，数据库、nginx 配置、`.env` 都不变。①**助手直接改文件：**开着 Computer Use 的助手多了六个技能（表格、文档、演示、PDF、文件、系统设置），在这台电脑上直接读写 .xlsx、.docx、.pptx、.pdf，不用打开应用一步步点；改之前 HXBot 先留一份修改前的文件（数据文件夹的 file-versions，默认最多 2 GB，“设置 → Computer Use”里能改成 1～50 GB），改完从磁盘读回核对；对话里多一张卡片，列出改了哪些格子、段落、页，点“恢复到修改前”就回去（恢复前再留一份，还能再回去）；空间满了先问：删最早的旧版本、这次不留版本，或者取消。②**老格式：**.xls、.doc、.ppt 先复制一份，交给这台电脑上的 LibreOffice、Numbers、Pages、Keynote 或 Office（Windows 上 Office、WPS）转换后再改，改动存成旁边的新文件，原文件不动；.csv 由 HXBot 自己读；Keynote 的 .key 由 Keynote 自己改。HXBot 只按副本的唯一名字找自己的文档，只关自己的副本，只退出它自己打开的应用，**用户开着的文档不受影响**（这一条是在用户的 Mac 上查出来、改好、再实测过的）。③**排队看得见：**对话和任务里排着队的写“排队（第 n 位，约 m 分钟）”和原因；团队进度卡每个成员一行（在做什么、排第几位、等什么），下面可以点“更急 / 普通 / 不急”。手机端这次不更新（1.5.0），照常显示，不显示名次。④**模型服务商忙时自动缓一缓：**每个服务商同时发几个请求由 HXBot 按回复快慢自己调，被限速（429）时减半并暂停一会儿，你自己发的消息照样先试；开着“自动选择模型”的助手，排队太久时新工作改用同档或更好的模型；团队因为没有进展等原因暂停时，请一个小模型给出看法，只供参考，照常问你。⑤**修好的问题：**团队派出的工作空等最多 60 秒（v1.7.1 起）；经 OpenCode 的本机模型被当成付费的。《隐私政策》不变（1.5 版）。
**v1.7.3.1 改的（服务器还没上线过 v1.7.3.1 时一起生效）：**V1.7.3 的紧急修正（用户 2026-11-19：“无法检查更新”“边干活边更新，更新完，保存，然后重启！”“还是在 mac 程序坞中出现第二个应用！”“紧急修正 V1.7.3，紧急上线！”），改的是桌面端；服务器只改了两个脚本（publish-downloads.py、check.sh），带上新的新功能页。①**查到的原因：**服务器上没有应用内更新文件（`https://bot.hxallai.com/updates/desktop/latest-mac.yml` 是 404），Mac 版却把 404、登录失效、网络不通、服务器出错都显示成同一句“无法检查更新，请重试”；“这台电脑上的服务器”用 HXBot 自己的程序启动，macOS 在它启动的那一刻就给它一个程序坞图标，v1.7.2 是之后再藏，每次启动、重启服务器都会冒出第二个 HXBot。②**边干活边更新：**以前只有打开 HXBot 后 10 分钟内找到的新版本才自动装，用着用着才找到的要等下次打开；现在每 4 分钟查一次，任何时候找到都在后台下载（限速）、装好；等助手都空闲就保存并重启，等的时候新的定时任务先不开始（到点的重启后补上）；最多等 10 分钟，到时间还在忙也先保存再重启，被重启打断的助手重启后收到 HXBot 自动发的“接着做”（先看清做到哪一步，已经改过东西的不重复）。HXBot 正在启动（升级数据库）或正在下载、安装时绝不这样打断；右下角“HXBot 正在安装更新”照常可以取消这一次。**这一条从 0.67.13 起生效：0.67.12 及更早的还按它们自己的规则，打开 HXBot 时才更新到 0.67.13。**③**程序坞：**HXBot 的应用信息里写明“启动时不进程序坞”（LSUIElement），服务器从头到尾没有图标；主程序在启动完成之前切回普通应用，程序坞图标和菜单栏照旧。④**检查更新说清原因：**没有更新文件（404）、登录失效（401、403，先重新核对登录再试一次）、网络不通（先改走系统的网络和代理再试一次）、服务器出错（5xx）各有各的提示，更新日志记下状态码。⑤**服务器：**整理下载目录（publish-downloads.py）时，下载页的安装包比应用内更新文件新、或更新文件没传，最后大字提示怎么补；check.sh 多两项核对 Mac、Windows 的应用内更新文件和下载页是不是同一个版本。服务器的数据库、nginx 配置、`.env` 都不变；《隐私政策》不变（1.5 版）。

### 1.2 确认能登录服务器

### 3.0 最省事：FTP 传两个目录，再执行一条命令（路线 A）

### 7.4 电脑操控：哪些设置直接改，哪些要先自检

在 GitHub 真机上全部通过的设置（macOS 16 项全部，Windows 16 项里的 15 项），助手在任何一台电脑上都直接改。只有 Windows 的屏幕亮度（GitHub 的机器上没有可调亮度的屏幕），用户要先在自己的电脑上运行一次自检：“设置 → Computer Use → 这台电脑上的应用和设置 → 运行自检”。自检不改变任何设置的值；通过的设置，助手之后就直接修改。在那之前，助手改这类设置时会打开那一页、用 Computer Use 在页面上改（慢一些，结果一样），并提醒用户可以运行自检。

在对话里试三句话（助手要开着 Computer Use）：“打开蓝牙设置”“把深色模式打开”（试完再说“关掉深色模式”）“打开备忘录”（Windows 上说“打开记事本”）。三件事都应在一两秒内完成，助手不截图。再说“在备忘录里新建一条，写上测试”（Windows 上说“在记事本里写上测试”）：对话里出现进度卡，步骤一个个打勾（第 1.6 节第七部分做过的可以只看一眼）。再说“把备忘录的窗口放到左半边”（Windows：记事本）：窗口移过去，步骤里写着 computer_app（第 1.6 节第五部分做过的可以只看一眼）。

Mac 上从 0.67.7～0.67.14 应用内更新到 0.67.15 的电脑：“设置 → Computer Use”里的授权仍是“已授予”。从 0.67.6 或更早更新上来的：“辅助功能”“屏幕录制”显示没有授予是正常的（旧版的授权对新签名不算数），点“授予”按第 1.6 节第六部分第 4、5 步授权一次。以后的版本升级后不用再做。

### 7.5 团队协作、自动选择模型和建议卡

在装好 0.67.15 的电脑上，打开一个助手的设置：“自动选择模型”已打开、倾向“质量优先”；“建议卡”下面是一行“团队：人数按工作定；同时干活由电脑安排（现在 n 个）”和一项“为团队新建的成员”，没有“调整上限”。

在装好 0.67.15 的电脑上（不是第 1.6 节试过的那台也行），打开一个助手的“自动选择模型”，发一条写作的消息：回复之前应出现“自动选模型 · 写作：……”这一行。网页版打开同一个助手的对话，也应看到这一行。助手设置里的“最近的选择”应有这一条。

### 7.6 连接 OpenCode 的服务商和新功能页

1. 在装好 0.67.15 的电脑上，“设置 → 服务商”底部应有“OpenCode 全部服务商”一行，点“连接服务商”打开窗口，能看到服务商清单（第 1.6 节第十部分做过的可以只看一眼）。
2. 浏览器打开 https://bot.hxallai.com/whats-new/ ：最上面是“桌面端 0.67.15 · 手机端 1.5.1”一节，下面仍有“桌面端 0.67.14”～“桌面端 0.67.3”各节，截图都能打开（手机上打开时顶栏可以左右滑动，页面不会左右晃）；点右上角 English 显示英文页。

### 7.7 多开智能体和团队

在装好 0.67.15 的电脑上（第 1.6 节第三部分做过的可以只看一眼）：发一件要几个人分工的事，例如“帮我调研三家竞品的定价，分别整理成表，再写一页对比结论”，建议卡出来后点“开始”。团队房间里的分派都在看板上、没有一件被退回；带头的看到的分派回复里有“已排队，第 n 位……”或“已开始：电脑同时在做 m 件。”。在团队房间点停止，2 秒内不再有新的成员开始。

### 7.8 程序坞和别的应用存取文件

在装好 0.67.15 的电脑上（第 1.6 节第二部分做过的可以只看一眼）：开着 HXBot 和“这台电脑上的服务器”，Mac 的程序坞（Windows 的任务栏）里只有一个 HXBot；在别的应用里打开、保存一次文件，对话框 1～2 秒内出来。有用户说过“程序坞里好几个 HXBot”“存文件卡”的，请他们更新后再看一次。

### 7.9 几个助手同时用电脑

在装好 0.67.15 的电脑上（第 1.6 节第一部分做过的可以只看一眼）：“设置 → Computer Use”里有“停放后自动续做”，是打开的。让一个开着 Computer Use 的助手在“文本编辑”（Windows：记事本）里写一行字，发出后马上在文档里打几个字：助手的对话里出现“等你停手……”，你打的字之间没有插进助手的字；停手 5 秒，它接着写完。有用户说过“助手和我抢鼠标、抢键盘”的，请他们更新后再看一次。


### 7.10 程序坞、检查更新和边干活边更新（v1.7.3.1）

在装好 0.67.15 的 Mac 上（第 1.6 节第零之三部分做过的可以只看一眼）：程序坞里只有一个 HXBot；“设置 → 服务器”里重启一个“这台电脑上的服务器”，程序坞里不冒出第二个；“设置 → 关于”点“检查更新”，显示已是最新版本（0.67.15）。

**这次上传 0.67.15 时核对边干活边更新**（0.67.13 起才有）：让一台装着 0.67.13 或 0.67.14 的电脑开着 HXBot、让一个助手做一件要十几分钟的事（例如“把这个文件夹里的文件逐个读一遍，每个写一句总结”），再上传 0.67.15：几分钟内右下角提示“HXBot 正在安装更新”；助手手上的事做完（或最多 10 分钟后）HXBot 自动重启进入 0.67.15（先播开机动画）；重启前还在做的助手，重启后对话里有一条“（HXBot 自动发送）HXBot 为安装更新重启了……”，它接着把事做完，没有重复已经做过的改动。

### 7.11 助手直接改文件、排队看得见（v1.7.4）

在装好 0.67.15 的电脑上（第 1.6 节第零之二部分做过的可以只看一眼）：让一个开着 Computer Use 的助手改一个表格里的一格（例如“把文稿里销售.xlsx 第 2 行的金额改成 150”）：对话里出现“改了 销售.xlsx……”的卡片，写着“HXBot 已读回核对”；点“恢复到修改前”，卡片显示“已恢复”，文件回到原样。“设置 → Computer Use”里“修改前保留的版本”显示已用多少。让助手组一个团队做一件要几分钟的事：进度卡上每个成员一行，下面有“更急 / 普通 / 不急”。手机上打开同一个对话，照常显示。有用户说过“助手改坏了文件”“不知道排到第几”的，请他们更新后再看一次。

### 7.12 开机动画、定时任务、工作流和删除助手（v1.7.5）

在装好 0.67.15 的电脑上（第 1.6 节第零部分做过的可以只看一眼）：打开一个升级前就有的定时任务，“时区未确认”已经确认过的不再显示；新建定时任务必须选时区，“接下来三次”列出本地时间和 UTC。工作流菜单里有“运行上限…”。删除一个助手后马上退出、再打开，它不会回来；网页版和手机上也没有它。有条件的，让一个团队做一件要几十分钟的事：团队没进展的提醒出来时点“继续”，“设置 → Computer Use”的“按你的选择调整的时间”里写着这个团队改成了多少分钟，点“恢复默认”就回去。有用户说过“删掉的助手又回来了”“定时任务没按时跑、不知道跑没跑成”的，请他们更新后再看一次。

### 上传时（你的电脑上）

| 看到的提示 | 原因 | 怎么办 |
| --- | --- | --- |
| `REMOTE HOST IDENTIFICATION HAS CHANGED`、`Host key verification failed` | 你的 Mac 记的服务器 SSH 密钥和服务器现在给的不一样：多半是服务器重装、重置过，也可能是网络被人截了 | 先不要连。在阿里云控制台用 Workbench 登录服务器，执行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`，看指纹和提示里的是否一模一样。一样：在 Mac 上执行 `ssh-keygen -R 47.119.145.170`，再 `ssh root@47.119.145.170`，核对显示的指纹后输入 yes。不一样：不要连，把两边截图发回来。也可以改用第 3.0 节的 FTP 做法 |
| `……的签名身份不对，没有上传` | v1.7.3.1 之前的上传脚本只认 `certificate leaf`，有的 Mac 写的是 `certificate root`（同一张自签证书） | 用 v1.7.3.1 及以后交付文件夹 `client/` 里的 `upload-downloads.sh`（两种写法都认，并核对指纹 9FA98521…）；不要加 `HXBOT_ALLOW_UNSIGNED_MAC=1` |
| `文件名不符合规则：……` | 安装包改过名 | 用打包生成的原名：`HXBot-0.67.15-arm64.dmg`、`HXBot-0.67.15-x64.exe`、`HXBot-1.5.1-android.apk` |
| `找不到文件：……` | 不在源码目录里，或路径写错 | 先 `cd` 到源码目录，`ls dist dist-hx` 看文件在不在 |
| `提示：dist 里没有 latest-mac.yml（或 latest.yml），这次不更新 Mac（Windows）的应用内更新` | 文件被删了或挪走了 | 安装包照样传上去了，用户能在下载页下载；但已安装的客户端在应用里看不到更新。重新打包，或把同一次打包的 yml 放回 dist 后再传一次 |
| `提示：……latest.yml 是 0.67.2 版的，和 HXBot-0.67.15-x64.exe 不一致` | dist 里混着两次打包的文件 | 用同一次打包生成的文件。最稳妥：删掉 dist 重新打包 |
| `提示：没找到 dist/HXBot-0.67.15-arm64.zip，这次不更新 Mac 的应用内更新` | zip 被删了 | 重新打包 Mac 版 |
| `Permission denied (publickey,password)` | 不能登录服务器 | 第 1.2～1.4 节 |

| `No space left on device` | 服务器磁盘满了（系统盘 40 GiB） | 登录服务器 `df -h /` 查看；删掉 `/opt/hxbot/downloads/` 里很旧的安装包（`updates/desktop/` 里的 `.blockmap` 文件留着），`docker image prune -f` 删掉没在用的旧镜像 |

### 启用和升级时（服务器上）

| 看到的提示 | 原因 | 怎么办 |
| --- | --- | --- |
| `新上传的 latest.yml 指向的文件不在服务器上：……没有启用，Windows 客户端仍更新到原来的版本` | 安装包没传上去，或传了另一次打包的 yml | 按第 3 步重新上传 Windows 版（Mac 同理） |

| 用户说“网页版（或首页）每次打开都放动画” | 浏览器不让网站存数据，或每次关闭时清除网站数据（无痕窗口也一样），每次都算第一次。点一下就能跳过；想不再播放的，在浏览器里允许 bot.hxallai.com 保存数据 |
| 用户说“定时任务上写着时区未确认” | 正常：升级前建的定时任务，确认前照旧按原来的时区运行。打开它选一次时区，或在对话里那条“升级到 v1.7.5 时改了……”下面点“确认这些时区” |
| 用户说“定时任务没跑，对话里有一张等确认的卡片” | 正常：补跑的那次（或升级时改成每次运行前先问的定时任务）要发送、发布、付款、删除，确认前什么都不做。点“运行这一次”或“这次跳过”；到下次运行时间前没人回答，这次记“已跳过：到下次时间前没人回答” |
| 安卓用户说“提示 1.5.1 来了，点更新后下载不了” | 下载中心里没有 1.5.1 的安装包 | 按第 3 步补传 `HXBot-1.5.1-android.apk`（publish-downloads.py 会同时更新手机端的下载地址） |
| iPhone 用户问“为什么没有新版本” | 正常：这一版 iPhone 不发包（没有邓白氏码），仍是 1.5.0，照常使用；连着 0.67.15 的电脑时，删除的助手也随即消失 |
| Windows 提示“Windows 已保护你的电脑” | 点“更多信息 → 仍要运行” |
| 安卓装新版提示“签名不一致”或“与已安装的应用冲突” | 新 APK 不是用原来的签名打的。不要让用户卸载（会丢数据），按《客户端构建》第 4.2 节找回原来的签名文件重新打包 |

## 第 9 节：以后的版本怎么上线

服务器到了 v1.6.2 之后，每个新版本都是同样的几步：

1. 打包新版本的客户端（哪个端改了打哪个端，见交付说明）。
   Mac 版每一版都用仓库 Secrets 里的同一张证书签名，不用再运行 `mac-signing-cert.sh`；**不要重新生成证书**（新证书等于新应用，所有 Mac 用户的授权都要重给一次）。换了打包用的仓库时，用 `bash hx/scripts/mac-signing-cert.sh 账号名/新仓库名 --upload` 把原来的证书写进新仓库（《客户端构建》第 6.3 节第三部分）。
2. 先通知用户（第 2 步），再按第 3 步上传。这时“应用内更新：”一段会直接显示新版本，已装旧版本的桌面端随即在后台下载，**不用做第 6 步**。0.67.13 起：以后的版本（大版本也一样）都不拦，用户打开 HXBot 时自动下载、装好，在助手都空闲时重启进入新版，不用点；还装着 0.67.2～0.67.9 的电脑按它们自己的规则弹窗，版本号第二段一变会挡住界面，所以在这些电脑都装上 0.67.13 之前，新版本的版本号保持 0.67.x。新功能介绍来自源码的 `hx/release-notes.json`，打包前写好。服务器不再按版本拒绝客户端，也不再有单独设成必须更新的版本。
3. 升级服务器，一条命令（v1.6.2 起服务器上已经有升级脚本）。交付件所在的文件夹换成那一版实际放的位置（例如 `/Volumes/US203/HX Web/交付日期/HXBot/版本号`，路径有空格，要加英文双引号）：

在 Mac 的“终端”里：

```bash
cd "/Volumes/US203/HX Web/交付日期/HXBot/版本号"                     # 换成那一版交付件实际所在的文件夹
scp hxbot-server-update-v版本号.zip SHA256SUMS root@47.119.145.170:/opt/
ssh root@47.119.145.170
```

登录服务器后，先核对（应显示 `hxbot-server-update-v版本号.zip: OK`），再开 tmux 窗口升级（同第 5.3 节）：

```bash
cd /opt && sha256sum --ignore-missing -c SHA256SUMS
tmux new -s hxbot
```

```bash
bash /opt/hxbot/server/scripts/update.sh /opt/hxbot-server-update-v版本号.zip
```

更新包要求服务器正好是它的起点版本（交付说明里写着）；不是的话脚本会提示，改用全量包 `hxbot-server-v版本号.zip`，命令相同。

4. 按第 7 步检查。

**服务器上只放最新的安装包就够了**：下载页每个平台只显示最新的一个；0.67.1 及以后的桌面端在应用里直接升到最新版，中间跳过几个版本都可以；0.67.0、手机端 1.4.x 及以前的没有应用内更新，在下载页直接装最新版。旧安装包可以删，`/opt/hxbot/downloads/updates/desktop/` 里旧版本的 `.blockmap` 留着（Windows 增量下载用）。

## 附录：从 v1.6 之前的版本升级（路线 C）

只有第 1.5 节显示“数据库迁移”是空的才看这一节。v1.6 之前的版本里，所有人共用一个登录口令；v1.6 起每人一个账号、用自己的密码登录。并且升级到 v1.6.2 及以后时所有设备的登录都会失效一次，所以**升级后每位老用户都要先在门户用原来的邮箱“创建账号”、设置自己的密码，再用新客户端登录**。原来的账号、服务器、成员关系都保留。

先照常做完第 2～4 步（通知用户、上传客户端，安卓 1.5.1 也要传），再按下面做。

### C.1 先决定老用户怎么证明“这个邮箱是我的”（二选一）

- **推荐：开着邮箱验证。**老用户注册时收一封验证码邮件。要先有发信邮箱（bot@hxallai.com 的 SMTP 设置），填写方法见《部署文档》第 5.3 节，在下面 C.2 的第 6a 步填。短信验证没批下来就关掉。
- **两项验证都关掉。**老用户注册时多填一项“原来的登录口令”证明身份。这种情况下，过渡期内**不要清空** .env 里的 `HX_LOGIN_PASSWORD`。

### C.2 手工升级（在服务器上，在 tmux 窗口里）

把全量包传上去并核对（同第 5.2 节路线 B），然后登录服务器，开 tmux 窗口（同第 5.3 节开头）：

```bash
ssh root@47.119.145.170
command -v tmux >/dev/null || (apt-get update && apt-get install -y tmux)
tmux new -s hxbot
```

在 tmux 窗口里**一行一行执行**，任何一行报错就停下来，不要跳过：

```bash
cd /opt/hxbot
bash server/scripts/backup.sh                              # 1. 备份账号数据库
install -m 600 server/.env /root/hxbot.env.bak             # 2. 备份配置
rm -rf server/account/dist server/account/migrations       # 3. 删除旧的程序文件（不影响数据和配置）
unzip -o /opt/hxbot-server-v1.7.5.zip                      # 4. 解压新版本（压缩包里没有 .env，不会覆盖配置）
cp -r server/portal/. portal/                              # 5. 更新门户首页和使用指南、条款、隐私政策页面
cd server
bash scripts/setup-https.sh                                # 6. 更新 nginx 配置（已有证书不会重新申请，不用写邮箱）
bash scripts/set-env.sh --show                             # 6a. 核对配置
```

**第 6a 步会显示两行“提醒：”**（新版本默认开着邮箱验证和手机验证，旧的 .env 里没有发信邮箱和短信的设置）。按 C.1 的选择处理：

```bash
# 选“开着邮箱验证”：先按《部署文档》第 5.3 节填好发信邮箱，再关掉还没批下来的短信验证
bash scripts/set-env.sh HX_PHONE_VERIFICATION off
```

```bash
# 选“两项验证都关掉”
bash scripts/set-env.sh HX_EMAIL_VERIFICATION off
bash scripts/set-env.sh HX_PHONE_VERIFICATION off
```

然后再执行一次 `bash scripts/set-env.sh --show`，**没有“提醒：”开头的行**再继续：

```bash
docker compose up -d --build                               # 7. 重新构建并启动，必须带 --build（几分钟）
bash scripts/check.sh                                      # 8. 检查，每一项都应是“通过”
```

接着做本手册的第 6 步（启用应用内更新文件）和第 7 步（升级后检查）。

### C.3 通知老用户、结束过渡

升级完成后发通知，内容参考：

> HXBot 已升级为每人一个账号，旧版客户端不能再登录。请先打开 https://bot.hxallai.com ，点“创建账号”，用你原来登录的邮箱注册并设置自己的密码；然后在下载页下载新版客户端安装（Mac 把新的 HXBot 拖进“应用程序”替换旧的，Windows 直接运行安装程序），用邮箱和新密码登录。原来的服务器和成员关系都保留。

在服务器上看还有谁没设置密码。输出最后的“以前用共用口令登录过、还没有设置自己密码的邮箱”就是名单；这一段不再出现，过渡就结束了：

```bash
cd /opt/hxbot/server
bash scripts/users.sh list
```

过渡结束后清空旧口令，并重启账号服务：

```bash
cd /opt/hxbot/server
bash scripts/set-env.sh HX_LOGIN_PASSWORD ''
docker compose up -d account
```

清空之后（并且关着邮箱验证时），还没设置密码的老用户注册会提示“请联系管理员为这个邮箱设置密码”：核实身份后用 `bash scripts/users.sh add 他的邮箱` 为他建好账号，还是原来的那个账号。开着邮箱验证时不受旧口令影响，随时可以清空。

升级中哪一行报错了：第 1 行已经把账号数据库备份在 `/opt/hxbot/backups/account-日期-时间.tgz`（屏幕上显示“已备份：……”），第 2 行把配置备份在 `/root/hxbot.env.bak`。不要自己删文件或重装，把报错的那一行和它下面的输出、以及 `docker compose logs --tail 100 account` 的输出发给维护人员，按他的说明处理（数据库的恢复方法在《部署文档》“数据库的备份与恢复”一节）。
